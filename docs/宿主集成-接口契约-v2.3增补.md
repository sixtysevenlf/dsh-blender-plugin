## §S0 背景与目标

v1.x–v2.2 的"选中"是 **DSH 侧点截图**：DSH 面板里点画面 → `POST /host/view/pick` 反投影 → 「加入消息」。
它有三个实测痛点：图小/会陈旧、点小零件不准、必须切窗口。

v2.3 把**选中入口移到 Blender 侧**（用户明确选择）：

1. 用户在 **Blender 原生选区**里选物体（点、框选、Shift 加选都行）；
2. 按 3D 视图 `N` →「DSH Blender Bridge」→ **Selection → DSH** → 「发送选中到 DSH」；
3. addon 把选中 **POST** 给 DSH 后端；Web 客户端半边把它**插入当前会话草稿**（**不自动发送**）；
4. 同时 addon 在 Blender 侧统一判定 **human / agent / idle / both** 四态（模态操作、最近人类操作、agent 命令窗口），
   面板实时显示，模型可经 `blender_rt_cmd get_activity_state` 查询。

**同版本删除**：DSH 侧视口面板（Web 侧栏 + TUI 侧栏）、点击进消息、模型请求点选 `blender_rt_pick` 全部移除
（模型工具 16 → **15**）；后端 `/host/view/*`、`/host/pick*`、`/host/ready` 路由**同步删除**。
现存宿主路由只有：`/host/selection`（+ `/latest`、`/consume`）、`/host/scene-items`（`@` 提及数据源）、
`/host/jobs`（+ `/log`）。
选中的两个入口统一为 N 面板的 **多选模式 / 集合模式**。

> 保留的只有 `@` 提及（`GET /host/scene-items`）；截图点选、`blender_rt_pick` 与 `/host/view/*`、`/host/pick*`、`/host/ready` 已随面板一起删除。

## §S1 addon 侧（v1.8 起，协议号仍 11；v2.5 为 addon v1.10）

### §S1.1 新命令

| 命令 | 参数 | 返回 |
|---|---|---|
| `get_activity_state` | 无 | activity 快照（见 §S1.2）。**查询命令自身不算 agent**。 |
| `get_selection` | 无 | `{count, names, truncated, active, mode, objects, scene, file, activity}` |
| `send_selection_to_dsh` | `timeout?`（秒，默认 3.0） | `{ok, seq?, received_at?, status_code?, error?, hint?, backend_url, payload}` |
| `get_collections` | `limit?`（默认 200） | `{count, returned, collections:[{name,count,selected_count,parent}], scene}` |
| `send_collection_to_dsh` | `collection?`（缺省取场景属性 `dshbb_collection_target`）、`timeout?` | 同 `send_selection_to_dsh`，但 `selection.kind="collection"` |

- 三条都是**常驻命令**（不挂在 5 个集成门控下），并进 `get_addon_info.capabilities`。
- 都走 Blender 主线程（与 `get_scene_info` 同类；渲染中会先吃 `BUSY_RENDER` 的既有语义）。
- addon 版本 **v1.8**；`bl_info["version"] = (1, 8)`；协议号保持 **11**（新增命令向后兼容，旧插件仍可连）。

### §S1.2 activity 快照（统一状态）

```json
{
  "state": "idle | human | agent | both",
  "human_active": false,
  "agent_active": false,
  "human_idle_ms": 1234,
  "agent_idle_ms": 567,
  "last_human_kind": "operator:object.select_all | selection | undo | modal:transform.translate | null",
  "agent_depth": 0,
  "modal_operators": ["transform.translate"],
  "mode": "OBJECT",
  "selection": {"count": 2, "names": ["Cube", "Camera"], "active": "Cube", "mode": "OBJECT", "truncated": false},
  "windows_ms": {"human": 1500, "agent": 1500},
  "scene": "Scene",
  "ts": 1792415489.9,
  "source": "addon"
}
```

**判定口径**（`addon/dsh_blender_bridge.py` 的 `ActivityTracker`）：

- **human 信号**：`bpy.context.window.modal_operators` 非空（拖拽/变换/菜单等模态操作，**持续有效**）·
  最近 1.5 s 内出现过人类操作符（含被 `_IGNORED_OPERATORS` 过滤的 view3d 导航）· 撤销/重做 ·
  原生选区/活动对象/模式变化（1.5 s 窗口）。
- **agent 信号**：`UserEditRecorder.agent_command()` 括号内（`agent_depth > 0`）或最近一次 agent 命令结束 ≤1.5 s。
- **归因规则**：agent 命令期间的人类信号被抑制；命令结束时作废选区指纹（否则每次工具调用后都误报 `human`）。
- **查询自身**：`get_activity_state` / `get_selection` 用 `include_current_command=false` —— 状态里**不含这次查询**，
  否则模型每次查询都会看到 `state=agent`。
- **privacy**：只本地判定，**不依赖 telemetry_consent、不上传**。与 `drain_human_activity`（遥测同意后才有事件）是两回事。

### §S1.3 选中 payload（addon → 后端）

```json
{
  "v": 1,
  "source": "blender-addon",
  "sent_at": 1792415489912,
  "selection": {
    "count": 2,
    "names": ["Cube", "Camera"],
    "truncated": false,
    "active": "Cube",
    "mode": "OBJECT",
    "objects": [
      {"name": "Cube", "type": "MESH", "dimensions_mm": [2000, 2000, 2000]},
      {"name": "Camera", "type": "CAMERA", "dimensions_mm": [0, 0, 0]}
    ]
  },
  "scene": {"name": "Scene", "file": "machine.blend"},
  "activity": { "...§S1.2 快照..." }
}
```

- `names` 上限 200、`objects` 上限 50、`collections` 上限 50（addon 侧先截，后端再截一次）；`file` 只给 **basename**。
- **集合 payload**（`send_collection_to_dsh` / N 面板集合模式）：`selection.kind="collection"`、`selection.collection="<名字>"`、
  `count`=集合内对象总数、`names`=前 200 个成员；客户端草稿文本为「Blender 集合：<名字>（N 件，前 k 件：…）」。
- **N 面板两种模式**：场景属性 `dshbb_selection_mode = "MULTI" | "COLLECTION"`（默认 MULTI）。
  MULTI 显示当前选中的**对象列表**并发送 `kind="objects"`；
  COLLECTION 显示集合下拉（`dshbb_collection_target`，PointerProperty）+ **成员列表** + 件数 + 子集合摘要，
  并发送 `kind="collection"`。切到 COLLECTION 时若未选集合，`update` 回调会自动挑"选中对象最常出现的集合"；
  面板的 ⟳ 按钮（`dshbb.use_selection_collection`）可随时重新推断。
- **列表 UI（v2.3.1+）**：对象 / 成员列表默认折叠，展开后是 Blender `UIList`（自带滚动条），
  高度由场景属性 `dshbb_list_rows`（3–30，默认 8）控制；后端地址收在折叠的「后端 / 高级」里。
- **子元素 payload（v2.4，`selection.sub`）**：编辑模式 / 姿态模式发送时附带，结构如下：

```json
"sub": {
  "type": "MESH",                 // MESH | ARMATURE | CURVE | LATTICE | OTHER
  "object": "Cube",
  "mode": "EDIT_MESH",
  "select_mode": {"vertex": true, "edge": false, "face": false},
  "counts": {"vertices": 12, "edges": 0, "faces": 0},
  "indices": {"vertices": [0, 3, 7], "edges": [], "faces": []},
  "bones": ["Bone.001"],          // type=ARMATURE 时
  "points": [[0, 2], [0, 5]],     // type=CURVE/LATTICE 时为 (spline_index, point_index)
  "truncated": false
}
```

  addon 侧每类索引上限 **2000**、骨骼名 **500**；后端会再夹一次并过滤非整数/负数。
  后端地址、面板列表等 UI 状态不进 payload。
- 后端地址：`DSH_BLENDER_BACKEND_URL` 环境变量 → 场景属性 `dshbb_backend_url` → 默认 `http://127.0.0.1:9877`。
- N 面板按钮与 `send_selection_to_dsh` 命令**同一实现**（按钮内部就是调它）。发送失败在面板上显示原因，不弹窗。

### §S1.4 暂停 AI 操作（v2.5，addon v1.10）

- 场景属性 `dshbb_ai_paused`（Bool，默认 `False`）+ 操作符 `dshbb.toggle_ai_pause`；N 面板顶部按钮切换。
- 暂停后 socket **只放行只读命令**：`ping`、`get_*`、`drain_human_activity`、`describe_node_type`、`bpy_api_lookup`；
  其余（`execute_code`、资产下载/生成/导入、`send_*`、`set_*` 等）返回
  `{"status":"error","error":"AI_PAUSED","message":"…"}`。
- `get_activity_state` 回执增加 `paused: true|false`；暂停期间模型无法自行解除，必须人在 Blender 面板点「继续 AI 操作」。
- 边界：只作用于 GUI addon socket；无头 Blender 进程 / 文件系统不受影响。

## §S2 后端路由（零 Blender 往返）

三条都在 `/host/*` 下，遵循基础契约 §1.1 的 CORS 规则（loopback / `dsh-app://app` 才回显 ACAO）。

### §S2.1 `POST /host/selection` —— addon 推送选中

- 请求体：§S1.3 payload（`content-type: application/json`）。
- `200` → `{"ok": true, "seq": 3, "received_at": 1792415489920}`
- `400` → `{"ok": false, "error": "invalid_payload"}`（非对象 / 解析失败）
- **不校验写租约**：这是用户侧推送（与 `/host/view/pick` 同类），不做场景写操作。
- 存储层消毒：名字/字符串截断（`MAX_STRING_CHARS=200`）、条数上限、未知字段丢弃（`runtime/selectionstore.mjs`）。

### §S2.2 `GET /host/selection/latest` —— 客户端轮询

```json
{
  "ok": true,
  "seq": 3,
  "consumed_seq": 2,
  "unconsumed": true,
  "received_at": 1792415489920,
  "stale_ms": 412,
  "selection": { "...§S1.3.selection..." },
  "activity": { "...§S1.2..." },
  "scene": {"name": "Scene", "file": "machine.blend"},
  "last_consume": {"seq": 2, "ok": false, "how": null, "reason": "草稿已有内容，备用通道不覆盖", "at": 1792415488711}
}
```

- **只有 `unconsumed=true` 时才带 `selection/activity/scene`**（避免页面重载后把旧选中重复插入）。
- `last_consume` 是**诊断字段**：客户端把插入结果回传（见 §S2.3），
  用于回答"按钮点了、后端也收到了，为什么草稿里没字"。
- 纯内存、零 I/O；`since` 参数不再需要（消费者用 `unconsumed` + `consume` 的 CAS 语义）。

### §S2.3 `POST /host/selection/consume` —— 标记已插入

- 请求体：`{"seq": 3, "ok": true, "how": "actions"}`；`ok/how/reason` 可省（curl/老客户端合法）。
- `200` → `{"ok": true, "consumed_seq": 3}`；非法 seq（0/负数/未来/非整数）→ `400 {"ok": false, "consumed_seq": N, "error": "invalid_seq"}`。
- `consumed_seq` **只增不减**；同一 seq 重复 consume 幂等。
- 多标签页竞争：服务端按 seq 去重；极端情况下同一选中可能被两个客户端各插一次（已知边界，见 §S5）。

## §S3 客户端半边（Web）

### §S3.1 无头桥的座位

- 注册到 `conversation.input.dock`（**session 作用域、常驻挂载、渲染 `null`**），
  id `blender-selection-bridge`，order 90。
- 因此：**侧栏面板收起也照常接收**；不需要用户先打开 DSH 面板。
- 每个打开的会话各自挂一个桥；只有**当前会话**会插入（`inject` 提供的 `sessionId` 决定目标）。

### §S3.2 轮询与插入

1. 每 **100 ms** `GET /host/selection/latest`（`no-store`）；失败静默、下一 tick 重试。
   （v2.6.1 性能实测：1200 ms 时端到端 p50 ~993 ms，100 ms 时 ~156 ms；单客户端 10 req/s 的本地 GET 成本可忽略。）
2. `unconsumed === true` 且 `seq` 未处理过 → 生成草稿文本：
   `Blender 选中：<names，顿号分隔>（共 N 件，只列前 M 件）。活动对象：X。模式：OBJECT。用户说"这个/这些"时指它们；对象名在 bpy.data.objects 里可直接用。`
3. 写入当前会话草稿（**不自动发送**）：
   - 首选 `inputActions.insertText(text, captureInsertion())`（可追加、保留用户已有内容）；
   - 备用 `SessionInput.setDraft(text)`：**只在读得到且草稿为空**时写，绝不覆盖用户内容。
4. 插入成功 → `POST /host/selection/consume {seq, ok:true, how}`。
5. 插入失败 → **不消费**，下一 tick 重试（最多 3 次；第 3 次消费并回传 `ok:false, reason`，避免卡死）。
6. 通过 `fallbackInput.notify("info", …)` 提示"已接收 Blender 选中（已加入草稿，未发送）"（服务可用时）。

### §S3.3 不做的事

- 不自动发送消息、不新建会话、不改动其他会话草稿。
- 不轮询 Blender（零 bpy 往返）；不需要 DSH 侧栏面板处于打开状态。
- 页面在后台也继续轮询（用户可能刚在 Blender 点完按钮就切回 DSH）。

## §S5 已知边界（如实记录）

1. **客户端半边需 DSH 重启（或页面刷新）**：`lib/client.js` 是启动时装入的模块；开发期 HMR 可能热加载，但正式升级必须重启。
2. **TUI 草稿**：`conversation.input.dock` 是 Web 客户端座位，dsh-TUI 不加载客户端半边。
   v2.6.1 起由 host 侧的 TUI 宿主半边接上（见 §S6）：选中以**上下文 chip** 的形式挂到下一条消息，需要 dsh-TUI 提供
   `tuiContextChips` 接缝；没有这个接缝的 dsh-TUI 版本上仍是旧行为（后端收到、TUI 里不出现）。**TUI 侧视口面板已在 v2.3 删除，不恢复。**
3. **只进"当前会话"**：桥挂在当前打开的会话上；若用户切到别的会话再点 Blender 按钮，会进切换后会话的草稿。
4. **后台轮询**：页面隐藏时仍按 100 ms 轮询（为了"点完就切回"的场景）；v2.6.1 实测该间隔下端到端 p50 ~156 ms。若极端在意隐藏页的耗电，可后续加可配置开关。
5. **多标签页**：极端情况下同一 seq 可能被两个标签页各插一次；服务端不撒谎，`last_consume` 保留最后一条。
6. **旧 addon**：v1.7 及更早没有这 3 条命令 → 按钮不存在、`get_selection` 报 unknown；模型工具面不受影响。
7. **子元素粒度**：目前展开 网格（点/边/面）、骨架（编辑/姿态骨骼）、曲线/曲面控制点、晶格点；
   文本/蜡笔等编辑模式只带 `type:"OTHER"` + note，不假装知道选中了哪些元素。
   子元素选择变化**不进入 activity 指纹**（activity 仍按对象级选区判定，不逐 tick 扫描）；
   列表展开时 timer 每 0.5s 同步一次 UIList 内容（大网格展开会有枚举开销，收起即停）。
8. **热重载/重复插件的座位冲突**：同一 id 重复注册会由 slots 层报错；正式环境一次加载不会有此问题（开发期以重启为准）。

## §S6 dsh-TUI 宿主半边（v2.6.1）

dsh-TUI 不加载 `lib/client.js`，§S3 的客户端半边在 TUI 里不存在。v2.6.1 在 **host 侧**（`src/tui-host.ts`，与模型工具同进程）
用 dsh-TUI 的宿主接缝补上同一套体验。**不恢复**视口面板 / 点选，不改 15 个工具的入参与模型侧回执。

### §S6.1 启用规则

- 每块都用 `ctx.inject([...])` 懒等对应服务：宿主没有就永远不启用（Web / headless / 旧版 dsh-TUI 零影响）。
- 插件行配置 `tui: false` 整体关掉（默认 `true`）。
- `blender_viewport(op="doctor")` 多一行「TUI 宿主半边：选中 chip ✅ · 页脚 ✅ · @ 提及 ✅ · /blender ✅」，
  非 dsh-TUI 宿主时写明「未启用」。

| 块 | 宿主接缝 | 行为 |
|---|---|---|
| 选中 → chip | `tuiContextChips.attachContext`（dsh-TUI 新接缝） | 每 100 ms 轮询 `/host/selection/latest`；同一个 key `selection` 重发会**替换**上一条 chip |
| toast | `tuiToast.show`（可选） | 「已接收 Blender 选中 · 挂到下一条消息（未发送）」；挂不上时提示一次 |
| 页脚字段 | `tuiStatus.setField`（dsh-TUI #1628 起） | 每 3000 ms 读 `/host/state`，内容变了才写；`right-head`、≤ 24 cell、窄于 60 列隐藏 |
| `@` 提及 | `tuiMentions.register`（dsh-TUI 新接缝） | 第一次查询拉一份全量 `/host/scene-items`（≤ 1000 条）缓存，之后本地过滤立即返回，缓存超过 5 s 在后台刷新；插入文本与 Web codec 的 `serialize` 同口径：`<blender-object>名字</blender-object>`（材质 / 集合同理） |
| `/blender` | `commands.register`（DSH 核心，Web 也有）+ `tuiCommandTrees`（补全） | `status`（默认，零 Blender 往返）/ `doctor`（真跑一次 bpy 往返）/ `jobs` |

### §S6.2 选中 → chip 的语义

与 §S3.2 同一套 CAS：**挂上才** `consume {seq, ok:true, how:"tui-chip"}`；挂不上不消费、下一 tick 重试，
第 3 次失败 `consume {ok:false, reason}`。差别只有两处：

- 写入目标是**上下文 chip** 而不是草稿文本：chip 随用户的**下一条**消息发给模型（`<attached-context source="plugin" …>`），
  用户可以删掉，**不自动发送**；文本与 §S3.2 第 2 步逐字相同（`tests/tui_host_selftest.mjs` 对拍 `lib/client.js`）。
- 空选中直接 `consume {ok:false}`（没有可重试的东西），不再空转 3 次。

### §S6.3 `GET /host/state`（零 Blender 往返）

只读内存里的 `engine.metrics()`、租约表、render_guard 标记文件与作业台账：

```json
{
  "ok": true,
  "channel": { "lastOkAgeMs": 812, "lastCmd": "execute_code", "lastCmdAgeMs": 812, "inflight": 0,
               "lastError": null, "lastErrorAgeMs": null, "diagnosis": null, "aiPaused": false },
  "lease": { "...与 /who 的 lease 同形..." },
  "render": { "busy": false, "ageMs": null, "scene": null },
  "jobs": { "running": 0 },
  "backend": { "pid": 4242, "uptimeMs": 61234 }
}
```

- `aiPaused`：addon「暂停 AI 操作」拒掉一条命令时置 `true`（协议层只留下 message「AI 操作已暂停：…」），**下一次成功即清空**。
  后端不为它轮询 Blender，所以暂停后要等 AI 下一次被拒才会显示。
- `channel.lastOkAgeMs === null` = 这个后端进程里 GUI 通道从没成功过（页脚显示「未连接」）。

### §S6.4 页脚优先级

`后端不可达 ○` → `AI 暂停 ⏸` → `渲染中` → `主线程忙` → `未连接 ○` → `他人租约` → `●`（正常）；有 headless 作业在跑时文本尾部加「· 作业 N」。
悬停说明写明原因与修法（`detail`，≤ 160 cell）。

### §S6.5 已知边界

1. chip 只进**当前绑定的会话**；还没进会话（launchpad）时挂不上，3 次后按失败消费（与 Web 的「只进当前会话」一致）。
2. Web 客户端与 dsh-TUI 同时连同一个后端时两边都会轮询，谁先挂上谁消费（同 §S5.5）。
3. `@` 提及：dsh-TUI 每次查询只给约 300 ms，而 `/host/scene-items` 至少两次 bpy 往返（模块探测 + 查询，首次还要注入），直接查经常超时。
   所以走缓存（§S6.1 表）：**冷启动那一次**多半超时、回空，但缓存会填上，下一次按键就有结果；对象改名后最多 5 s 才反映到候选里。
   只在用户打 `@` 时才碰 Blender，不轮询。
4. dsh-TUI 侧的 `tuiContextChips` / `tuiMentions` 接缝在 ccch1mneyyy/dsh-TUI 另行提交；接缝落地前，对应两块不启用。
