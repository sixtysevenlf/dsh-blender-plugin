# 证据分级与读图纪律（v0.8.10 / 外部反馈 92 §4-§5 落地）

> 来源：j20-build 项目五方实测（92 报告）。核心结论：**"致命判断 100% 来自脚本，不来自看图"** ——
> lead 读了 ≈26 张图（约 2–3 万 token），其中至少 2 张是完全无效的重复；而抓到的重量级缺陷
>（自交 13 处、零面积面 39 处、二面角 90 分位 11.61°、UV 唯一率 21.5%、舱盖缝 20.36 mm、逐部位隔离失效）
> **全部是脚本量出来的**。所以把"看图"从**巡检手段**降级为**异常确认手段**。

## 1. 成本模型（先算账）

视觉输入成本 ≈ 像素面积成正比（经验式 \`tokens ≈ W×H/750\`）：

| 用途 | 尺寸 | ≈tokens | 相对成本 |
|---|---|---|---|
| 整机 beauty | 1600×900 | 1920 | **25×** |
| 整机 QC | 1280×720 | 1229 | 16× |
| 部位 QC | 960×540 | 691 | 9× |
| 二值轮廓叠合 | 800×450 | 480 | 6× |
| **异常小裁切** | 240×240 | **77** | **1×** |

推论：**一张整机图 = 25 张 240×240 的小裁切**。而且模型看到的图是降采样+重编码副本，脚本读的是磁盘原图 ——
**付费买低分辨率副本 vs 免费拿全分辨率原图**，这个不对称就是优化的支点。

## 2. 四级证据制度（只有 L2/L3 才允许读图）

| 级别 | 形式 | 谁读 | 单次成本 | 用途 | 必须出现的场合 |
|---|---|---|---|---|---|
| **L0** | 数值指标表（期望 vs 实际 + PASS/FAIL） | 脚本生成，模型读**文本** | ≈0 | 尺寸/角度/自检计数/耗时/IoU 矩阵/二面角分布/UV 唯一率 | **每一轮、每一次改动** |
| **L1** | 二值轮廓叠合图（≤800×450，参考红/模型蓝/重合黑） | 模型读 1 张 | ≈480 | 几何偏差一眼可见，且可计算 | 每个阶段门 |
| **L2** | 异常区域小裁切（≤320×320，一次 ≤6 张） | 模型读 | ≈6×140 | 确认"脚本指出的异常到底长什么样" | **仅当 L0 出 FAIL** |
| **L3** | 整机成品渲染（beauty） | 模型读 1–2 张 | ≈1900 | 审美终判（最终由用户裁决） | 仅里程碑 / 交付 |

**核心纪律：L0 不出 FAIL，就不允许读 L1/L2；L3 只给用户看，不作为几何正确性的依据。**

## 3. 每轮读图预算（写死）

1. **每轮 ≤ 6 张图，每张 ≤ 800×450**（≈≤4.3k tokens/轮）。
2. **读图前**必须由脚本输出"最异常的 N 个区域"（排序依据：IoU 最低 / 二面角 90 分位最高 / 边界偏差最大 / 掩膜面积差最大）。
3. **读图前先写断言**：这张图要验证哪 2–3 条**可测命题**。
4. **读图后写三分法**：【确认看到的】【推断的】【我没有能力判断的】；凡无法用数字证实的视觉判断，
   必须标注 **"未经证实的视觉印象"**，不得写成"通过"。
5. 整机图只留给交付确认 1–2 张。

> 反直觉点：**拼图不省 token**（像素总量不变），省的是**调用次数与注意力**；要省 token 只能"降像素"或"不读图"。

## 4. 工具映射（哪条 op 产出哪一级）

| 级别 | 用什么产出 |
|---|---|
| **L0** | \`blender_rt_plan(op="audit_scene")\` 网格体检 · \`audit_mesh\` 单件深挖 · \`audit_duplicates\` 同名资源 · \`qc_compare\`（IoU/Dice/缺多面积/边界距离/剖面差，含 warnings）· \`qc_render_views\` 的 \`render_views.jsonl\`（逐张 ms/bytes/md5/coverage/margin） |
| **L1** | \`qc_compare\` 的三联 sheet（参考\|渲染\|叠合）· \`qc_render_views\` 的 \`sheet=N\`（N 宫格 + 网格 + 标尺 + 每格指标） |
| **L2** | \`montage\`（\`K.dsh_montage_api\`）裁切拼图：\`tile=420\`、总宽 ≤1700 px、12–16 格；异常优先只给 3 个最大偏差区域 |
| **L3** | \`qc_render_views\` 多视角出图（\`warmup=true\` 让单张耗时干净）· \`blender_rt_see\` 自定义视角 |

**阈值说明**：12–16 格 / tile 400–420 / 总宽 ≤1700 px 来自 j20-build 实测（ref-scout：6 次调用覆盖 66 张，省约 51 次单图调用；
超过 ~1700 px 会被 harness 二次缩放，小格细节先糊）。这些是**默认值、可配**，不是定律。

## 5. 场景化配方

- **每轮改动**：\`audit_scene\` + \`qc_render_views\`（3–4 视角 + jsonl）→ 只读 L0 表；FAIL 才进 L2。
- **阶段门**：加 1 张 L1 轮廓叠合（\`qc_compare\` 的 sheet）。
- **交付**：加 1 张 L3 beauty + \`audit_duplicates\`（防止同名分叉的资源混进交付件）。
- **"这个细节对不对"**：先写成可测命题（缝宽 mm / 波峰数 / 二面角分位 / UV 唯一率）→ 脚本量 → 只有脚本说不清时才看图。
