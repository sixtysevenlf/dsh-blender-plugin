# 证据分级与读图纪律（v0.8.10 / 外部反馈 92 §4-§5 落地）

> 来源：j20-build 项目五方实测（92 报告）。核心结论：**"致命判断 100% 来自脚本，不来自看图"** ——
> lead 读了 ≈26 张图（约 2–3 万 token），其中至少 2 张是完全无效的重复；而抓到的重量级缺陷
>（自交 13 处、零面积面 39 处、二面角 90 分位 11.61°、UV 唯一率 21.5%、舱盖缝 20.36 mm、逐部位隔离失效）
> **全部是脚本量出来的**。所以把"看图"从**巡检手段**降级为**异常确认手段**。

## 1. 成本模型（先算账）

视觉输入成本 ≈ 像素面积成正比（经验式 \`tokens ≈ W×H/750\`）：

| 用途 | 尺寸 | ≈tokens | 相对成本 |
|---|---|---|---|
| 整机 beauty | 1600×900 | 1920 | **25×** |
| 整机 QC | 1280×720 | 1229 | 16× |
| 部位 QC | 960×540 | 691 | 9× |
| 二值轮廓叠合 | 800×450 | 480 | 6× |
| **异常小裁切** | 240×240 | **77** | **1×** |

推论：**一张整机图 = 25 张 240×240 的小裁切**。而且模型看到的图是降采样+重编码副本，脚本读的是磁盘原图 ——
**付费买低分辨率副本 vs 免费拿全分辨率原图**，这个不对称就是优化的支点。

## 2. 四级证据制度（只有 L2/L3 才允许读图）

| 级别 | 形式 | 谁读 | 单次成本 | 用途 | 必须出现的场合 |
|---|---|---|---|---|---|
| **L0** | 数值指标表（期望 vs 实际 + PASS/FAIL） | 脚本生成，模型读**文本** | ≈0 | 尺寸/角度/自检计数/耗时/IoU 矩阵/二面角分布/UV 唯一率 | **每一轮、每一次改动** |
| **L1** | 二值轮廓叠合图（≤800×450，参考红/模型蓝/重合黑） | 模型读 1 张 | ≈480 | 几何偏差一眼可见，且可计算 | 每个阶段门 |
| **L2** | 异常区域小裁切（≤320×320，一次 ≤6 张） | 模型读 | ≈6×140 | 确认"脚本指出的异常到底长什么样" | **仅当 L0 出 FAIL** |
| **L3** | 整机成品渲染（beauty） | 模型读 1–2 张 | ≈1900 | 审美终判（最终由用户裁决） | 仅里程碑 / 交付 |

**核心纪律：L0 不出 FAIL，就不允许读 L1/L2；L3 只给用户看，不作为几何正确性的依据。**

## 3. 每轮读图预算（写死）

1. **每轮 ≤ 6 张图，每张 ≤ 800×450**（≈≤4.3k tokens/轮）。
2. **读图前**必须由脚本输出"最异常的 N 个区域"（排序依据：IoU 最低 / 二面角 90 分位最高 / 边界偏差最大 / 掩膜面积差最大）。
3. **读图前先写断言**：这张图要验证哪 2–3 条**可测命题**。
4. **读图后写三分法**：【确认看到的】【推断的】【我没有能力判断的】；凡无法用数字证实的视觉判断，
   必须标注 **"未经证实的视觉印象"**，不得写成"通过"。
5. 整机图只留给交付确认 1–2 张。

> 反直觉点：**拼图不省 token**（像素总量不变），省的是**调用次数与注意力**；要省 token 只能"降像素"或"不读图"。

## 4. 工具映射（哪条 op 产出哪一级）

| 级别 | 用什么产出 |
|---|---|
| **L0** | \`blender_rt_plan(op="audit_scene")\` 网格体检 · \`audit_mesh\` 单件深挖 · \`audit_duplicates\` 同名资源 · \`qc_compare\`（IoU/Dice/缺多面积/边界距离/剖面差，含 warnings）· \`qc_render_views\` 的 \`render_views.jsonl\`（逐张 ms/bytes/md5/coverage/margin） |
| **L1** | \`qc_compare\` 的三联 sheet（参考\|渲染\|叠合）· \`qc_render_views\` 的 \`sheet=N\`（N 宫格 + 网格 + 标尺 + 每格指标） |
| **L2** | \`montage\`（\`K.dsh_montage_api\`）裁切拼图：\`tile=420\`、总宽 ≤1700 px、12–16 格；异常优先只给 3 个最大偏差区域 |
| **L3** | \`qc_render_views\` 多视角出图（\`warmup=true\` 让单张耗时干净）· \`blender_rt_see\` 自定义视角 |

**阈值说明**：12–16 格 / tile 400–420 / 总宽 ≤1700 px 来自 j20-build 实测（ref-scout：6 次调用覆盖 66 张，省约 51 次单图调用；
超过 ~1700 px 会被 harness 二次缩放，小格细节先糊）。这些是**默认值、可配**，不是定律。

## 5. 场景化配方

- **每轮改动**：\`audit_scene\` + \`qc_render_views\`（3–4 视角 + jsonl）→ 只读 L0 表；FAIL 才进 L2。
- **阶段门**：加 1 张 L1 轮廓叠合（\`qc_compare\` 的 sheet）。
- **交付**：加 1 张 L3 beauty + \`audit_duplicates\`（防止同名分叉的资源混进交付件）。
- **"这个细节对不对"**：先写成可测命题（缝宽 mm / 波峰数 / 二面角分位 / UV 唯一率）→ 脚本量 → 只有脚本说不清时才看图。

## 6. 两条硬规则：像素行序（E1）与批量射线（E2）（v0.9.3 / 93 反馈 §6）

### 6.1 E1 · Blender 的 `image.pixels` / `foreach_get` 是**自下而上**的

> **硬规则：任何把 Blender 像素缓冲与 PIL / cv2 / PNG 解码器对拍的地方，先 `[::-1]`。**

**代价证据**：reviewer 因此误判「相机重建与渲染不一致」，甚至怀疑渲染脚本被改，追了 **~4 轮 / 20 分钟**；
加上 `[::-1]` 之后同一组对拍：IoU **0.463 → 0.955**、**0.786 → 0.972**。

```python
import numpy as np, bpy

def load_rgba_top_down(path):
    """Blender 图像 → (h, w, 4) float32，行序与图像坐标一致（上→下）。"""
    img = bpy.data.images.load(path, check_existing=False)
    w, h = int(img.size[0]), int(img.size[1])
    buf = np.empty(w * h * 4, dtype=np.float32)
    img.pixels.foreach_get(buf)        # foreach_get 比 list(img.pixels) 快 1~2 个数量级
    return buf.reshape(h, w, 4)[::-1]  # ← 关键：Blender 的第 0 行 = 图像**底部**
```

**对拍自检（copy-paste，期望 < 1/255）**：

```python
from PIL import Image
a = load_rgba_top_down("/mnt/d/work/out/front.png")
b = np.asarray(Image.open("/mnt/d/work/out/front.png").convert("RGBA"), dtype=np.float32) / 255.0
print("max_abs_diff =", float(np.abs(a - b).max()))   # 不给 [::-1] 会得到"上下翻转"的大差值
```

**不翻的症状**：掩膜上下颠倒 → IoU 掉一半、剖面差爆表、`qc_compare` 的「缺面积」与「多面积」**同时**很大
（同一个轮廓不可能既缺又多 —— 看到这个组合先怀疑行序）。

**已经替你翻好的通路**（别重复翻）：

| 通路 | 行序 |
|---|---|
| `K.dsh_qc_api["load"](path)` → `(srgb[h,w,3], alpha[h,w])` | **已翻成上→下**（qc.py 文档串原文） |
| `K.dsh_qc_api["compare"]` / `qc_render_views` 的 `ref_path` 比对 | 走上面的 load，已翻 |
| 自己 `image.pixels.foreach_get` / `img.pixels[:]` | **未翻** → 必须 `[::-1]` |

一句话：**用 qc API 就不用翻；自己 foreach_get 就必须翻** —— 两者混用才是翻车点。

### 6.2 E2 · 批量射线用 `BVHTree.FromPolygons + bvh.ray_cast`，别用 `scene.ray_cast`

> **硬规则：逐像素 / 逐采样点的射线批量查询，一律先建 BVH 再 `bvh.ray_cast`；
> `scene.ray_cast` 只适合"手点几下"的偶发查询。**

**代价证据**：reviewer 用 `scene.ray_cast` 两次撞 120 s / 600 s 上限（≈12 分钟 + 2 轮返工）；
换 `BVHTree` 后同样工作量 **0.6~0.9 s/机位**。原因：`scene.ray_cast` **每次调用都过 depsgraph**
（求值 + 更新），逐像素 = 逐像素过 depsgraph。

```python
import bpy, numpy as np
from mathutils.bvhtree import BVHTree

def world_tris(objs):
    """可见 mesh 的**世界坐标**三角面 (N,3,3) float64 —— 与 audit.py 的 _bvh_from_tris 同口径。"""
    dg = bpy.context.evaluated_depsgraph_get()
    out = []
    for ob in objs:
        if ob.type != "MESH" or ob.hide_render:
            continue
        me = ob.evaluated_get(dg).to_mesh()
        me.calc_loop_triangles()
        v = np.empty(len(me.vertices) * 3, dtype=np.float64)
        me.vertices.foreach_get("co", v)
        v = v.reshape(-1, 3)
        idx = np.empty(len(me.loop_triangles) * 3, dtype=np.int32)
        me.loop_triangles.foreach_get("vertices", idx)
        tris = v[idx.reshape(-1, 3)]                                    # (T,3,3)
        mw = np.array(ob.matrix_world)
        tris = np.concatenate([tris, np.ones((len(tris), 3, 1))], axis=2) @ mw.T
        out.append(tris[:, :, :3])
        ob.evaluated_get(dg).to_mesh_clear()
    return np.concatenate(out) if out else np.zeros((0, 3, 3))

def build_bvh(tris):
    V = tris.reshape(-1, 3).tolist()
    polys = [(3 * i, 3 * i + 1, 3 * i + 2) for i in range(len(tris))]
    return BVHTree.FromPolygons(V, polys, all_triangles=True)   # all_triangles=True → 返回 index = 三角面下标

bvh = build_bvh(world_tris([o for o in bpy.data.objects if o.type == "MESH"]))
hit = bvh.ray_cast((0.0, 0.0, 5.0), (0.0, 0.0, -1.0), 100.0)    # → (loc, normal, index, dist) 或 (None,)*4
```

**批量用法（遮挡 / 可见性 / 奇偶判定）**：

```python
def ray_hits(bvh, origins, dirs, limit=1e4):
    """origins / dirs: (M,3)。返回 (M,) bool —— 命中即 True。"""
    return np.array([bvh.ray_cast(tuple(map(float, o)), tuple(map(float, d)), limit)[0] is not None
                     for o, d in zip(origins, dirs)], dtype=bool)
```

两条实践注意（audit.py 的实测结论，照抄不吃亏）：

1. **命中后要沿方向前进 eps 再打**（否则原地自命中，奇偶计数全错）；迭代上限写死并**回报 unknown** ——
   别把「没判出来」当成「没相交」；
2. `BVHTree.FromPolygons` 的构建成本随面数线性涨：面数超 ~50 万时先按 bbox 分格，或退化成点对点距离
   （audit 里 `BVH_MAX_TRIS = 500000` 就是这个口径）。

> `ds_raycast_batch()` 内核辅助**尚未实现**（93 反馈 E2 的建议项）—— 在那之前，上面两个函数就是可用形态。

## 7. 读图量测（附录 A / T-A4 落地，v0.9.3）

> 适用场景：**没有正交三视图，只有官方 3/4 透视美图**，要靠它量尺寸、定站位、锁比例。
> 本轮代价：母图被统一降采样到 1500 px（≈55 px/m）再分发 —— 0.1 m 板缝 ≈5 px、0.05 m 铆钉 ≈2 px，
> **等于不可读**；原生分辨率约 **126 px/m**（缝 12.6 px）。站位表是 Lead **目测**填的却被写成冻结契约，
> 6 路分件据此对齐 → **错误自洽**（装配完美、整体偏离真船）；全程**零量化校验**（没有剪影 IoU / 边缘叠加）。

### 7.1 四条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **禁用量测自缩图**：量测在**原生分辨率**图上做；只有给模型看的图才降采样 | 降采样后 <0.3 m 的特征在图上只剩几个像素，量出来的就是噪声 |
| 2 | **量测必须带 provenance 与误差**：每条尺寸记 源图路径 + md5 / 原生尺寸 / 降采样倍率 / px_per_m / 换算误差 | 没有 provenance 的数字无法复核，源图更新后也无法判失效 |
| 3 | **< 0.3 m 的特征必须有原生裁剪**（不缩放的原图裁剪 + 坐标） | 这是「图上到底读不读得出来」的唯一判据 |
| 4 | **透视图的 X 向站位一律标「近似」**（带 ± 误差区间），不得写成冻结契约 | 3/4 透视里沿视线方向的位移不能直接换算；目测站位写成契约会把误差放大到全局 |

### 7.2 px/m 标定与 provenance（复制即用）

```python
import json, hashlib
import numpy as np
from PIL import Image

def ref_measure_stub(image, p1, p2, known_len_m):
    """【临时替代】在原生图上量一条已知长度 → px_per_m，并记 provenance。
    注意：ref_measure 原语尚未实现（见 §7.4），这是最小可用版。"""
    im = Image.open(image); W, H = im.size
    md5 = hashlib.md5(open(image, "rb").read()).hexdigest()
    px = float(np.hypot(p2[0] - p1[0], p2[1] - p1[1]))
    return {"image": image, "md5": md5, "native_px": [W, H], "p1": p1, "p2": p2,
            "known_len_m": known_len_m, "px": round(px, 2),
            "px_per_m": round(px / known_len_m, 3),
            "err_m_per_px": round(known_len_m / px, 5),
            "err_m_at_300px": round(300.0 * known_len_m / px, 4)}   # 离标定线 300 px 处的累积误差

print(json.dumps(ref_measure_stub("/mnt/d/ref/aurora_native.png", (820, 640), (1620, 648), 6.45),
                 ensure_ascii=False))
# → {"px_per_m": 124.03, "err_m_per_px": 0.00806, "err_m_at_300px": 2.419, ...}
```

**站位表必须长这样**（带误差与来源，否则不叫契约）：

```python
stations = [

```

> 6 路分件对齐得很好，整体却偏了。**没有 err_m 与 md5 的站位表，不许进契约。**

### 7.3 原生裁剪（不缩放）与可读性判据

```python
import os, json
from PIL import Image

def ref_crop_native(image, crops, outdir):
    """【临时替代】原生分辨率裁剪（**不缩放**）+ 元数据清单。
    注意：ref_crop_atlas 原语尚未实现（见 §7.4）。"""
    im = Image.open(image).convert("RGB"); W, H = im.size
    os.makedirs(outdir, exist_ok=True)
    rows = []
    for c in crops:
        x0, y0, x1, y1 = c["box_px"]
        tile = im.crop((x0, y0, x1, y1))          # 关键：不 resize
        p = os.path.join(outdir, "%s.png" % c["name"])
        tile.save(p)
        rows.append({"name": c["name"], "box_px": [x0, y0, x1, y1], "px": [x1 - x0, y1 - y0],
                     "scale": 1.0, "source": image, "source_px": [W, H], "path": p})
    json.dump(rows, open(os.path.join(outdir, "atlas.json"), "w"), ensure_ascii=False, indent=2)
    return rows

def unreadable(features, px_per_m=55.0, min_px=8):
    """图上 < min_px 的特征 = 不可读 → 换更近的来源，或标成「未知」（不许猜）。"""
    return [{"feature": f["name"], "m": f["m"], "px": round(f["m"] * px_per_m, 1), "verdict": "不可读"}
            for f in features if f["m"] * px_per_m < min_px]

# 本轮实际口径：分发图 ≈55 px/m
print(unreadable([{"name": "板缝", "m": 0.10}, {"name": "铆钉", "m": 0.05}], px_per_m=55.0))
# → 板缝 5.5 px / 铆钉 2.8 px，全部「不可读」；换原生图（124 px/m）后 12.4 px / 6.2 px
```

### 7.5 剪影对拍：现在就能做（T-A5）

`qc_compare` 已有 IoU / Dice / 缺面积 / 多面积 / 边界距离 / 逐层剖面差 + 三联对照图（参考 | 渲染 | 叠合），
**并且可以 headless 直调**：

```python
blender_rt_headless(preload="qc", script="""
import json
r = K.dsh_qc_api["compare"]("/mnt/d/ref/aurora_front_native.png", [820, 300, 1500, 1400],
                             "/mnt/d/work/out/front.png", label="front",
                             out_dir="/mnt/d/work/out/qc")
print('HEADLESS ' + (r if isinstance(r, str) else json.dumps(r, ensure_ascii=False)))
""")
```

口径（v0.8.3 起，照抄别记错）：`iou` 是**固定对齐**（诚实值），搜索对齐另给 `iou_search`；
**尺度漂移 > 5%** 与 **搜索吸收 > 0.05** 都会告警；`ref_box` 可省略（默认整图）。

> **阶段门建议（附录 A.3）**：把「白模与比例锁定」当**硬关卡** ——
> 入口条件 = **带误差的站位表 + 原生特征裁剪图册 + 剪影 IoU 达标**；不达标不派分件任务。
> 本轮跳过了它直接进细节还原，于是「每块板都倒角、每颗铆钉都算面数」的工程投入全花在了错误的轮廓上。
