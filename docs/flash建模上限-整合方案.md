# flash 建模上限：门 · 人形人脸 · 视觉感知 三方整合方案

> 结论先行：**上限 = 外部通路的覆盖面**，不是模型能力。
> flash（deepseek-v4.1-flash）在本项目里暴露的三类问题——门靠不住、人形人脸做不好、看不清参考图——
> 是**同一个根因**的三个切面：**凡需要"眼力 / 专业经验 / 主观判断"的环节，它都不可靠**。
> 提上限的唯一有效方向：**把这些环节换成外部可计算的通路，模型只负责编排与读数字。**

## 0. 统一诊断

| 环节 | flash 的短板表现 | 本项目的实测证据 |
|---|---|---|
| **验收（门）** | 它说"看着行"，判据不成体系 | 111 条失败里 68% 是超时；长尾 5 个新族**真实使用 0 次**（"不熟的不敢用"） |
| **创作（人形/人脸）** | 解剖/比例/拓扑是专业知识，逐点控制做不到 | 一次 95 对象装配里 `sculpt_*` **一次没调用**（形种不对 + 改拓扑不可复算） |
| **观察（视觉）** | 分辨率先降采样、计数与小目标识别天生弱 | 现场靠 `rt_see` 抓到 5 处形体缺陷，但细节类判据仍要人给数值 |

统一公式：

```
可靠产出 = 模型能稳定做到的（编排 / 填参数 / 读数字）
         + 外部通路能覆盖的（测量 / 几何 / 规则 / 资产）
```

flash 的短板**全部落在第二项**——所以手段不是"让它变强"，而是**把第二项做大**。

## 1. 目标管线（每个环节都产出数字，且至少两条独立通路）

```
参考图/图纸 ──► [测量·OCR·向量直读] ──► spec.py（数字，冻结）
                                          │
                                          ▼
                    [参数化生成 / 资产基座 + landmarks 拟合]
                                          │
                                          ▼
                     [几何门] audit/fix/print  ─┐
                     [资产门] glTF-Validator    ├─► verdict（三态，脚本给结论）
                     [比例门] head/human ratios ─┘
                                          │
                                          ▼
                        渲染 ──► [差分·IoU·landmark 误差] ──► 数字反馈
```

**硬规则**：任一环节只有一条通路时，上限就是那条通路的盲区（本轮实测到的"正好相贴被误报成浮块"就是单通路盲区）。

## 2. 最终手段清单

### P0 · 当天可交付（零外部依赖）

| # | 手段 | 做什么 | 验收口径 |
|---|---|---|---|
| 1 | **门标定套件** | 故意注入 8 类缺陷（平移超差 / 删铆钉 / 断流形 / 反转法线 / 薄壁 / 自交 / 浮块 / 重复件），断言"每类都被某条门抓住" | **缺陷捕获率**（目标 ≥7/8）；抓不住的立刻暴露成待补的门 |
| 2 | **感知四件套** | `img_scan`（轮廓/bbox/长宽比/主轴角/直线角度/取色）· `img_crop`（ROI 裁剪+上采样）· `img_annotate`（坐标与比例线画回图）· `img_diff`（轮廓差分+热图+IoU） | 同一张参考图："直接问模型" vs "`img_scan` 出数字"的**误差对比** |
| 3 | **比例门 + 数值配方** | `head_proportions` / `human_proportions`（眼线位置、五眼宽、三庭、头身比、肩宽…）进 gate spec；技能补"人脸/人形"两节，写明**禁自由雕** | 比例超差能被 `pass_if` 抓到；配方可复现 |
| 4 | **感知协议（技能层）** | ① 看图必须产出 spec.py 数字，否则算白看；② 每次 ≤2 张图且带明确问题（yes/no 或数字）；③ 每张图带像素↔毫米标尺；④ 后续轮次只消费数字 | 技能评审通过；后续任务不再重复读图 |

### P1 · 1–3 天（少量外部依赖）

| # | 手段 | 依赖 | 收益 |
|---|---|---|---|
| 5 | **参考图 → landmark → 拟合** | MediaPipe Face Mesh / EMOCA / MPFB2 | 识别度来自参考图**算出来的** landmarks，模型不碰顶点 |
| 6 | **资产门**：`deliver_verify` 接 glTF-Validator | node / CLI | 交付物"能不能被下游解析"变成规则码门 |
| 7 | **第二自交通路**：Open3D 或 pymeshlab 复核自交/水密 | pip（独立进程，不塞进 Blender） | 两条通路不一致 = 有一条有盲区 |
| 8 | **face eval harness** | 无 | 给出 **landmark 误差 / 头部轮廓 IoU / 首次通过率** 三个基线数字，改革才有参照 |

### P2 · 按需（当 spec 复杂或要求 CAD 级精度时）

| # | 手段 | 何时值得 |
|---|---|---|
| 9 | OCCT（pythonocc）：`BRepCheck_Analyzer` / `BRepExtrema_DistShapeShape` / `BRepAlgoAPI_Common` | ±3 mm 公差与互插体积要"算出来"而不是"网格近似出来" |
| 10 | manifold3d：构造性布尔 | 想让非法几何**不可能产生**，而不是事后修 |
| 11 | OCR（tesseract/PaddleOCR）· DXF/STEP 直读（ezdxf/OCCT） | 参考是**工程图/图纸**时收益最大：数字精确、视觉完全绕开 |
| 12 | 策略语言升级（Rego / CUE / JSON Schema） | gate spec 复杂到需要复用/继承/版本化 |
| 13 | inspect_ai：给**验证者代理**做评测 | 验证者开始承担主观门时，回答"它到底抓不抓得住" |

## 3. 明确不做（都不解决根因）

1. 给 flash 加更多雕刻笔刷 / 更细的 prompt —— 让它**手写人脸顶点**在结构上做不到；
2. 指望"给它更高分辨率的图" —— 视觉编码器先降采样，小细节在编码阶段就丢了；
3. 用"换代理"代替"换通路" —— 独立验证子代理的价值在**陌生视角**，不在**更细的观察**（省 token 那轮已实测：门调用本身很便宜，贵的是重复加载上下文）。

## 4. 一周落地路线

| 天 | 做什么 | 当天验收 |
|---|---|---|
| D1 | 门标定套件 + 感知四件套 | 缺陷捕获率报告 + 参考图误差对比表 |
| D2 | 比例门（head/human）+ 技能两节（含禁自由雕硬规则） | 比例超差能被门抓到；配方跑通 |
| D3 | face eval harness（拿基线） | landmark 误差 / 轮廓 IoU / 首次通过率 |
| D4–5 | 拟合路径（MPFB2 基座 或 MediaPipe/EMOCA landmarks） | face eval 三个数字 vs D3 基线 |
| D6–7 | 资产门（glTF-Validator）+ 第二自交通路（Open3D/pymeshlab） | 交付物规则码门通过；两通路一致性报告 |

## 5. 一句话

> **不要训练模型的眼睛和手，要给它们外挂量具、模具和验收标准。**
> 模型负责编排、填参数、读数字；测量、几何、规则、资产交给外部通路——这就是 flash 在本项目里的上限。
