# 配置参考（分享版）

> 分享版的全部机器相关设置都在 `runtime/config.mjs`：**环境变量 → 配置文件 → 自动探测 → 默认值**。
> 作者自用版把这些写死在源码里；分享版**换机器不用改任何代码**。

---

## 1. 优先级链（高 → 低）

```text
┌ 1. 环境变量        DSH_BLENDER_*（见 §3）
├ 2. 配置文件        $DSH_BLENDER_CONFIG
│                    → <包根>/dsh-blender.config.json
│                    → ~/.dsh/dsh-blender.config.json
├ 3. 自动探测        工作目录（Windows %LOCALAPPDATA%\dsh-blender-rt，取不到则 os.tmpdir()）
│                    blender.exe（Program Files / Steam 常见位置 / PATH）
└ 4. 内置默认        addon 127.0.0.1:9876 · 后端 127.0.0.1:9877 · 租约 TTL 600000 ms · holder=plugin-pid-<pid>
```

**怎么确认当前生效的是什么**：

```bash
curl -sS http://127.0.0.1:9877/who | python3 -m json.tool | sed -n '/"config"/,/}/p'
# 或者让模型调：blender_viewport(op="doctor")   → 返回里的 config 段
```

`config` 段里会写明 `configFile`（用了哪个配置文件，没用到就是 `null`）、`workDir.from`、`blenderFrom`（配置 / 自动探测 / path / not-found）。

## 2. 配置文件

复制样例并改名即可生效：

```bash
cp dsh-blender.config.example.json dsh-blender.config.json
```

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `workDir` | string | 自动 | 帧 PNG / 无头脚本 / 临时产物目录。**Windows 形式**（`D:\\work\\dsh-blender-rt`）；WSL 下会映射成 `/mnt/d/...`。必须"两端都能读写" |
| `blenderExe` | string | 自动 | blender 可执行文件。WSL 里给 `/mnt/d/.../blender.exe`（Windows 进程）；纯 Windows 给 `D:\\...\\blender.exe` |
| `addonHost` | string | `127.0.0.1` | addon 监听地址（一般不用改） |
| `addonPort` | number | `9876` | addon 端口（addon 面板里可改；这里要一致） |
| `addonProtocol` | string | `auto` | Blender 侧 addon 的线上协议：`auto`（探测一次并缓存）/ `ahujasid` / `category-action`。见 §6 末「两种 addon 协议」 |
| `httpPort` | number | `9877` | 本插件后端端口（两台 Blender 并存时改一台） |
| `holder` | string | `plugin-pid-<pid>` | 写通道租约身份（多会话时便于分辨谁在写） |
| `leaseTtlMs` | number | `600000` | 租约有效期；持有者每次都续期，超时自动失效 |
| `blenderUserConfig` | string | `null` | 用户 Blender 配置目录（GPU 偏好所在）。**无头进程默认读不到它** → 想继承就设它并配合 `factory_startup=false`（env：`DSH_BLENDER_USER_CONFIG`） |
| `blenderUserScripts` | string | `null` | 用户 Blender 脚本目录（addon 所在），同上（env：`DSH_BLENDER_USER_SCRIPTS`） |
| `workerPort` | number | `9879` | 热无头 worker 的本地端口（与 addon 9876 / 后端 9877 区分；env：`DSH_BLENDER_WORKER_PORT`） |

| 变量 | 等价于 | 备注 |

## 4. blender.exe 怎么被找到

探测顺序（`config.mjs:detectBlenderExe`）：

1. `DSH_BLENDER_EXE` 环境变量；
2. 配置文件 `blenderExe`；
3. **自动扫描**：
   - Windows：`%ProgramFiles%\\Blender Foundation\\Blender*\\blender.exe`（按目录名排序取第一个存在的）；
   - WSL：`/mnt/{c,d,e,f}/Program Files/Blender Foundation/Blender*/blender.exe`，以及 `SteamLibrary/steamapps/common/Blender/blender.exe`、`Steam/steamapps/common/Blender/blender.exe`；
4. `PATH`（Windows `where blender`；Linux `which blender`）；
5. 都没有 → `config.blenderExe = null`，`blender_rt_headless` 会报 `blender-exe-missing` 并提示三种配置方式。

**三种配置方式（任选）**：

```bash
# ① 环境变量
export DSH_BLENDER_EXE=/mnt/d/SteamLibrary/steamapps/common/Blender/blender.exe     # WSL
#   Windows: set DSH_BLENDER_EXE=D:\Program Files\Blender Foundation\Blender 5.2\blender.exe

# ② 包根配置
echo '{"blenderExe":"/mnt/d/.../blender.exe"}' > dsh-blender.config.json

# ③ 用户级配置（多个工程共用）
mkdir -p ~/.dsh && echo '{"blenderExe":"/mnt/d/.../blender.exe"}' > ~/.dsh/dsh-blender.config.json
```

## 5. 工作目录（为什么要"成对"）

Blender（Windows 进程）负责**写**帧 PNG 与无头脚本；宿主（WSL 里的 Node）负责**读**它们。所以需要同一个物理目录的两个写法：

| | 例子 |
|---|---|
| Blender 侧（Windows 路径） | `C:\Users\\<你>\\AppData\\Local\\dsh-blender-rt` |
| 宿主侧（WSL 路径） | `/mnt/c/Users/<你>/AppData/Local/dsh-blender-rt` |

- 默认自动取 Windows 的 `%LOCALAPPDATA%\\dsh-blender-rt`（在 WSL 里通过 `cmd.exe /c echo %LOCALAPPDATA%` 问一次，结果会缓存）；
- 取不到（没有 WSL 互操作 / 纯 Linux）→ 退回 `os.tmpdir()/dsh-blender-rt`（此时要求 Blender 与宿主同机）；
- **不要**配成 WSL 内部路径（如 `/home/me/x`）：Windows Blender 只能通过 UNC 访问，而 **UNC 写入会静默失败**；
- 别配到只读挂载（WSL 里 `/mnt/c` 通常只读，除非你在 Windows 侧开了对应权限）。

## 5.5 GPU 语义（无头渲染最贵的坑）

**问题**：无头进程（`blender -b`）**默认读不到用户偏好** → `prefs.compute_device_type = NONE`、设备列表为空 → 即使工程文件里写着 `scene.cycles.device = "GPU"`，**Cycles 也会静默跑 CPU**。
本机实测（1821 对象工程，480×270/32spp）：**CPU 2.78 s vs GPU 预热 0.18 s = 15.4×**。

**三层解法**（按推荐顺序）：

1. **默认的 `gpu:"auto"` 前导**（零配置）：按 `OPTIX→CUDA→HIP→ONEAPI→METAL` 顺序设置 `compute_device_type` + 勾选 GPU 设备 + `scene.cycles.device="GPU"`，并回传 `gpu` 字段（`before/after/configured/fell_back_to_cpu`）；
2. **`use_user_config: true`**：透传 `BLENDER_USER_CONFIG` / `BLENDER_USER_SCRIPTS`（配合 `factory_startup=false`，让无头进程继承你那套偏好与 addon）；
3. **`gpu: "true"`**：要求必须有 GPU，没有就 `ok=false`（不想再被静默降级坑一次时用）。

> 一句话：**别信文件里的 `device=GPU`，要看回执里的 `gpu.after.gpu_enabled`。**

## 5.6 热无头会话与长任务

| 场景 | 用什么 | 说明 |
|---|---|---|
| 一次性重活（渲染/批量几何/校验） | `blender_rt_headless` | 冷启动 0.9–1.2 s，干净、可复现 |
| **反复迭代**（几十次重建/导入） | **`blender_rt_worker`** | 常驻 `blender -b`；`start` → `exec`（复用持久内核 `K`）→ `status` → `stop`；串行执行 |
| 单次 > 5 分钟 | 热会话，或把结果写文件 | 客户端 `fetch` 的响应头超时是 **300 s**（实测 `UND_ERR_HEADERS_TIMEOUT`）；`/headless` 与 `/worker` 已改**流式**（响应头立刻返回 + 15 s 心跳）→ 现在可以跑过 5 分钟 |

**超时/断连的语义**：客户端断开**不等于任务失败** —— 服务端子进程会继续跑完，产物仍在 `outdir`，全量日志路径在 `logs` 字段里。遇到 `fetch failed` 先翻目录。

## 6. 端口与多实例

| 场景 | 做法 |
|---|---|
| 单 Blender 单会话 | 默认即可（9876 + 9877） |
| **两台 Blender 并行** | 第二台：addon 面板改端口（比如 9896）；插件侧 `httpPort=9898, addonPort=9896`（配置文件或环境变量） |
| 临时排错 | `node runtime/server.mjs --port 9888`（命令行 `--port` 优先于配置） |

### 两种 addon 协议（`addonProtocol`）

Blender 侧存在两种**互不兼容**的 addon 实现，本插件都支持：

| | ahujasid 血统（`MCP for Blender` v1.6） | harveyxiacn 增强版（`blender_mcp_addon`） |
|---|---|---|
| 请求 | `{"type":"get_scene_info","params":{}}`（**无分帧**） | `{"id":..,"type":"command","category":"scene","action":"get_info","params":{}}` + `\n` |
| 应答 | `{"status":"success","result":{…}}` | `{"id":..,"success":true,"data":{…}}` + `\n` |
| 命令词汇 | 扁平名（`ping` / `execute_code` / …） | `category.action`（`system.get_info` / `utility.execute_python` / …） |

`auto`（默认）在通道首次使用时**探测一次并缓存**：先发不带换行的扁平 ping（只有扁平 addon 会回），
没回再发带换行的 category/action ping，并按回包封套形状纠错（避免 addon 偶尔忙一下就把协议判错）。
配置成具体值则不探测。探测结果会出现在 `/doctor`（`protocol` / `protocol_label` / `protocol_from`）
与 `/who` 的 `config.addonProtocol` 里。

**症状对照**：装了另一种 addon 时，`/doctor` 原先只会报 `addon-thread-stuck`（端口通、ping 不回），
与"addon 客户端线程卡住"无法区分；现在会直接给出 `detected_protocol` 和"把 `addonProtocol` 改成 X"的修法。

`category-action` 侧没有 PolyHaven / Hyper3D / Sketchfab / Poly Pizza / Hunyuan3D 这几条资产集成通道，
对应命令会**明确报错**（不假装成功）；`get_viewport_screenshot` 与 `get_world_state_snapshot`
由插件侧生成 python 借 `utility.execute_python` 执行，不依赖对面的同名 handler。

自检（不需要 Blender、不需要 DSH）：`node tests/protocol_selftest.mjs`。

## 7. 租约（并发写保护）

| 项 | 说明 |
|---|---|
| 谁受保护 | 写路由：`/act /cmd /loop /perf(写 op) /opt(join) /headless`；**只读 op 豁免**（`perf status/help`、`loop status/board/help`、`opt analyze`） |
| 无租约时 | 完全无阻力（单 agent 日常） |
| 别人持有时 | 返回 `409 {ok:false, error:"leased", holder, expiresInMs, hint}` |
| 抢占 | `blender_viewport {op:"lease", force:true}` 或在 HTTP body 里 `force:true` |
| 续期 | 插件每 15 s 心跳；**只在本来就持有时**才续（空闲不抢） |
| 释放 | `blender_viewport {op:"release"}` |
| 查看 | `blender_viewport {op:"who"}` 或 `curl /who` |

## 8. 两种部署形态

### A. DSH 在 WSL，Blender 在 Windows（推荐）

- 需要：WSL 互操作（`cmd.exe` / `blender.exe` 能直接执行）；
- 无头工具通过 binfmt 直接起 `blender.exe`（stdout/stderr 直连回传）；
- 路径映射自动：`/mnt/d/x` ↔ `D:\x`。

### B. DSH 与 Blender 同在 Windows

- `config.mjs` 检测到 `process.platform === 'win32'` 时路径映射自动退化为"原样返回"；
- `blenderExe` 给 Windows 路径即可；
- 无头工具直接 `spawn` 该 exe。
