## Findings and honest limitations (not claimed as passes)

1. Coverage (plan 6.11 / gate C5) is NOT met. Measured addon package coverage is
   28% line/branch overall (4334 statements / 1342 branches). UI modules are
   excluded by the plan but network-bound command/integration modules, plugin
   registration and some helpers are still far below the >=80/70 addon target.
   This is reported as C5 open for the R2 reviewer / T12 ratchet; it is not part
   of T10's completion definition, but it must not be read as "coverage passed".
   pytest-cov 7.1.0 had to be installed because the venv lacked the dev
   dependency declared in requirements-dev.txt.
2. blender --command extension validate is inapplicable to this artifact: the
   add-on is a legacy bl_info package, not a Blender extension, so the validator
   fails on the missing blender_manifest.toml. The real validation is the
   install/enable E2E; build.log records both the failure text and that reason.
3. Blender 4.2's bpy.ops.preferences.addon_remove is a UI operator whose execute()
   ends with context.area.tag_redraw(). In --background mode it raises
   AttributeError on a None area; the headless runner documents that, then
   removes the package directory directly. The GUI probe invokes the real
   operator under bpy.context.temp_override(window/area/screen) and it succeeds
   (remove_error None), so the release GUI path is covered.
4. Plan 8.2 B4 says the launcher validates "addon v1.10 / protocol 11"; the
   product is v1.11 / protocol 11. runtime/launch.mjs actually accepts
   protocol == 11 and version >= (1,10). test_addon_launcher_contract.py asserts
   that real contract against the real addon version (1,11). This is a stale plan
   wording, not a code defect.
5. tests/BEHAVIOR_MATRIX.md was not edited (owned by T14 / out of T10 scope). Its
   CMD rows still point at the static contract test; T10's execution matrix and
   E2E logs are the stronger evidence the Lead/T14 may want to link.
6. tests/README.md was not edited (owned by T11/T13); layer invocation is
   documented here and in commands.txt instead.
7. GUI E2E needs an interactive desktop and briefly opens a Blender window; it
   skips on CI non-Windows / T10_SKIP_GUI=1 and is not part of the default suite.
   The final evidence run was a single clean pass with no retry.
8. No product bug was found that would require changing addon/runtime/src.
9. Known non-issues verified: the pause gate runs before the agent recorder (so
   a rejected request is not attributed to the agent); selection payload caps
   (200 names / 50 objects / 8 activity names) and the AI_PAUSED message are
   frozen by tests.
10. The 39-command matrix executes every command through the real dispatch
    layer with recorder handlers (params forwarding, envelope, pause, gate);
    commands that need network providers are not executed against live remote
    APIs (offline environment), which is why handler bodies for those modules
    remain low-coverage.
