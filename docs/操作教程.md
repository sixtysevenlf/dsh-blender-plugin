
# 操作教程 —— 从零到顺手

> 面向第一次拿到这个包的人：**装上 → 连通 → 会用 → 会排错**，全程约 40 分钟（熟练后 5 分钟）。
> 当前版本：插件 **v3.1.0**（6 个模型工具）· Blender addon **v2.0.0 / protocol 12** · Gateway `127.0.0.1:39877`（addon 主动连接，无入站端口）。
> 前置条件（Blender + `DSH Blender Bridge` addon + Node ≥ 24.9 + DSH）见 [README `2](../README.md#2-前置条件4-条缺一不可)；GUI 通道要求 Blender 开着且 addon 已 Connect，后台作业不要求 GUI。
> 配置项（工作目录 / blender.exe / 端口 / 会话与作业超时）见 [配置参考.md](配置参考.md)。

## 0. 心智模型：先理解这 4 件事

1. **两条线并行**
   - **GUI 通道**：addon 主动连接 Gateway（WebSocket，默认 `127.0.0.1:39877/addon`）；毫秒级、实时，但**要求 Blender GUI 开着**，且所有命令串行占用它。`blender_session`（会话/权限）、`blender_op`（算子 / 内环 / 精简 / 配方）、`blender_py`、`blender_see`、`blender_inspect` 都走它；执行型 op 需要 ready 的 GUI 会话。
   - **后台作业**：`blender_run` 提交的一次性 `blender -b` 进程（`kind="headless"`）或声明式最终渲染（`kind="render"`）独立进程；**不占 GUI 通道**，可与 GUI 线同时跑。submit 立即返回 jobId，之后 status / wait / collect / cancel 收结果。
   - 3.1 **没有**持久 worker 会话、没有 `session` / `session="auto"` 参数、也不会自动降级到无头 —— 需要无头就在 `blender_run` 里显式提交作业。
2. **四种"看"**（都由 `blender_see` 出图，语义不同）
   - `viewpoint="viewport"` 视口帧 = **用户正在看的角度**（含视口着色与覆盖物）；
   - `viewpoint="custom"` = **你指定的机位**（`from` + `look_at`，不建相机、不动用户视口）；
   - `viewpoint="camera"` = **当前帧的求值相机**（按渲染比例取景，不改 `scene.camera` / 帧 / 选择 / 视口）；
   - `full=true` = **整个 Blender 窗口**（看 UI / 面板 / 其他编辑器）；
   - `mode="sequence"` = 固定机位连续采样（最多 32 帧、逐帧 hash；**不执行代码**，只观察画面）。
3. **内环 vs 外环**：模型回合（几秒）贵，Blender 事件循环（160 tick/s）便宜 →
   **搜索放 Blender 侧（`blender_op(action="loop", …)`），决策与验收放模型侧**。详见 [假设驱动建模 cookbook](假设驱动建模-cookbook.md)。
4. **会话归属与写权限**：GUI 会话有归属与写 scope。`blender_session` 负责 `attach/claim`（附着 / 认领）、`grant/revoke`（把 `exclusive` / `collection:名` / `prefix:名` / `object:名` 写权限授予子 agent）、`mark_read`（清掉 human_modified 冲突）；`pause/resume` **只有人类能操作**（agent 调用返回 `human_action_required`）。Gateway 进程与 Blender 启动由 DSH 宿主管理，模型面**没有** lease / launch / restart 这类通道运维动作。

> 方法论：证据不足时如何明确报 unresolved、用探针翻转假设、把"为什么这么建模"写清楚 —— 见 [假设驱动建模 cookbook](假设驱动建模-cookbook.md)。

### 什么时候用哪个工具

| 你要做的事 | 用哪个 | 为什么 |
|---|---|---|
| 看一眼现在长什么样 | `blender_see`（`viewpoint="viewport"`） | 50–160 ms，最便宜；GUI 会话在线即可 |
| 换个角度看（不想动用户视口） | `blender_see`（`viewpoint="custom", from, look_at`） | 零场景改动，可重复（md5 稳定） |
| 用场景相机的构图看 | `blender_see`（`viewpoint="camera"`） | 当前帧求值相机 + 渲染比例，不改场景 |
| 改一步就想验证 | `blender_py(code=…, see=True)` | 一个原子步 ≈105 ms；GUI Python 固定 exclusive |
| 判断"动没动 / 对不对" | `blender_see`（`mode="sequence", seconds, fps`） | 时间窗连续采样 + 逐帧 hash，一次最多 32 帧 |
| 搜索 / 拟合参数（几千次迭代） | `blender_op(action="loop")` | 内环跑在 Blender 侧，不花模型回合 |
| 多目标 + 约束的测量 | `blender_op(action="loop")` + `penalize` | 罚项把违规量并入单一 score |
| 收敛后复核 / 复用 | `blender_py` 复算 + `blender_op(action="loop", op="export")` | 防"只优化了你写的目标函数" |
| plan 判定 / 验收 / 导出 | `blender_op(action="plan", op=…)` | 34 family / 228 op 的唯一入口；执行型要 GUI 会话 |
| Cycles 成品渲染 / 相机动画 | `blender_run(action="submit", kind="render", …)` | 声明式、异步、有界队列 |
| 大批量几何 / 校验 / 长脚本 | `blender_run(action="submit", kind="headless", …)` | fresh `blender -b` 进程：不占 GUI、超时可杀 |
| 长活 / 批处理（>100 s） | `blender_run` submit → wait / collect | 返回 jobId，超时不丢结果 |
| 多视角 QC / 成品出图 | `blender_op(op="qc_render_views")` 或 `blender_run(kind="render")` | 自动取景 + 三点光 + 逐张 md5；分钟级走作业 |
| 参考图量尺寸 / 标定 | `blender_op(op="img_digest / img_probe / img_measure / img_calib")` | 把"看不清"变成数字表，不靠眼睛估 |
| 装配合并 / 穿模 / 修复 / 交付 | `blender_op(op="asm_*")` | manifest 驱动 + verdict 三态 + gate 后再导出 |
| 白模 / Seedance 参考包 | `blender_op(op="blockout_*")` | 声明式 parts + 4 视图 PNG / 拼图 + MP4 转台 |
| 同机位 QC 一页 verdict | `blender_op(op="visualreport_report")` | IoU / 缺多面积 / 缺陷 crop + mm 定位 |
| 按参考图反推尺寸 | `blender_op(op="shapesolve_solve")` | 多视轮廓拟合，不渲染、不依赖 timers |
| 缺陷评估（插件抓不抓得住） | `blender_op(op="eval_run")` | 合成缺陷集 capture_rate + 基线回放 |
| 开工体检 / 回退点 / 强制交付 | `blender_op(op="gate_*")` + `blender_session(action="txn")` | 不过门不导出；drill 进交付流程 |
| 渲染慢要调参 | `blender_run(action="tune", op="status"→"analyze"→"apply")` | 先量后调；预设可 revert |
| 场景对象太多导致每轮同步慢 | `blender_op(action="opt", op="analyze"→"join")` | ≈1.4 ms/对象；几何零损失，务必先存回退点 |
| addon 只读命令 / 命令面 | `blender_inspect(command=…)` | help 只列可执行只读命令；写命令会指路 |
| 出错不知卡在哪 | `blender_session(action="doctor")` | 真跑一次 bpy 往返 + 三级判定 + 修法 |
| virtual-gui 起不来（缺 Xvfb/VirtualGL/helper） | `/blender doctor --fix` | 只安装缺失前提；不装依赖不启动，也不回落 headless |
| 多个会话抢同一个 Blender | `blender_session(action="grants"/"status")` | 看持有者与写权限；用完 release / revoke |

## 1. 安装与连通

### 1.1 Blender 侧：装 addon 并 Connect

1. 在 Blender 里打开 `Edit ▸ Preferences ▸ Extensions ▸ Install from Disk...`，选 `dsh_blender_bridge.zip`（Blender 扩展包，模块名 `bl_ext.user_default.dsh_blender_bridge`）。
2. 启用它（勾选 checkbox）。
3. 打开一个 **3D 视图**，按 `N` 打开右侧栏 → 找到「DSH Blender Bridge」面板 → 点 **Connect**（addon 主动连接 Gateway；默认 39877）。
4. 面板里可顺手打开需要的集成（PolyHaven / Hyper3D / Sketchfab / Poly Pizza / Hunyuan3D）；**这些开关是 scene 属性** —— 改完记得存进你的 startup / 工程文件（重启 Blender 会丢未保存的）。

> ⚠️ **addon 迁移**：只支持本仓 `DSH Blender Bridge` **v2.0.0 / protocol 12**。旧的 `MCP for Blender` / `blender_mcp` **已不再支持**，请先停用旧 addon 再安装/启用本仓 addon（3.1 addon 主动外连 Gateway，不占 9876 入站端口；但旧 MCP 桥仍可能监听 9876，不能同时开）。迁移要点见 [../MIGRATIONS.md](../MIGRATIONS.md)。

> 判断 addon 是否已连接：在终端跑 `curl -sS http://127.0.0.1:39877/doctor`；或直接 `node lib/runtime/_probe_tools.js` 看 Gateway 实例与命令面。

### 1.2 从 npm 安装插件（普通用户）

普通用户不需要 clone 或构建；npm 包自带构建后的 `lib/`。

```bash
dsh plugin --profile <profile> add dsh-blender-plugin@3.1.0
dsh --profile <profile> --dump-config | grep -A3 dsh-blender-plugin
# 然后重启 DSH
```

> DSH Desktop 用户可以在 Plugins 页面安装 bundle `dsh-blender-plugin@3.1.0`。
> 不需要同时使用"运行时注入"与"bundle 装配"：两个 fiber 会重复注册同名工具。

### 1.3 从源码构建（开发者）

只有修改插件源码时才需要：

```bash
git clone https://github.com/sixtysevenlf/dsh-blender-plugin.git
cd dsh-blender-plugin
npm ci --legacy-peer-deps && npm run build   # 构建 lib/ 与 lib/runtime/
```

然后按开发方式把 checkout 链到 profile：`node_modules/dsh-blender-plugin` 建 junction，
profile 的 `dependencies` 加 `"dsh-blender-plugin": "link:<本目录绝对路径>"`，
`dsh.profile.bundles` 加 `"dsh-blender-plugin"`，再 `--dump-config` 预演并重启 DSH。

### 1.4 后端自检（三条命令）

```bash
curl -sS http://127.0.0.1:39877/health   # {"ok":true,...}    后端进程活着
curl -sS http://127.0.0.1:39877/doctor   # ⭐ kind=ok 才算"Blender 也连上了"
curl -sS http://127.0.0.1:39877/who      # 会话 + 写权限租约 + 通道指标 + 当前生效配置
```

**唯一验收判据**：`/doctor` 返回 `kind=ok`（或 `blender_session(action="doctor")` 的 `kind=ok`）。其它自检失败只说明那一项功能有问题，**不能替代**这条验收。

DSH TUI 里直接跑 `/blender doctor`；加 `--fix` 会读取 `/doctor` 的 `virtualGui.installPlans`，显示并引导安装 virtual-gui 前提（发行版矩阵与一键范围见 [配置参考 §5.7.1](配置参考.md)）。

`/doctor` 返回里的关键字段：

| 字段 | 含义 |
|---|---|
| `kind` | `ok` / `blender-unreachable` / `main-thread-busy` / `addon-thread-stuck` / `addon-unresponsive` / `addon-error` |
| `summary` `fix` | 一句结论 + 一句修法（直接照着做） |
| `ping_ms` `roundTripMs` | `ping`（不碰 bpy）与 `status`（真跑 bpy）的耗时 |
| `config` | **当前生效配置**：工作目录、blender.exe、端口、配置文件来源 —— 排错先看它 |

### 1.5 插件工具自检

```text
blender_session(action="doctor")          # 同 /doctor，但在工具回执里更可读；kind=ok 是唯一验收判据
blender_op(op="catalog")                  # 应为 34 个 family / 228 个 op（6 个模型工具）
blender_inspect()                         # addon 只读命令表（常驻 + 集成门控）+ 5 个集成状态
blender_see(max_size=560)                 # GUI 在线时：应返回一张图，50–100 ms
blender_run(action="submit", kind="headless", script="print('HEADLESS {ok:true}')")
                                          # 纯后台时：返回 jobId → action=wait/collect 收结果
```

### 1.6 addon 兼容性探针

```bash
node lib/runtime/_probe_tools.js
# 只连 Gateway HTTP（不直连 addon 端口）：探 /health /status /doctor /commands /act
# 输出 ready_instances、命令面统计与每条探针的 ok / 耗时；哪条失败就说明对应层出问题
```

### 1.7 随包 skill 自检

**不用单独安装**：`blender-modeling` skill 就在插件包的 `skills/blender-modeling/`，DSH 启动时自动注册为 bundled skill
（rank 600；你自己装在 `~/.dsh/skills/blender-modeling` 的 user 级 400 副本仍然优先）。


## 2. 六个工具逐个上手

> 约定：所有工具都要求**后端在跑**（插件自动拉起）。
> GUI 通道工具（`blender_session` 的多数动作、`blender_op` 执行型 op、`blender_py`、`blender_see`、`blender_inspect` 命令）需要 **ready 的 GUI 会话**：用户在 Blender 里 Connect，或 `blender_session(action="attach")` 附着他已打开的会话。
> 不需要 GUI 会话的：`blender_op` 的 `catalog` / 只读 op / `args.dry_run=true`（本地或 Gateway 只读路径，也不会启动 Blender），以及 `blender_run` 的作业提交（fresh `blender -b` / 声明式渲染）。
> 参数名用工具 schema 里的原名（WSL / Windows 通用）；3.0 旧工具名见下表迁移。

### 从 3.0 工具名迁移

| 3.0 | 3.1 |
|---|---|
| `blender_rt_see` | `blender_see` |
| `blender_rt_watch` | `blender_see(mode="sequence")`（`code=` 移到 `blender_py`） |
| `blender_rt_do` | `blender_py`（`session/preload/auto/view_size` 移除） |
| `blender_rt_plan` | `blender_op(action="plan", …)`（`op/args/path/attach_images` 不变） |
| `blender_rt_loop` | `blender_op(action="loop", …)` |
| `blender_rt_opt` | `blender_op(action="opt", …)` |
| `blender_rt_preset` | `blender_op(action="preset", …)` |
| `blender_rt_perf` | `blender_run(action="tune", …)` |
| `blender_rt_headless` | `blender_run(action="submit", kind="headless", …)`（异步；wait / collect 收） |
| `blender_rt_job` | `blender_run(action="submit" \| "status" \| "wait" \| "collect" \| "cancel" \| "list")` |
| `blender_rt_cmd(name=X, params=Y)` | `blender_inspect(command=X, args=Y)` |
| `blender_rt_commands` | `blender_inspect()`（默认 help） |

### ① `blender_session` —— 会话 / 归属 / 权限 / 事务

| 参数 | 说明 |
|---|---|
| `action`（必填） | list / status / doctor / attach / claim / detach / release / grant / revoke / grants / pause / resume / mark_read / presence / heartbeat / start / stop / txn / help |
| `session_id` | 会话 id（大多数会话级动作必填） |
| `instance_id` | attach / claim 时的 addon 实例 id（多实例必填；`status` 里能看到 `instanceId`） |
| `kind` | start 的会话类型，只接受 `virtual-gui` |
| `scopes` | grant / mark_read 的 scope 列表：`exclusive`、`collection:COL`、`prefix:OBJ_`、`object:Cube`；多个用逗号分隔 |
| `target_agent_id` / `target_dsh_session_id` / `target_host_id` | grant 的目标（同 DSH session / 跨 DSH session / 跨 host） |
| `grant_id` | revoke 的授权 id |
| `ttl_ms` | grant 有效期毫秒（默认由 Gateway 决定） |
| `op` `label` `note` `objects` `keep` `into` `backup` | txn 子动作参数（见下表） |
| `force` | 保留参数：由 Gateway 决定是否接受强抢语义 |

| action | 作用 | 要点 |
|---|---|---|
| list / status / doctor | 看会话 / 实例 / 通道 | `doctor` 真跑一次 bpy 往返 + 三级判定，`kind=ok` 是唯一验收判据 |
| attach / claim / detach / release | 附着 / 认领 / 脱离 GUI 会话 | 多实例必须给 `instance_id`；`claim` 认领会话所有权 |
| grant / revoke / grants | 写 scope 授权 | 把 `exclusive` / `collection:名` / `prefix:名` / `object:名` 授予子 agent；`revoke` 按 `grant_id` |
| pause / resume | 暂停 / 恢复 AI 操作 | **human-only**：agent 调用返回 `human_action_required`，让用户在 N 面板点 |
| mark_read | 清掉 `human_modified` 冲突 | 人改过场景、你确认已读后清标记 |
| presence / heartbeat | 在场 / 心跳 | 多 agent 面板显示；长任务期间可主动心跳 |
| start / stop | virtual-gui 会话 | `start` 第一次返回 `consent_required`，用户授权后由宿主带一次性 token 重试；**user-gui 永远由用户自己打开 Blender 并 Connect** |
| txn | 事务快照 / 回滚 | 见下表 |
| help | 帮助 | |

`action="txn"` 子动作：

| op | 作用 |
|---|---|
| `snapshot` | 文件级快照（`label` / `note`），整场景可回退 |
| `restore` | 载入快照（`into="auto"` 默认落回快照出处文件；`"snapshot"` 非破坏只看一眼；`"original"` 必须能回写）；`backup` 默认先留 pre_restore 备份 |
| `list` / `prune` | 快照 + mark 清单 / 只保留最近 `keep` 个快照 |
| `mark` / `revert` / `marks` / `drop` | 对象级 mark / 就地回滚（只记 transform / 材质槽 / 可见性 / 修改器开关，毫秒级）；`marks` 列清单，`drop` 删除 |
| `help` | 完整契约 |

边界：对象级 **不含拓扑 / UV / 顶点级改动**（Boolean、合并、删面之后回不去）→ 用文件级 `snapshot/restore`。
`restore` 默认先备份：`backup=True` 先留 `_pre_restore_*` 快照，会话脏且要覆盖原文件时另留磁盘副本 `_pre_restore_file_*`。

```text
blender_session(action="status")
blender_session(action="attach", instance_id="…")          # 多实例时明确附着哪一个
blender_session(action="grant", target_agent_id="agent-2", scopes="object:Cube,prefix:Wheel_", ttl_ms=600000)
blender_session(action="grants")
blender_session(action="revoke", grant_id="grant-…")
blender_session(action="txn", op="snapshot", label="before_join", note="Boolean 前")
blender_session(action="txn", op="mark", label="iter7", objects="Cube,Wheel_L")
… 改动 …
blender_session(action="txn", op="revert", label="iter7")  # 拓扑变过的对象会跳过并报告
```

> `txn` 的 `restore / mark / revert` 属写操作：需要 exclusive grant，且人类未暂停。
> Gateway 进程与 launch 运维不在模型面 —— 启动/重启由 DSH 宿主管理；模型侧诊断只用 `action="status"/"doctor"`。

### ② `blender_op` —— 算子 / 内环 / 精简 / 配方

| 参数 | 说明 |
|---|---|
| `action` | plan（默认）/ loop / opt / preset / help |
| `op` | plan：catalog 算子名；loop：start / status / stop / board / export / help / bench；opt：analyze / join / help；preset：list / get / apply / save / delete / export / import / help |
| `args` | plan / opt / preset 的参数对象（JSON），例如 `{"family":"audit"}` |
| `path` | plan report / loop export 的输出路径（可选） |
| `attach_images` | plan：是否把结果里的图附图（默认按 op 决定） |
| `spec` `history` `board` `limit` `groups` `top` `include_variants` `note` `iterations` `session` `target` | loop / preset 子面参数（见下） |
| `name` `kind` `tags` `names` `targets` `data` `overwrite` | preset 子面参数（见下） |

#### `action="plan"` —— catalog 算子（34 family / 228 op）

##### 多视角渲染 harness —— 一条命令出 N 张 + jsonl + 预算判定

```text
blender_op(op="qc_render_views", args={
  views: ["iso","front","right"],        # 具名视角 / "az=35,el=20" / {name, from, look_at, lens, ortho}
  res: [512,512], samples: 64,           # 采样同时写 EEVEE taa_render_samples 与 Cycles samples
  budget_s: 120,                         # 别名 thr；累计渲染超了立即停，已出的图保留
  outdir: "D:/DSH/blender/out/qc_render_p21",
  ref_path: "D:/work/ref_front.png", ref_box: [9,38,444,545]   # 可选：逐张走 qc_compare（默认固定对齐）
})
```

- **自动取景**：合并所有可见 mesh 的 AABB（`targets:[名字]` 可限定）→ 逐角解算相机距离 + `margin`（默认 1.12）；
  给了 `from` / `look_at` 就按显式机位，不再自动取景。
- **固定三点光**：SUN key 3.2 / fill 1.0 / rim 2.4，角度固定且相对相机方位角（+35°/45°、-50°/8°、+165°/30°）；
  **只在本进程内临时建**，出图后删除并把 scene 渲染设置全部还原（`lights_mode:"only"` 可临时屏蔽场景里的灯，也会还原）。
- **产出**：`<outdir>/<tag>_<view>.png` + `<outdir>/render_views.jsonl`，每行 = 一张图
  （`{view, ms, bytes, hash, path, res, engine, samples, camera, frame{bbox, margin_px, coverage, pred_bbox_px, proj_err_px}}`）。
- **预算**：`within_budget=false` + `stopped_early` + `skipped_views`；已完成的行 / 图**不删**。
- **长活**：本 op 在 GUI 会话里同步跑；预计 >5 min 或批量请提交后台作业 ——
  `blender_run(action="submit", kind="headless", preload="qc,qc_render", script="print('HEADLESS ' + K.dsh_qc_render_api['render_views']({...}))")`，
  或纯渲染走 `blender_run(action="submit", kind="render", …)`；之后 `wait` / `collect` 取结果。
- **不改场景**：GUI 进程里默认拒绝打开别的 `.blend`（要开就传 `allow_open_file=true`）；临时相机 / 灯用完即删。
- 自检：`blender_op(op="qc_render_help")` 出参数速查；`K.dsh_qc_render_api["selftest"]()` 跑取景 / 投影自检。

实测（350 可见 mesh / 512×512 / 64 采样 / EEVEE+RT）：3 视角 2124 / 798 / 565 ms、共 3487 ms、jsonl 3 行、
512 画幅四边余量 36 px（预测 bbox 与实出 alpha bbox 差 ≤2 px）；预算 1.0 s 的对照跑只出 1 张即停且图保留。

#### `action="loop"` —— 内环搜索（最核心的一个）

```text
blender_op(action="loop", op="start", spec={
  "setup":  "import random\nK.ob = bpy.data.objects['Cube']",
  "step":   "px = ns['i'] % 7; ns['params'] = {'sx': 1 + px * 0.1}",
  "measure":"ns['score'] = abs(bpy.data.objects['Cube'].dimensions.x - 2.0)",
  "iterations": 3000, "budget_ms": 20000, "interval": 0, "measure_every": 5,
  "minimize": True, "top_k": 20, "group_key": None
})
blender_op(action="loop", op="status", history=12)
blender_op(action="loop", op="board", limit=10)
blender_op(action="loop", op="export", path="/tmp/best_fit.py", top=3)
blender_op(action="loop", op="stop")            # 急停
blender_op(action="loop", op="bench", iterations=5000)
```

- `setup/step/measure` 源码共享命名空间 `ns`；`measure` 必须写 `ns["score"]`，可写 `ns["params"] / ns["metrics"] / ns["violations"]`；
- 预置：`bpy / K / math / random / numpy(np) / i / frac / penalize / anneal / record`；
- **必须给 `iterations` 或 `budget_ms`**（安全阀）；`interval=0` 最快；`redraw_every=0` 不重绘最快；
- 多目标：`ns['score'] = penalize(errors_dict, violations, weights, lam)`；步长退火：`anneal(v0, v1, ns['frac'])`；
- `top_k + group_key` = 候选表（跨对象批量时按对象分组各留最优）；
- 内环默认跑在 **GUI 会话**里（`target="gui"`，默认）；工具还保留一个内部无头实现（`target="session"`），**不是用户面能力**，需要无头请用 `blender_run` 提交作业；
- `op=help` 打印完整契约。

#### `action="opt"` —— 对象精简

```text
blender_op(action="opt", op="analyze")
blender_op(action="opt", op="join", args={dry_run:true})                      # 先空跑看报告
blender_op(action="opt", op="join", args={dry_run:false, save_before:"/tmp/pre_join.blend"})
```

合并规则（安全）：同集合 / 同材质 / 同父级 / 无修改器 / 无动画 / 无形态键 / 无自定义属性 / 无实例 / 非库链接 → **几何零损失**（面数顶点数不变）。务必先给 `save_before`。

### ③ `blender_py` —— GUI Python（改一步看一眼）

| 参数 | 说明 |
|---|---|
| `code` / `file` | 要执行的 Python 源码 / 磁盘上的 `.py`（二选一；`file` 自动注入 `__file__` + sys.path） |
| `see` | 跑完是否抓当前视口一帧（默认 true） |
| `max_size` | `see` 的最长边像素，默认 560 |
| `force` | `see`：同画面默认不重复附图，`true` 强制重发 |
| `wait_ms` | 等待其它 py 释放的毫秒数（0–5000，默认 0；占用中返回 `py_busy`） |

- 只在 **ready 的 GUI 会话**里执行，固定 `exclusive`（不排队列）；**没有会话直接拒绝**，不会启动 headless、不会自动降级。
- 代码在 **Blender 主线程**执行，预置 `bpy / math / mathutils / Vector`；每次调用是全新命名空间，跨调用状态挂**持久内核 `K`**。
- `see=true`（默认）会顺带回一帧，GUI 整步 ≈105 ms；超过 ~1 s 的重活请改用 `blender_run(kind="headless")`。

```text

blender_py(file="//tools/probe.py", see=False)     # 直接跑工作区脚本（K.run 语义，会回收 stdout）
```

### ④ `blender_see` —— 看 GUI（唯一截图入口）

| 参数 | 说明 |
|---|---|
| `viewpoint` | viewport（默认，当前 GUI 视口）/ camera（当前帧相机）/ custom（from+look_at 自定义机位） |
| `mode` | frame（默认，单帧）/ sequence（固定机位序列帧，只 viewport / custom） |
| `camera` | viewpoint=camera 时可选相机名；省略或 `true` = `scene.camera`；其他 viewpoint 不接受 |
| `aspect` | 1:1 / 4:3 / 16:9（默认 16:9）；viewport / custom / sequence 用；camera 不接受 |
| `max_size` | 固定档位：1:1 544/768/1024/1280；4:3 640/960/1280；16:9 1024/1152/1280；camera 544/768/1024/1280；默认 1024 |
| `from` / `look_at` | 【custom】相机位置 / 注视点，`"x,y,z"` 或数组 |
| `lens` / `ortho` / `ortho_scale` | 【custom】焦距 mm（默认 50）/ 正交开关 / 正交尺度（贴长边，默认 10） |
| `full` + `area` | frame + viewport：整窗口 / 区域截图（固定 1024 长边，看 UI 时用） |
| `shading` / `overlays` | 【custom / sequence】临时切换着色（WIREFRAME/SOLID/MATERIAL/RENDERED）/ 覆盖物，出图后还原 |
| `diagnostics` | 【frame + custom】强制跑覆盖率 / 空帧诊断（默认按需） |
| `seconds` / `fps` | 【sequence】采样时长 0.2–20 秒（默认 2）/ 采样频率 0.5–8（默认 4）；帧数 `round(seconds*fps) ≤32` |
| `force` | 同画面默认不重复附图；`true` 强制重发 |

**固定档位**（只给 `aspect` 时取该比例最小档；非法值直接报错，不夹取）：

| aspect | 可选 max_size |
|---|---|
| 1:1 | 544 / 768 / 1024 / 1280 |
| 4:3 | 640 / 960 / 1280 |
| 16:9（默认） | 1024 / 1152 / 1280 |
| camera | 544 / 768 / 1024 / 1280 |

```text
blender_see(max_size=560)                                       # 当前视口帧
blender_see(viewpoint="custom", from="9,-9,6", look_at="0,0,1", lens=35)
blender_see(viewpoint="custom", from="0,0,12", look_at="0,0,1", ortho=True, ortho_scale=12,
            shading="MATERIAL", aspect="1:1", max_size=1024)

```

- **只服务 GUI 会话**：没有 ready 会话直接拒绝；**不会**回落无头、也不会启动 Blender。
- `viewpoint="camera"` 只取当前帧求值，**不改** `scene.camera` / 帧 / 选择 / 用户视口；PANO 不支持，DOF / 运动模糊只给 `preview_only`。
- `mode="sequence"` 不执行 code、不改场景；要"先跑一段代码再逐帧看"用 `blender_py` 执行代码 + 再 `blender_see`；逐帧 hash 全相同 = 画面没变（动画没跑起来 / 参数没生效）。`fps` 别开太高（每帧占主线程 ~55–100 ms，会卡人）。
- `full=true` 整窗截图必须 GUI；`view_size` 已移除 —— 画幅用 `aspect` + `max_size` 固定档位表达。
- 相机动画 / 批量渲染走 `blender_run(action="submit", kind="render", …)`，不要用截图代替渲染。

### ⑤ `blender_run` —— 作业 / 渲染 / 调参（唯一作业入口）

| action | 作用 | 要点 |
|---|---|---|
| `submit` | 提交作业：`kind="render"`（声明式渲染）或 `kind="headless"`（跑脚本） | **立即返回 jobId**；没有同步模式 |
| `status` | 单次查状态 | `state` / slot / timing / pid / result / artifacts |
| `wait` | 阻塞到终态或超时 | 默认 **120 s**、上限 **600 s**；**超时不取消作业** |
| `collect` | 取日志与产物 | `stdout` / `stderr` 尾部（`tail` 默认 4000）+ result（exit / signal / parsed）+ artifacts |
| `cancel` | 取消作业 | 幂等：已到终态也回 ok；清进程树 |
| `list` | 列作业 | 可按 `state`（queued/assigned/running/completed/failed/canceled）/ `kind` / `owner` 过滤 |
| `perf` | 队列指标 | pending / byState / slots（gpu·cpu）/ oldestQueuedAt |
| `tune` | Cycles 渲染分析 | `op="status"` / `"analyze"` / `"apply"` / `"revert"` / `"help"` |
| `help` | 契约 | |

| 参数 | 说明 |
|---|---|
| `action` | submit / status / wait / collect / cancel / list / perf / tune / help（默认：带 `kind` 则 submit，否则 list） |
| `kind` | submit：`render`（声明式渲染）或 `headless`（跑脚本） |
| `id` | status / wait / collect / cancel 的 jobId |
| `priority` | submit：队列优先级（-100..100，默认 0；越大越优先） |
| `timeout_ms` | wait：等待上限（默认 120000，最大 600000，**超时不取消**）；headless：进程上限（默认 180000，最大 1800000） |
| `tail` | collect：日志尾部字符数，默认 4000 |
| `state` / `owner` | list：按状态 / DSH session id 过滤 |

`kind="render"`（声明式最终渲染，**不接受 script**）：

| 参数 | 说明 |
|---|---|
| `file` | 要渲染的 `.blend` |
| `output` | 输出文件模板（如 `//render/frame_####`） |
| `outdir` | 输出目录 |
| `frames` | 帧区间 `[start,end]` / `"1-10"` / 单帧 `5`；**给了区间自动加 `-a`（相机动画）** |
| `resolution` | `[width,height]` |
| `samples` | 采样数（Cycles samples / EEVEE `taa_render_samples`） |
| `engine` | `CYCLES` / `BLENDER_EEVEE_NEXT` / `BLENDER_WORKBENCH` |
| `format` | 图片格式（PNG/JPEG/OPEN_EXR…） |
| `camera` | `true` 用场景相机，或相机对象名 |

`kind="headless"`（fresh `blender -b` 进程跑脚本）：

| 参数 | 说明 |
|---|---|
| `script` / `script_file` | Python 源码 / 直接跑一个 .py 文件（后者自动注入 `__file__` + sys.path，多文件工程更省事） |
| `file` | 打开的 .blend（WSL 或 Windows 路径都行，自动映射） |
| `outdir` / `out_json` | 产物目录 / 结构化结果落盘路径（都接受 WSL 路径） |
| `timeout_ms` | 进程上限：默认 180000，上限 1800000（到点杀进程树） |
| `preload` | 预载 runtime 模块（逗号分隔）→ `K.dsh_*_api`，如 `"audit,qc,qc_render"`、`"assembly,audit,contract,clearance,gate,mesh_fix,geo,txn"`、`"imgtools"` |
| `engine` | `eevee`（默认，带光追前导）/ `cycles` / `keep` / `none`（纯 numpy/图像任务省 1–1.5 s） |
| `factory_startup` | 默认 true（干净、快、不与运行中的 GUI 会话抢资源）；要用用户偏好 / 启动文件设 false |
| `bootstrap` | 默认 true（注入持久内核 `K`）；false 时脚本原样跑 |
| `workdir` / `env` / `args` | 脚本内 chdir + sys.path 首位 / 子进程环境变量 / 额外命令行参数（引号成对不拆：`--flag "a b"`） |
| `shots` | 多视角一体化出图（走 `qc_render_views` harness，见 `7.2） |
| `expect` | 断言（如 `{"minNewObjects":1}`）：空跑即失败 |
| `include_noise` | 产物清单是否含 `__pycache__` / `*.blend1`（默认过滤） |
| `hard_exit` | 完成后直接退出（默认 true，规避 Blender 5.2.3 退出 AV；false = 旧行为） |
| `gpu` / `run_id` | GPU 前导语义（auto / true / false）/ 显式作业 id（台账复现） |

约定：脚本里 `print("HEADLESS {json}")`（单行 JSON）→ 工具把最后一行解析成 `result.parsed`；大结果给 `out_json`。

**作业生命周期**（`submit` → 按 id 收结果）：

```text
blender_run(action="submit", kind="headless",
            script_file="D:\\work\\proj\\tools\\build.py", args="--part hull",
            env={"STAGE": "qc"}, outdir="D:\\work\\out", timeout_ms=1200000)
# → 回执首行给 jobId（RUN <jobId> · headless · queued …）
blender_run(action="status",  id="<jobId>")     # state / slot / timing / pid / result / artifacts
blender_run(action="wait",    id="<jobId>", timeout_ms=600000)   # 阻塞到终态或超时；超时不取消
blender_run(action="collect", id="<jobId>")     # 日志尾 + result（exit/signal/parsed）+ artifacts
blender_run(action="cancel",  id="<jobId>")     # 幂等，清进程树
blender_run(action="list", state="running")
blender_run(action="perf")
```

- **队列有界**：pending 64 / GPU 1 / CPU 2；满了返回 `QUEUE_FULL`（等 running 完成或 cancel 不需要的）。
- **没有同步模式、没有 `as_job` / `wait_s`**：提交即返回，长活永远走 submit → wait / collect。**客户端超时 ≠ 作业失败**，服务端子进程继续跑、产物仍落盘。
- **失败给结构化信息**：`logs`（全量日志路径）/ `lastException` / `traceback` / `reason`；`outdir` 产物默认过滤 `__pycache__ / *.pyc / *.blend1|2 / tmp*`。
- **GPU 前导**：headless 默认注入 GPU 前导（`gpu:"auto"`）并回传 `gpu` 字段 —— 无头进程读不到用户偏好，Cycles 会静默回落 CPU（实测 15.4×）。
- 脚本内可用 `dsh_stage("building")` 打阶段心跳（单行 `DSH_STAGE {json}`）；`status` 解析最后一条，长任务可观测。
- 脚本内可用 `K.win_path / K.wsl_path / K.blend_path / K.out_dir`；异常回传 partial stdout / traceback。

```text
blender_run(action="submit", kind="render",
            file="D:/work/aurora/Aurora.blend", output="//render/frame_####",
            frames="1-120", resolution=[1920,1080], samples=128,
            engine="CYCLES", format="PNG", camera=True, outdir="D:/work/out/frames")
```

```text
blender_run(action="tune", op="status")     # 现状（引擎/设备/采样/降噪/persistent/对象数）
blender_run(action="tune", op="analyze")    # 差分实测：每轮 CPU 侧同步 vs 每采样 GPU 成本（占主线程十几秒）
blender_run(action="tune", op="apply")      # 预设：persistent_data + 降噪器自动判定 + auto_tile off + 采样上限
blender_run(action="tune", op="revert")     # 还原 apply 之前（自动存快照）
```

经验值（作者机器，2318 对象）：**每轮 CPU 同步 ≈4.2 s，persistent_data 让重复渲染 14.6 s → 0.79 s**；砍采样对 CPU 侧几乎无帮助。

### ⑥ `blender_inspect` —— addon 只读命令目录与执行

- 不给 `command` = **help**：列出 addon 的可执行**只读**命令（`name(args)` / enabled / pause_safe / description / access / gate）。
- 内部传输命令（`execute_code` / `get_viewport_screenshot` / `send_selection_to_dsh` / `send_collection_to_dsh`）**不列出也不可执行**：执行 Python 用 `blender_py`，截图 / 看视口用 `blender_see`，作业用 `blender_run`。

```text

blender_inspect(command="get_object_info", args={"name": "Cube"})
```

### 配方 3：内环拟合（让搜索跑在 Blender 侧）

目标：把 6 个尺寸参数调到目标包围盒（示意）。

```text
blender_op(action="loop", op="start", spec={
  "setup": "TARGET=(3.2,1.4,1.1)\nK.target=TARGET",
  "step": "import random\nns['params']={'w':round(random.uniform(2.6,3.8),3),'h':round(random.uniform(0.9,1.9),3)}",
  "measure": "bpy.data.objects['Cube'].dimensions=ns['params']['w'],ns['params']['h'],1.0"
             "\nerr=[abs(bpy.data.objects['Cube'].dimensions.x-K.target[0]),abs(bpy.data.objects['Cube'].dimensions.y-K.target[1])]"
             "\nns['metrics']={'ex':err[0],'ey':err[1]}"
             "\nns['violations']={'ratio':max(0.0, 1.6-bpy.data.objects['Cube'].dimensions.x/max(1e-6,bpy.data.objects['Cube'].dimensions.y))}"
             "\nns['score']=penalize({'ex':err[0],'ey':err[1]},{'ratio':ns['violations']['ratio']},lam=5.0)",
  "iterations": 5000, "budget_ms": 30000, "measure_every": 1, "top_k": 20, "interval": 0
})
blender_op(action="loop", op="status")   # 看 best / tps / history
blender_op(action="loop", op="board")    # 候选表
blender_op(action="loop", op="export", path="/tmp/fit_best.py")   # 落成可复用脚本
```

**更省事的路（声明式）**：同一件事也能一次调用交给 `blender_op(op="shape_search", …)` —— `objective`（`silhouette_iou` / `profile_err` / `aabb_err`）+ `params` 区间 + `apply`（每轮把 `ns["params"]` 落到场景的代码，改完记得 `view_layer.update()`）。它自动选 grid / random、托管 start → 轮询 → board → export，并把场景落到 best（内环自己会停在"最后一次迭代"）；先 `dry_run=true` 可只校验并回 spec（不启动内环、不需要 GUI 会话）。要 `penalize` / `anneal` / 多目标 / `group_key` 分批，仍回到上面手写 spec。**它只在 GUI 会话里有效**（不花模型回合的内环跑在 Blender 侧）。

**收敛后必须换一条通路复核**（例如用 `blender_py` 重新量一遍包围盒 / 体积 / 渲染），因为内环只优化你写的 `score`。

## 3.5 P0–P2 新链路速查

> 一句话：**装配是否成形**、**改了多少**、**判定会不会过期**、**参考图能不能量**、**白模/交付能不能一键跑** —— 都有判据与入口。

### 3.5.0 边界与验收（先读）

- **验收唯一判据**：`blender_session(action="doctor")` 返回 `kind=ok`；其它自检只定位单项功能。
- **明确不覆盖 / 默认未装依赖**（不要当已支持用）：
  - **人脸 / landmark 检测**：不自带人脸检测 —— `face_*` 要你提供 landmarks（自己标或外部 MediaPipe / EMOCA 出）；本机无 cv2 / MediaPipe；
  - **OCR**：不支持；
  - **DXF**：不支持（导入 / 导出都没有）；
  - **外部第二通路**：`ext.gltf_validate` / `ext.ext_mesh_check` 依赖 `runtime/ext/` 下本地安装的 glTF-Validator / Open3D（默认部署未装，提示里会给安装命令；未装时明确 `ok:false`）；manifold3d 也未安装。
- 所有"新能力"都遵守三态纪律：`degraded`（证据不足 / 降级）**不等于通过**；`unresolved` 不猜。

### 3.5.1 异步作业（没有 GUI 会话时的备用通道）

3.1 里"无头"只有一种：`blender_run(action="submit", kind="headless")` 起一个 **fresh **blender -b**** 进程跑脚本。没有交互式无头会话（worker）、没有 `session=auto`、没有"exec 一步看一眼"的无头形态 —— 改一步看一眼一律走 GUI 的 `blender_py`。

```text
blender_run(action="submit", kind="headless", preload="audit,assembly,imgtools",
            script="…", timeout_ms=1200000, outdir="D:/out")
blender_run(action="wait", id="<jobId>", timeout_ms=600000)     # 阻塞到终态或超时；超时不取消
blender_run(action="collect", id="<jobId>")                     # stdout/stderr 尾部 + result + artifacts
```

- 每个作业是独立 fresh 进程：**不要指望跨作业的 `K` 状态**；中间结果用文件（`out_json` / 工作区路径）传递。要连续状态，用 GUI 会话里的 `blender_py`。
- 队列有界（pending 64 / GPU 1 / CPU 2，满了 `QUEUE_FULL`）；长活就是 `submit` 后接着干别的，`status` / `wait` / `collect` 按 id 收。
- 批处理 / 长渲染 / 不需要人看视口的活才走无头；要"看视口 / 整窗 / 吃用户当前场景"的，一律 GUI 工具（`blender_see` / `blender_py`）。
- 需要多机位、计时、预算的批量出图用 `qc_render_views`（见配方 7）；作业形态的 `preload="qc,qc_render"` 同样可用。

### 3.5.2 参考图量具（img_digest / img_probe / img_measure / img_calib）

协议：**看图必须产出数字**（写进 spec.py），否则算白看；每次 ≤2 张图且带明确问题。

```text
blender_op(op="img_digest", args={path:"D:/ref/front.png", known_len:{mm:2000, px:320}})
  # → 轮廓/bbox/对称/直线/特征/比例尺/可读性 + 原生裁剪图册 + 标注总图
  #   + verdict（ready_for_spec / needs_scale / needs_views / unreadable / degraded）
blender_op(op="img_probe",  args={image_id:"…", op:"scan_y", y_px:420})     # 亚像素边缘/宽度/圆孔/距离/灰度剖面
blender_op(op="img_measure",args={image_id:"…", px_per_mm:0.16, targets:[{key:"width", feature:"bbox_w", expect_mm:2000, tol_pct:2}]})
blender_op(op="img_calib",  args={views:[…], shared:[{key:"width", views:{"front":640,"side":638}}]})   # 多视逐视标定 + 跨视一致性
```

- 没有 `known_len` ⇒ 所有 mm 字段为 `null`（**绝不编**）；px 是 loaded 尺度，回执给 `native_px / loaded_px` 换算；
- `img_digest` 一次给"可确认数字表 + 原生裁剪图册 + 可读性 + 下一步"；`img_probe / img_measure` 按需量测；`img_calib` 输出每视 `px_per_mm` 与跨视偏差；
- 判"像不像"用 `img_diff` 的 IoU（L2 证据），不靠肉眼估。
- `img_digest / img_probe / img_measure / img_calib` 是只读 op：无需 GUI 会话即可跑（本地或 Gateway 只读通道），不会启动 Blender。

### 3.5.3 装配（asm_scan / manifest / merge / repair / export / gate）

```text
blender_op(op="asm_manifest", args={action:"init", path:"D:/proj/assembly.json", assembly:"Aurora"})
blender_op(op="asm_manifest", args={action:"add_part", path:…, part:{id:"P1", file:"…/part_a.blend", objects:["GEO_A"]}})
blender_op(op="asm_manifest", args={action:"seal", path:…})
blender_op(op="asm_scan",     args={manifest:"D:/proj/assembly.json"})     # clash/contained/float/unresolved 全对全
blender_op(op="asm_merge",    args={manifest:…, dry_run:true})              # 先看 append 计划
blender_op(op="asm_merge",    args={manifest:…, out_blend:"D:/proj/merged.blend", dry_run:false})
blender_op(op="asm_repair",   args={manifest:…, dry_run:true, policy:"safe"})   # 规划；dry_run=false 才动手（先 snapshot，复扫）
blender_op(op="asm_gate",     args={manifest:…})                            # export_allowed 仅 verdict=pass
blender_op(op="asm_export",   args={manifest:…, out_dir:"D:/Blender/proj", name:"proj", merge:true})
```

- **asm_repair policy**：默认档（safe 行为）自动只做 **translate / snap**；**显式 `policy="safe"` 硬禁布尔 / scale**；`policy="manual"` 只规划不执行（`dry_run=false` 也只回只读计划）；`policy="aggressive"` 保留布尔路径（仍需 `allow_boolean=true`，布尔改拓扑且必须有文件级 snapshot）。`plan[].risk` / `blocked[].blocked_reason` 逐条可读。⚠ 兼容旧调用：不传 policy 时 `allow_boolean=true` 仍视为显式授权。
- **asm_export**：`merge=true` 先 `asm_merge`（gate + snapshot，不过门不导出）；GLB / FBX / OBJ 官方导出器（自动 enable `io_scene_gltf2` / `io_scene_fbx`）；`dry_run=true` 只回计划不写盘；`manifest_md5` + 逐文件 md5 + append-only ledger；**全部格式失败 `ok:false`**。
- **判据**：`hidden_ok` = 声明内隐藏交叠（不过报）；`clash` = 真穿模；`contained` = 完全包含（旧全对全漏判的补丁）；`unresolved` = 证据不足；`asm_gate` 用 manifest 连接图判浮空。
- 装配 op 里 `dry_run=true` 与只读 op（`asm_scan / asm_manifest / asm_gate / asm_selftest / asm_help`）不需要 GUI 会话；真正执行 `asm_merge / asm_repair / asm_export` 需要 ready GUI 会话。

### 3.5.6b 参数化曲面（surface_*）

### 3.5.9 仍有效的既有能力（速查）

> 评估表：`docs/Procedura-融合分析.md`；历史版本说明见 `CHANGELOG.md`（仅作历史，操作以本文为准）。

#### 3.5.9.1 网格体检与装配门（op 前缀 `audit_`）

```python
blender_op(op="audit_scene")                       # 全场景：哪几个对象最脏（只读）
blender_op(op="audit_connectivity")                # 连通分量：这堆对象连成几块？谁跟谁不挨着？（只读）
blender_op(op="audit_connectivity", args={"micro_gap_mm": 2.0})   # 口径：带设计间隙的装配件按工艺给
blender_op(op="audit_gate")                        # 出厂门：连通 + 包络 + 三态（未确认 → degraded，不给通过）
blender_op(op="audit_drift", args={"a": "objA", "b": "objB"})     # 形状漂移（对称 Chamfer，BVHTree 点到曲面）
blender_op(op="audit_measure", args={"scope": "Cockpit", "k": 4}) # 测量包：bbox + 逐轴间隙/重叠 mm/% + 邻居
blender_op(op="audit_snap_floaters", args={"scope": "Cockpit"})   # 浮块贴到最近邻（默认 dry_run，只报告）
blender_op(op="montage", args={"images": [], "cols": 4})          # 拼图（证据分级 L2）
```

判据（`audit_help` 里也有）：

- **可见浮块** = 分量最长 bbox 边 ≥ 全模型最长边 **1%**（严重度只看它，不看体积）。
- **相接口径** `micro_gap_mm`：默认 **0.3 mm**（单一实体 / 3D 打印口径）；带设计间隙的装配件按工艺给（1–2 mm 常见）。
  口径与间隙分布随返回回传（`gate_caliber` / `gap_histogram` / `floater_gap_range_mm`）。
- 判据**不再是**「最大分量=主体、其余都是浮块」（两个等大零件会随机挑一个当浮体），而是**每个分量都问「你有没有跟别的分量相接」**。
- bbox 间隙在多对象装配里恒为 0（普遍重叠）→ micro 判定要过**网格级复核**（BVH + 面上采样）；
  **默认不设面数上限（全跑，验收不随规模退化）**；只有显式设 `DSH_*` env 或 `max_tris` 参数才启用上限 —— 那时超限会跳过复核 → `attached=null` → **门降级（ok=null）**，未确认绝不当成已通过。
- `audit_drift` 量的是**形状漂移**：归一化会消除平移与整体缩放，所以位移不看它 → 看 `bbox_delta.moved_mm`。
  0.05 ≈ 最长边 2.5%；同网格读 0。
- 实测参考（COCKPIT_DELIVERY，14 对象 / 97,438 面）：0.3 mm 口径 → 178 浮块（与最近邻相距 0.33–1.14 mm）+ 970 相接；2.0 mm → 63 浮块。
- 这些 `audit_*` op 都是只读的：`blender_op(op=…)` 不要求 GUI 会话，也不启动 Blender。

#### 3.5.9.2 契约层（contract 家族）

```python
blender_op(op="ledger")                                     # 证据账本：源变过的条目自动标 stale=true
blender_op(op="mate_check", args={"conn_id": "pin_fit", "fit": "location"})   # 配合门：接触面积/单边间隙/侵入
blender_op(op="fit_help", args={"feature": "socket"})       # 装配特征库（9 特征 + 四档 + ISO 273 + 共享标称纪律）
blender_op(op="interference_report", args={"scope": ["IX", "IY"]})  # 逐对深度/体积占比/严重度 + 计划内豁免
```

- 判定会**随几何失效**：`verify` 记录 bbox 快照，之后中心漂移 > 10% 对角线或尺寸 > 20% → 自动降级 `unresolved`（`verdict.demoted` 留理由）。
- `mate_check` 的 `nominal` 语义 = **期望单边间隙 mm**（可负）；只看不写状态，要落状态再调 `verify` / `advance`。

#### 3.5.9.3 事务与交付（`blender_session(action="txn")` / deliver_*）

3.1 的 txn 只有**两级快照**，没有旧的 `edit_begin/check/accept/revert` 预算流程：文件级 `snapshot` / `restore`（整场景回退，写 .blend 副本）与对象级 `mark` / `revert`（毫秒级、就地回滚 transform / 材质槽 / 可见性 / 修改器开关）。

```python
blender_session(action="txn", op="snapshot", label="before_boolean", note="拓扑改动前")   # 文件级快照（大场景 MB 级成本）
blender_session(action="txn", op="restore",  label="before_boolean", into="auto")        # 默认回写快照出处文件；into="snapshot" 只读查看
blender_session(action="txn", op="list")                                  # 快照 / mark 清单
blender_session(action="txn", op="prune", keep=5)                         # 只留最近 N 个快照
blender_session(action="txn", op="mark", objects=["Backrest"], label="tenon_12mm")  # 对象级回滚点（毫秒级）
blender_session(action="txn", op="revert", label="tenon_12mm")            # 只回对象级改动
blender_session(action="txn", op="marks"); blender_session(action="txn", op="drop")     # 列出 / 丢弃 mark
blender_op(op="deliver_export", args={"dir": "D:/Blender/house", "scope": "House", "name": "house"})
blender_op(op="deliver_verify", args={"path_or_dir": "D:/Blender/house"})    # 改一字节/加一面都会 FAIL
```

- `restore` 默认 `into="auto"`：载入快照后把会话放回**快照的出处文件**（保存落回自己的工程，不写进快照目录），并在载入前自动留 `pre_restore` 备份；要非破坏查看传 `into="snapshot"`。
- **对象级 mark/revert 不含拓扑 / UV / 顶点级改动** —— Boolean、合并、删面之后回不去（revert 会跳过并报告）；那种回滚用文件级 `snapshot` / `restore`。
- 快照 / mark 是会话内工具：`snapshot` / `restore` 会动场景，需要 ready GUI 会话；`list` / `marks` 只读。

#### 3.5.9.4 渲染 harness 三件（`qc_render_views`）

```python
blender_op(op="qc_render_views", args={"mode": "parts_color", "views": ["iso", "front", "top"]})
blender_op(op="qc_render_catalog")          # 22 视角 / 别名 / ortho 语义（未知名会回传，不再静默当 iso）
```

- 每个 jsonl 行都有**实测 `device`**（Cycles 静默回落 CPU 是 ≈7× 退化且无症状，这条专治它；拿不到就 `null` + 说明，不猜）。
- `parts_color` 出图**完整还原**（含共享 mesh 的隔离副本），图例在 `<outdir>/parts_color_meta.txt`。
- 长渲染（>1 min）不要同步等：改走 `blender_run(action="submit", kind="render", …)` 或 `kind="headless"` + `preload="qc,qc_render"`，再 `wait` / `collect`。

## 4. 安全与并发（务必读一遍）

1. **写操作前先留回退点**：`bpy.ops.wm.save_as_mainfile(filepath="...")`、`blender_session(action="txn", op="snapshot")`，或 `opt join` 的 `save_before`。
2. **内环必须有安全阀**：`iterations` / `budget_ms`；跑飞了用 `blender_op(action="loop", op="stop")` 急停（它会在下一个 tick 退出）。
3. **不要连续调 `render.render()`**（GUI 会话里容易撞 CUDA context，且全程占主线程）→ 改 `blender_run(action="submit", kind="render")` 或 `kind="headless"`。
4. **GPU / 驱动相关操作必须在主线程**：addon socket 线程里调 `cycles.preferences.get_devices()` 会直接崩 Blender（作者机器崩过一次）；需要排线程就用 `bpy.app.timers`。
5. **写作用域与多 agent**：
   - 写 op（改场景 / 渲染 / 事务）默认**独占**：一次只允许一个持有者；
   - 多 agent 用 `blender_session` 协作：`action="claim"` 建会话、`action="grant"`（`scopes` = `exclusive` / `collection:名` / `prefix:名` / `object:名`，`ttl_ms` 限时）把某块场景放开、`action="revoke"` 收回、`action="grants"` 查当前授权；
   - 冲突时按回执里的 holder / expiresInMs 等它结束或申请 grant；**3.1 模型侧没有 force 抢租约的工具**，Gateway 的 /lease 路由由宿主管理；
   - `blender_session(action="status")` / `who` 接口看当前持有者与剩余时间。
6. **`blender_py` 是万能通道**（有意保留）：它等于在 GUI 会话的 Blender 进程里执行任意 Python。
   - 通道只监听 `127.0.0.1`（别改成 `0.0.0.0` 暴露到公网）；
   - 别把 API key / 私有数据写进会被日志记录的字符串；
   - 只在可信的 Blender 工程与可信的模型侧使用；
   - 执行期间会话锁定（`py_busy`），别让两个 agent 同时发长脚本。

## 5. 排错速查

### 5.1 三级诊断（`doctor` 的 `kind`）

| kind | 含义 | 处置 |
|---|---|---|
| `ok` | TCP + ping + bpy 往返都通 | 无需处理 |
| `blender-unreachable` | Gateway 上没有 ready 的 addon 实例（addon 未启动 / 未 Connect / 协议被拒） | **宿主负责启动 Blender（3.1 Gateway 由宿主管理，模型侧没有 launch 工具）**：请用户启动 Blender → N 面板 →「DSH Blender Bridge」→ Connect；其后用 `blender_session(action="doctor")` 复核 |
| 写操作 409 `leased` 但对方会话其实已经关了 | `blender_session(action="status")` 看 holder | 宿主的 /lease 会自动回收死会话租约（holderAlive:false）；等一会儿重试或申请 grant |
| `main-thread-busy` | addon 活着（ping 通），但 bpy 命令超时 | Blender 在渲染 / 模态操作 / 跑重活 → 等它空下来；长渲染改 `blender_run(kind="render")` 作业 |
| `addon-thread-stuck` | 端口通但 ping 也不回 | 上一条长命令还在 addon 线程里；不要连发，等结束；必要时重启 Blender |
| `addon-unresponsive` | Gateway 有 addon 实例，但 addon 在预算内（doctor 4s、/status 5s）没回 `execute_code` 的 bpy 往返（超时） | 先确认 Blender 在运行且「DSH Blender Bridge」已 Connect；再等长命令 / 渲染结束，必要时重启 Blender。Gateway 进程本身由宿主看护，模型侧无需（也没有）restart 工具 |
| `addon-error` | addon 明确回了错误（非超时，如「AI 操作已暂停」/ 脚本报错 / `BUSY_RENDER`） | 按报错修；渲染中则等渲染结束或用 `render_wait`；不是主线程忙，不用反复重试 |

`/status` 在工具层另有一套 `code`：`addon_unresponsive`（addon 超时）、`addon_error`（addon 回错）、`busy_render`（Blender 正在渲染，等 `render_wait`）、`backend_timeout`（宿主等 `/status` 超时）、`backend_unreachable`（连接级失败，含 ETIMEDOUT / ECONNREFUSED）。

### 5.2 高频坑（按代价排序）

| 坑 | 现象 | 做法 |
|---|---|---|
| 帧 / 脚本路径两端不互通 | 出图报"文件不存在" / 工具读不到 | 用 `doctor` 的 `config.workDir` 核对；改成两端都能读写的目录 |
| 往 UNC（`\\\\wsl.localhost\\...`）写文件 | "返回成功但没有文件" | 写盘一律用 Windows 盘符路径（`D:\\...`） |
| `blender_py` 无状态 | 上次的变量读不到 | GUI 会话内 `blender_py` 共享同一 Blender 进程（变量/场景都在）；`blender_run` headless 每次是 fresh 进程，跨作业用文件传 |
| addon 面板重启后没 Connect | 命令全超时 | 重新 Connect；把需要的开关存进 startup |
| 参数名按 MCP 文档写 | `unexpected keyword argument` | 按 addon 真签名（`get_object_info(name)`） |
| 后端起不来 / 端口被占 | 工具报"后端不可用"（宿主侧） | 3.1 Gateway 由宿主看护；请宿主重启 DSH / 检查 `39877` 占用 |
| 找不到 blender.exe | `blender_run(kind="headless"/"render")` 报 `blender_exe_missing`（含配置指引，<1s 返回） | 三种配置方式见 [配置参考.md](配置参考.md) `4；Windows Steam 安装已自动探测（来源 `auto:steam`） |
| `blender_py` 报 `py_busy` | 会话正被占用（上一个脚本 / see 还没结束） | 等它结束再发；别并发连发长脚本；reduce 单步体量 |
| 提交后客户端超时 | 模型侧等待超时 | **不是作业失败**：作业仍在服务端跑 → `blender_run(action="status"/"wait"/"collect", id=…)` 按 id 收 |
| `QUEUE_FULL` | 队列满（pending 64 / GPU 1 / CPU 2） | 等 running 完成，或 `cancel` 不用的作业 |
| GLB / FBX 导出失败 | `asm_export` / `deliver_export` 某格式 `ok:false` | 看 `exports[].error`；GLB 需 `io_scene_gltf2`、FBX 需 `io_scene_fbx`（工具会自动 enable）；OBJ 用 `wm.obj_export` |
| `asm_export` 导出被拒 / 不写盘 | `ok:false` + merge/gate 回执 | `merge=true` 时先过 `asm_merge` 内部 gate（不过门不导出）；看 `merge.gate` 与 `blocked/error` |

## 7. 路径选择：GUI 优先，无头作业（当前）

> 路线决定与证据（历史归档）：[`docs/archive/headless优先-路线决定.md`](archive/headless优先-路线决定.md)。
> 一句话：**默认先开 GUI Blender + Connect**；只有无 GUI / 批处理 / 长活 / 不需要人看画面时才走无头作业 —— 无头也能出图看，不会失明，但每个作业都是 fresh 进程。

### 7.1 三十秒判定

| 你的情况 | 默认走 | 第一句怎么写 |
|---|---|---|
| 改一步看一眼 / 用户 live 场景 / 需要人看画面判断 | **GUI（默认）** | `blender_py(code=…, see=True)` / `blender_see` |
| 看用户视口 / 整窗截图 / 依赖屏幕 / 模态的 `bpy.ops` | **GUI（默认）** | `blender_see`（视口 / `full=True`）/ `blender_py` / `blender_op(op="gui_frame")` |
| 无 GUI、批处理、长活、数据探针 | **无头作业（备用）** | `blender_run(action="submit", kind="headless", preload="audit", script="…")` + `wait` / `collect` |
| 只读判定 / 验收 / 参考图量测（无 GUI） | **只读 op（本地或 Gateway 只读通道）** | `blender_op(op="audit_scene")` / `op="asm_scan"` —— 不要求会话，也不启动 Blender |
| 多视角 QC / 成品渲染（分钟级） | **无头作业 + `shots` / `kind="render"`（备用）** | `blender_run(action="submit", kind="render", …)` → `wait` / `collect` |
| 参考图对拍 / 交付导出 / 生成器复现 | **无头作业 + `preload`（备用）** | 见 `7.3 骨架 C |

**默认先开 GUI。** 只有明确「无 GUI / 批处理 / 长活 / 不需要人看画面」时才走无头作业；需要 live 场景 / 视口 / 屏幕上下文时，必须走 GUI。无头作业**不是**交互式会话：没有跨作业的 `K` 状态，也没有"执行一步、马上看"的形态。

### 7.2 无头作业参数与回执速查（`blender_run` · `kind="headless"`）

| 参数 | 类型 | 说明 |
|---|---|---|
| `script` / `script_file` | string | Python 源码 / 直接跑 .py 文件（后者自动注入 `__file__` + sys.path） |
| `file` | string | 打开的 .blend（WSL 或 Windows 路径，自动映射） |
| `preload` | string | 预载模块（逗号分隔）→ `K.dsh_*_api`，如 `"audit,qc,qc_render"` / `"assembly,audit,contract,clearance,gate,mesh_fix,geo,txn"` |
| `engine` | string | `eevee`（默认）/ `cycles` / `keep` / `none`（纯 python 任务省 1–1.5 s） |
| `shots` | JSON 数组 | **多视角一体化**：走内置 harness（`qc_render_views`）—— 省掉每个建模方 50~60 行相机 / 三点光 / AgX 样板 |
| `outdir` / `out_json` | string | **接受 WSL 路径**（`7.4），回执给真实写入路径 |
| `factory_startup` / `bootstrap` | bool | 默认都 true（干净启动 / 注入持久内核 `K`） |
| `workdir` / `env` / `args` | string / JSON | 脚本内 chdir + sys.path 首位 / 子进程环境变量 / 额外命令行参数 |
| `timeout_ms` | number | 进程上限：默认 180 s、上限 30 min（到点杀进程树） |
| `expect` / `include_noise` / `hard_exit` | | 断言（空跑即失败）/ 产物清单是否含噪音 / 完成后直接退出（默认 true） |
| `priority` / `run_id` / `gpu` | | 队列优先级（-100..100）/ 显式作业 id / GPU 前导语义（auto / true / false） |

`shots` 的元素字段（与 `qc_render_views` 的 `views` 元素同形）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✔ | 视角名（进文件名与回执） |
| `from` | ✔ | 相机位置 `[x,y,z]`（世界坐标） |
| `look_at` | ✔ | 注视点 `[x,y,z]` |
| `lens` | | 焦距 mm（默认 50） |
| `res` | | `[w,h]`；给**数字** = 正方形（`res: 1024` ≡ `[1024,1024]`） |
| `samples` | | 采样数 |
| `ortho` / `ortho_scale` | | 正交投影 / 正交尺度 |
| `margin` | | 自动取景余量（同 `qc_render_views`，默认 1.12） |

**回执**：`collect` 的 `result` 给 `exit / signal / parsed`，`artifacts` 列产物（含每张 `path / ms / md5 / coverage_estimate`）；
**主体占画面 < 5% → `warning.code = "subject_too_small"`**（取景自诊断：18.1 m 的件让 1.92 m 的引擎环只剩 ~140 px 这类事故，现在出图当场告警）。

```python
r = blender_run(action="submit", kind="headless",
                file="D:/work/aurora/Aurora.blend",
                outdir="D:/work/out/shots",           # WSL 路径也可以（`7.4）
                timeout_ms=1200000,
                shots=[
                  {"name": "iso",   "from": [9, -9, 6],  "look_at": [0, 0, 1], "lens": 35, "res": [1024, 576], "samples": 64},
                  {"name": "front", "from": [0, -14, 2], "look_at": [0, 0, 1], "lens": 50, "res": [1024, 576], "samples": 64},
                  {"name": "top",   "from": [0, 0, 16],  "look_at": [0, 0, 1], "ortho": True, "ortho_scale": 16, "res": 1024},
                ])
job = r.jobId                                    # submit 回执首行给 jobId；其余字段见 status
blender_run(action="wait", id=job, timeout_ms=600000)    # 阻塞到终态或超时；超时不取消
blender_run(action="collect", id=job)            # 日志尾 + result（exit/signal/parsed）+ artifacts
```

#### 作业生命周期（结果永不丢）

| 项 | 值 |
|---|---|
| 提交 | `blender_run(action="submit", kind="headless"|"render", …)` —— **立即返回 jobId**，没有同步模式 |
| 客户端等待 | `action="wait"` 默认 **120 s**、上限 **600 s**；到点回超时**不取消作业** |
| 怎么收结果 | `action="status"` 单次查 / `action="wait"` 阻塞等 / `action="collect"` 拿日志尾 + result + artifacts |
| 取消 | `action="cancel"` 幂等（已到终态也回 ok，清进程树） |
| 列表 / 队列 | `action="list"`（`state` / `kind` / `owner` 过滤）/ `action="perf"`（pending / slots gpu·cpu） |
| 队列上限 | pending 64 / GPU 1 / CPU 2；满了 `QUEUE_FULL` |
| 内层 timeout | `timeout_ms` 默认 180 s、上限 30 min（进程上限；与 wait 超时是两套预算） |

```python
# 预期 > 100 s：别赌，直接 submit 后干别的，按 id 收
r = blender_run(action="submit", kind="headless",
                script_file="D:/work/aurora/tools/preview.py",
                args="--part hull_aft", timeout_ms=900000)
blender_run(action="status",  id=r.jobId)                    # state / slot / timing / pid
blender_run(action="wait",    id=r.jobId, timeout_ms=600000) # 阻塞到完成或超时
blender_run(action="collect", id=r.jobId)                    # 日志尾 + result + artifacts
```

#### 回执结构化：别用正则抠结果

- `submit / status / wait / collect` 的回执是**结构化 presenter 文本**（首行 `RUN <id> · <kind> · <state> …`，随后 timing / pid / result / artifacts / logs），不是要二次正则的 JSON。
- 脚本里 `print("HEADLESS {json}")`（单行 JSON）→ `collect` 的 `result.parsed` 已解析；大结果给 `out_json`，截断时看 `resultPath` / `resultTruncated`。
- 不要再写 `result: (\{.*?\})` 这类正则（双层转义 + 截断时会抛异常）。

#### stage 心跳：长任务可观测

```python
# 脚本里打阶段心跳（bootstrap 注入；K.progress 等价）
dsh_stage("loading")
dsh_stage("building", part="hull_aft")            # 可带自定义键
for i in range(total):
    ...
    dsh_stage("rendering", done=i + 1, total=total)
```

- 输出形态：单行 `DSH_STAGE {"name":"building",...}`；作业日志里保留，`collect` 的 `logs.stdout` 尾部能读到；
- spawn 注入 **`PYTHONUNBUFFERED=1`** → 作业日志在**运行中**就有增量（不会等到进程退出才落盘）。

### 7.5 陷阱：bash 沙箱的 `/tmp` 与 fs 工具**不共享**（每次 bash 调用即焚）

**现象**（本机 web profile 实测复现）：

```bash
# 同一次 bash 调用里：看得见
echo hello > /tmp/dsh_probe.txt && ls -la /tmp/dsh_probe.txt      # ✅ 有文件
```

```bash
# 紧接着的**下一次** bash 调用：没了
ls -la /tmp/dsh_probe.txt     # ❌ No such file or directory
```

而 `read` / `read_image` 等 fs 工具**从来就看不到** bash 的 `/tmp`（`not found`）。
本轮 engine / hull_aft / gear-arms 各为这个坑浪费 1~2 轮（engine 原话：「同一 bash 调用里 `ls` 看得见，
紧接着 `read_image` 报 not found，另起一次 `ls` 是空目录」）。

**规则：临时文件必须落工作区**（或任务约定的产物目录），不要落 `/tmp`、`/var/tmp`、`$TMPDIR`。

```bash
# ✅ 正确：工作区下的临时目录，跨 bash 调用与 fs 工具都可见
mkdir -p /home/sixtyseven67/DSH/.tmp/<task> && python3 probe.py > /home/sixtyseven67/DSH/.tmp/<task>/probe.json
```

```python
# ✅ Blender 侧同理：产物目录给两端都能读写的路径（不要给只读挂载，也不要给 bash 的 /tmp）
blender_run(action="submit", kind="headless", outdir="/home/sixtyseven67/DSH/.tmp/hull_aft",
  script="import os, json; print('HEADLESS ' + json.dumps({'dir': os.getcwd()}))")
```

| ❌ 别这么写 | ✅ 改成 |
|---|---|
| `bash: … > /tmp/x.json` 然后 `read` 它 | 写 `<工作区>/.tmp/<task>/x.json` |
| `blender_run(kind="headless", outdir="/tmp/out")` | `outdir="<工作区>/.tmp/<task>/out"` |
| 产物落 `/mnt/d/...` 再 `read_image` | 落工作区；归档阶段再按约定拷到 `D:\\Blender\\<项目>\\` |
| 手拼 `\\\\wsl.localhost\\Ubuntu\\…` UNC | 直接给 WSL 路径（`7.4） |

### 7.6 常见误用（照这张表自查）

| 误用 | 后果 | 正确做法 |

| 跑 >100 s 的 headless 却同步等 | 白等一个等待窗口，还占着模型回合 | 预期长活直接 `submit` 后台 + `wait` / `collect`（超时不取消） |

## 8. GUI Blender 由宿主启动（3.1）

3.1 起 **Gateway 进程与 GUI Blender 的生命周期由宿主（DSH）管理，模型工具不再启动 / 重启 / 接管 Blender**。模型侧没有 `launch / restart / lease / release` 这类工具 —— 需要 GUI 时的标准流程是：

1. 用户自己启动 **GUI Blender**（不是 `blender -b`），在 `Edit → Preferences → Extensions → Install from Disk` 安装本仓的 `addon/dsh_blender_bridge.zip`；
2. 在 3D 视图按 `N` →「DSH Blender Bridge」→ **Connect**（addon 主动外连宿主 Gateway，无入站端口）；
3. 模型侧用 `blender_session(action="status")` / `action="doctor")` 复核会话与通道，`kind=ok` 后才执行写操作。

- **纯无头作业不需要 GUI**（`blender_run(action="submit", kind="headless"|"render")` 独立 `blender -b` 进程），也**不占用** GUI 会话。
- 诊断 / 重启 Gateway 是宿主的事：模型侧只报告状态并请用户处理（必要时重启 DSH），不尝试拉起 Blender。
- 多 agent 同时操作同一 Blender 时按 `4 的写作用域与 grant 规则协作，不存在"抢 launch / 抢租约"的模型工具。

## 9. 宿主集成（`@` 提及 + 原生选中）

> **DSH 侧的「Blender 视口」面板、点击进消息、模型请求点选与 TUI 侧栏面板均已删除。**
> 选中的入口改到 Blender 侧：原生选中 → N 面板发送（见 `10）；只读的视口截图仍由模型工具 `blender_see` 负责。
> 后端 `/host/view/*`、`/host/pick*`、`/host/ready` 路由**同步删除**；现存宿主路由只有
> `/host/selection`（+ `/latest`、`/consume`）、`/host/scene-items`、`/host/jobs`（+ `/log`）。

宿主集成是**用户侧**能力（你操作 → 进你自己的消息），**不是模型工具**：它走独立 HTTP 路由 `/host/*`，
**不进** op 目录、**不加**模型工具 ⇒ 6 个工具 / 228 个 op 的能力面**零变化**。

### 9.1 还在的能力：`@` 提及

输入框敲 `@` 出对象 / 材质 / 集合候选（引用带前缀 `object:<name>` / `material:<name>` / `collection:<name>`）；
选中后由 `codec` 拆掉前缀、序列化成 `<blender-object>Cube</blender-object>`，模型拿到确切名字，不用猜。
候选来自 `GET /host/scene-items?q=`（只读后端缓存，**不占** Blender 主线程）。

### 9.2 前置与端口

| # | 条件 | 怎么确认 |
|---|---|---|
| 1 | 宿主 Gateway 在跑（`127.0.0.1:39877`） | `curl -sS http://127.0.0.1:39877/health` |
| 2 | Blender 开着且 addon 已连接 Gateway | `curl -sS http://127.0.0.1:39877/doctor` → `kind=ok`；或 `blender_session(action="doctor")` |
| 3 | `lib/client.js` 已构建，且 **DSH 已重启** | `npx vitest run tests/unit/js/contract/client-bundle.test.ts` |
| 4 | addon **v2.0.0+ / protocol 12**（原生选中 / 集合 / 子元素 / 暂停 AI） | `blender_inspect(command="get_addon_info")` → `addon_version [2,0,0]`、`protocol_version 12` |

端口一览：Gateway `39877` · DSH GUI `3080`（addon 主动外连，**无入站端口**；都只监听本机，**不要**对外暴露）。

`/host/*` 的 CORS 只对 **HTTP loopback** 与**精确的 `dsh-app://app`** 回显 Origin（其他来源不带 `Access-Control-Allow-Origin`）。
这不是请求身份验证，也不是服务端 403 拒绝。

### 9.3 改完 / 升级完必须重启 DSH

客户端半边（`lib/client.js`）是 DSH 启动时加载的模块；升级本插件后**必须重启 DSH**，否则 `@` 提及与原生选中桥都不会更新。
Gateway 进程由宿主看护，模型侧没有重启工具。

### 9.4 自检

```bash
npx vitest run tests/unit/js/contract/client-bundle.test.ts     # bundle 形状 + @ codec + 选中文本/插入路径
npx vitest run tests/integration/js/selection-store.test.ts   # 后端选中存储（消毒/seq/consume）
```

## 10. Blender 原生选中 → DSH（addon v2.0.0+）

### 10.1 这是什么

"选中物体"不再必须去 DSH 的视口面板里点低清截图：**在 Blender 原生选区里选**，按 N 面板的按钮，
选中的对象名就会进 **DSH 当前会话的输入框**（草稿，**不自动发送**，发不发你决定）。

同时 Blender 侧给出统一的 **activity 判定**（人 / AI / 空闲 / 同时），面板实时显示，模型也能查 ——
AI 不会在你拖拽、变换、进编辑模式或刚撤销时把中间态当最终态。

### 10.2 三步用起来

1. **addon v2.0.0+（Blender 扩展包）**：用本仓 [`addon/dsh_blender_bridge.zip`](../addon/dsh_blender_bridge.zip)（或重新安装 / 启用一次），
   **重启 DSH**（客户端半边是启动时装载的）。
2. 在 Blender 视口里选物体：点选 / 框选 / Shift 加选都行；多选会发全部名字（上限 200）。
   进**编辑模式**选顶点 / 边 / 面，或**姿态模式**选骨骼，也会一起发送（`selection.sub`）。
3. 3D 视图按 `N` →「DSH Blender Bridge」→ **Selection → DSH**：
   - **多选模式**：选中若干物体 → 点「对象列表（N）▸」展开（默认折叠；带滚动条）→「发送选中到 DSH」；
   - **集合模式**：在「集合」下拉里选一个集合（或点旁边的 ⟳ 从选中对象自动推断）→ 点「成员列表（N）▸」展开查看
     →「发送集合到 DSH」（几百个零件不必逐个选）。
   - 展开后拖动「高度（行）」滑杆即可调整列表可见高度（3–30 行，默认 8），内容多了用列表自带滚动条。
   - **子元素**：编辑模式选点 / 线 / 面时，展开列表会多出「顶点 12 / 边 3 / 面 7」这类行；
     草稿会写成「Blender 编辑模式（网格）「Cube」：已选 12 顶点 / … 顶点索引：…」，
     模型按索引用 `bmesh` 精确改；骨骼则在姿态模式选，草稿给骨骼名。
   - 后端地址 / 覆盖项在折叠的「后端 / 高级」里。

然后回到 DSH：当前会话输入框里出现一行
`Blender 选中：Cube、Camera。活动对象：Cube。模式：OBJECT。用户说"这个/这些"时指它们；对象名在 bpy.data.objects 里可直接用。`

> 发送成功可在面板看到「最近发送：成功（seq N）」；DSH 侧插入成功与否可用
> `curl -sS http://127.0.0.1:39877/host/selection/latest` 的 `last_consume` 核对（`{ok:true, how:"actions"}` = 已进草稿）。

### 10.3 activity 四态

| `state` | 含义 | 触发 |
|---|---|---|
| `idle` | 空闲 | 两个窗口都没有信号 |
| `human` | 人在操作 | 模态操作（`window.modal_operators`：拖拽 / 变换 / 菜单等）**或** 1.5 s 内有人类操作符 / 撤销 / 选区变化 |
| `agent` | AI 在操作 | agent 命令执行中，或最近一次命令结束 ≤1.5 s |
| `both` | 同时 | 两个信号都在 |

- 面板**顶部**直接看活动状态；`agent` / `both` 时显示红色警告「AI 正在操作 Blender」。
  最近人类动作会显示成 `selection` / `undo` / `modal:transform.translate` 之类。
- **暂停 AI 操作**：面板顶部按钮；暂停后 socket 只放行只读查询（`get_*` / `ping` 等），
  `execute_code`、资产下载 / 模型生成 / 导入等写操作返回 `AI_PAUSED`；恢复只能在 Blender 里点「继续 AI 操作」。
- 模型侧查同一状态：`blender_inspect(command="get_activity_state")`（**查询自身不计入 agent**）；
  查原生选中：`blender_inspect(command="get_selection")`。
- 这个判定只在内存里计算、**不上传任何数据**；addon 没有遥测或人工编辑事件缓冲。

### 10.4 排错

| 现象 | 原因 / 处置 |
|---|---|
| 按钮是灰的 | 当前没有选中物体（Blender 里选一个再点） |
| `发送失败：Connection refused` / timeout | 宿主 Gateway / 插件后端没跑（先重启 DSH / 看 39877）；或 Blender 与 DSH 不在同一网络命名空间。可设环境变量 `DSH_BLENDER_BACKEND_URL` 或在场景属性 `dshbb_backend_url` 填可达地址（留空默认 `http://127.0.0.1:39877`） |
| 后端有 `seq`，但 DSH 输入框没字 | ① 升级后**没重启 DSH**（旧客户端半边不认识 `/host/selection`）；② 看 `/host/selection/latest` 的 `last_consume.reason`（草稿锁 / 备用通道非空 / TUI）；③ 当前会话不是你要写入的会话时，切到目标会话再点一次 |
| activity 一直 `agent` | 正常：agent 命令刚结束的 1.5 s 窗口内；等一会儿再查。`get_activity_state` 已排除查询自身 |
| 工具报 `AI_PAUSED` | 面板顶部「暂停 AI 操作」被按下了：让 AI 停手后，在 Blender 面板点「继续 AI 操作」 |
| 找不到环境 / 模型 API 面板 | 在 N 面板底部「环境与角色模型API调用」；父面板与「环境生成 / 模型生成」子面板默认都折叠，点开再配置 |
| 人明明在操作但显示 idle | addon 版本低于 v2.0.0；或操作是"纯视图导航"之外的输入且未触发操作符 / 选区变化（极少见）——把现象连同 `last_human_kind` 报回来 |
| TUI 里收不到 | 草稿桥只在 **Web 客户端**（`conversation.input.dock`）；TUI 的 `sendToChat` 未授权，这是既有边界 |

### 10.5 验收命令（可复跑）

```bash
# 1) addon 版本与命令
blender_inspect(command="get_addon_info")     # 期望 addon_version [2,0,0]，capabilities 含 get_activity_state/get_selection/send_selection_to_dsh
blender_inspect(command="get_activity_state") # 空闲时 state=idle
blender_inspect(command="get_selection")      # names 与视口选中一致

# 2) 后端三条路由（纯内存，不需要 Blender 在跑）
curl -sS -X POST http://127.0.0.1:39877/host/selection -H 'content-type: application/json' \
  -d '{"v":1,"source":"curl","selection":{"count":1,"names":["Cube"],"active":"Cube","mode":"OBJECT"}}'
curl -sS http://127.0.0.1:39877/host/selection/latest

# 3) 离线回归
npx vitest run tests/integration/js/selection-store.test.ts
npx vitest run tests/unit/js/contract/client-bundle.test.ts
npx vitest run tests/integration/js/host-selection.test.ts tests/integration/js/host-jobs.test.ts tests/integration/js/host-scene-items.test.ts      # 判据 S1–S3 自起 fake backend，无需 Blender
```
