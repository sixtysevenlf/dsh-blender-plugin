# 操作教程 —— 从零到顺手

> 面向第一次拿到这个包的人：**装上 → 连通 → 会用 → 会排错**，全程约 40 分钟（熟练后 5 分钟）。
> 当前版本：插件 **v2.6.2**（15 个模型工具）· Blender addon **v1.10 / protocol 11** · 后端 `127.0.0.1:9877` / addon `127.0.0.1:9876`。
> 前置条件（Blender + `DSH Blender Bridge` addon + Node ≥ 20 + DSH；**无头路径不要求 GUI 开着**）见 [README §2](../README.md#2-前置条件4-条缺一不可)。
> 配置项（工作目录 / blender.exe / 端口 / 租约 / worker TTL）见 [配置参考.md](配置参考.md)。

## 0. 心智模型：先理解这 4 件事

1. **三条线并行**
   - **GUI 直连通道**：TCP `127.0.0.1:9876` → addon；毫秒级、实时，但**要求 Blender GUI 开着**，且所有命令串行占用它。
   - **交互式无头会话**：持久 `blender -b` worker（`blender_rt_worker`）；`rt_do` / `rt_see` / `rt_watch` 传 `session`（或 GUI 不可达时自动降级）就走它，`rt_plan` 传 `session="auto"` 时大多数 plan op 也在 worker 里同步执行 —— **不需要 GUI**。
   - **一次性无头进程**：`blender.exe -b`（`blender_rt_headless` / `blender_rt_job`）独立进程；用于重渲染 / 批量几何 / 数据校验，**不占 GUI 通道**，可与上面两条线同时跑。
2. **三种"看"**（都由 `blender_rt_see` 出图，但语义不同；无 GUI 时传 `session` 走 worker 的 Workbench 离屏帧）
   - 视口帧 = **用户正在看的角度**（含视口着色与覆盖物）；
   - 自定义视角 = **你指定的相机**（`from` + `look_at`，不建相机、不动用户视口）；
   - `full=true` = **整个 Blender 窗口**（走 `screenshot_area`，看 UI / 面板 / 其他编辑器）。
3. **内环 vs 外环**：模型回合（几秒）贵，Blender 事件循环（160 tick/s）便宜 →
   **搜索放 Blender 侧（`blender_rt_loop`），决策与验收放模型侧**。详见 [操作教程.md](操作教程.md)。
4. **并发**：写操作受"租约"保护。默认无感；一旦有别的会话持有，你的写操作会拿到 `409 leased`（只读操作不受限）。

### 什么时候用哪个工具

| 你要做的事 | 用哪个 | 为什么 |
|---|---|---|
| 看一眼现在长什么样 | `blender_rt_see` | 50–160 ms，最便宜；**无 GUI 传 `session`** |
| 换个角度看（不想动用户视口） | `blender_rt_see {from, look_at}` | 零场景改动，可重复（md5 稳定）；无 GUI 走 worker 离屏 |
| 改一步就想验证 | `blender_rt_do {see:true}` | 一个原子步 ≈105 ms；**无 GUI 传 `session`**（50–150 ms/步） |
| 判断"动没动 / 对不对" | `blender_rt_watch` | 时间窗连续采样 + 逐帧 hash，一次最多 6 帧；无头可传 `session` |
| 搜索 / 拟合参数（几千次迭代） | `blender_rt_loop` | 内环跑，不花模型回合；无头传 `target:"session"` |
| 多目标 + 约束的测量 | `blender_rt_loop` + `penalize` | 罚项把违规量并入单一 score |
| 收敛后复核 / 复用 | 换一条通路复算 + `blender_rt_loop op=export` | 防"只优化了你写的目标函数" |
| 同一脚本反复跑 / 无 GUI 交互 | `blender_rt_worker` | 持久 `blender -b`；preload 注模块、see 出帧；空闲 15 min 自动回收 |
| plan op 无头跑（判定/验收/导出） | `blender_rt_plan {session:"auto"}` | 自动起 worker + 按 family 注入 preload，同步返回 |
| Cycles 成品渲染 / 大批量几何 / 校验 | `blender_rt_headless` | 独立进程：不占 GUI、不撞 CUDA context、超时可杀 |
| 长活 / 批处理（>100 s） | `blender_rt_job` | 后台作业 + wait/collect，超时不丢结果 |
| 离线多角度批量出图 | `blender_rt_headless {preload:"view"}` | 无头进程里直接用 `K.dsh_view_api` |
| 参考图量尺寸 / 标定 | `img_digest / img_probe / img_measure / img_calib` | 把"看不清"变成数字表，不靠眼睛估 |
| 装配合并 / 穿模 / 修复 / 交付 | `asm_scan / asm_manifest / asm_merge / asm_repair / asm_export / asm_gate` | manifest 驱动 + verdict 三态 + gate 后再导出 |
| 白模 / Seedance 参考包 | `blockout_base / batch / export / refsheet / turntable` | 声明式 parts + 4 视图 PNG/拼图 + MP4 转台 |
| 同机位 QC 一页 verdict | `visualreport_report` | IoU/缺多面积/缺陷 crop + mm 定位 |
| 按参考图反推尺寸 | `shapesolve_solve` | 无头多视轮廓拟合，不渲染、不依赖 timers |
| 缺陷评估（插件抓不抓得住） | `eval_run` | 合成缺陷集 capture_rate + 基线回放 |
| 开工体检 / 回退点 / 强制交付 | `gate_preflight / gate_checkpoint / gate_deliver` | 不过门不导出；drill 进交付流程 |
| 渲染慢要调参 | `blender_rt_perf` 先 status → analyze → apply | 先量后调；预设可 revert |
| 场景对象太多导致每轮同步慢 | `blender_rt_opt` analyze → join | ≈1.4 ms/对象；几何零损失，务必先存回退点 |
| 出错不知卡在哪 | `blender_viewport {op:"doctor"}` | 真跑一次 bpy 往返 + 三级判定 + 修法 |
| 多个会话抢同一个 Blender | `blender_viewport {op:"who"}` → `op:"lease"` | 409 会明确告知持有者与剩余时间 |

## 1. 安装与连通

### 1.1 Blender 侧：装 addon 并 Connect

1. 把 `DSH Blender Bridge` addon 放进 Blender 的 addon 目录（`Edit ▸ Preferences ▸ Add-ons ▸ Install...` 选 zip / 或放到 scripts/addons；模块名 `dsh_blender_bridge`）。
2. 启用它（勾选 checkbox）。
3. 打开一个 **3D 视图**，按 `N` 打开右侧栏 → 找到「DSH Blender Bridge」面板 → 点 **Connect**（默认端口 9876）。
4. 面板里可顺手打开需要的集成（PolyHaven / Hyper3D / Sketchfab / Poly Pizza / Hunyuan3D）；**这些开关是 scene 属性** —— 改完记得存进你的 startup / 工程文件（重启 Blender 会丢未保存的）。

> ⚠️ **addon 迁移**：只支持本仓 `DSH Blender Bridge` **v1.10+ / protocol 11**。旧的 `MCP for Blender` / `blender_mcp` **已不再支持**，请先停用旧 addon 再安装/启用本仓 addon（两个都占 9876，不能同时开）。迁移要点见 [../MIGRATIONS.md](../MIGRATIONS.md)。

> 判断 addon 是否在监听：在终端跑 `curl -sS http://127.0.0.1:9877/doctor`；或直接 `node runtime/_probe_tools.mjs` 看命令面。

### 1.2 构建插件（可选；本仓已提交 `lib/`）

```bash
cd dsh-blender-plugin
DSH_CHECKOUT=/path/to/dsh-harness bash scripts/build.sh   # 只有改了 src/ 才必须重建
# 期望最后三行： Linking build dependencies → Compiling src → lib → Build complete
ls lib/index.js           # 构建产物
```

> `scripts/build.sh` 会自动探测 `$HOME/dsh-harness`、`$HOME/dsh`、`$HOME/.dsh/dsh-harness`；都没有就显式给 `DSH_CHECKOUT`。

### 1.3 装到 DSH（bundle 式）

本包自带 `cordis.patch.yml` 并声明了 `dsh.bundle`，按官方 bundle 方式装配即可（重启后加载）：

```bash
# ① 建 junction（profile 的 node_modules 里）
ln -s /path/to/dsh-blender-plugin ~/.dsh/profiles/<profile>/node_modules/@dsh-external/dsh-blender-plugin
# ② profile 的 package.json：dependencies 加 "link:/path/to/dsh-blender-plugin"，
#    dsh.profile.bundles 加 "@dsh-external/dsh-blender-plugin"
# ③ 预演装配（不启动）：dsh --profile <profile> --dump-config | grep -A3 dsh-blender-plugin
# ④ 重启 DSH
```

不要同时用"运行时注入"与"bundle 装配"：两个 fiber 会重复注册同名工具。

### 1.4 后端自检（三条命令）

```bash
curl -sS http://127.0.0.1:9877/health   # {"ok":true,...}    后端进程活着
curl -sS http://127.0.0.1:9877/doctor   # ⭐ kind=ok 才算"Blender 也连上了"
curl -sS http://127.0.0.1:9877/who      # 租约 + 通道指标 + 当前生效配置
```

**唯一验收判据**：`/doctor` 返回 `kind=ok`（或 `blender_viewport(op="doctor")` 的 `kind=ok`）。其它自检失败只说明那一项功能有问题，**不能替代**这条验收。

`/doctor` 返回里的关键字段：

| 字段 | 含义 |
|---|---|
| `kind` | `ok` / `blender-unreachable` / `main-thread-busy` / `addon-thread-stuck` |
| `summary` `fix` | 一句结论 + 一句修法（直接照着做） |
| `ping_ms` `roundTripMs` | `ping`（不碰 bpy）与 `status`（真跑 bpy）的耗时 |
| `config` | **当前生效配置**：工作目录、blender.exe、端口、配置文件来源 —— 排错先看它 |

### 1.5 插件工具自检

```text
blender_viewport(op="doctor")          # 同 /doctor，但在工具的返回里更可读；kind=ok 是唯一验收判据
blender_rt_plan(op="catalog")          # 应为 34 个 family / 228 个 op（15 个模型工具）

blender_rt_worker(op="start")          # 纯无头时：worker start 后 op="see" 也应回一帧
```

## 2. 十五个工具逐个上手

> 约定：所有工具都要求**后端在跑**（插件自动拉起）；走 GUI 通道的工具还需要 Blender 的 addon 已 Connect。
> `blender_rt_headless` / `blender_rt_job` / `blender_rt_worker`，以及 `rt_do|rt_see|rt_watch|rt_plan` 的 `session` 路径**不需要 GUI**。
> 参数名用工具 schema 里的原名（WSL / Windows 通用）。

### ① `blender_rt_see` —— 看

| 参数 | 说明 |
|---|---|
| `max_size` | 最长边像素，默认 560（420 更快，900 更清晰；上限 1600） |
| `full` + `area` | 整窗截图 / 第 N 个区域（看 UI 时用） |
| `from` `look_at` | 自定义视角：相机位置 / 注视点，`"x,y,z"` 或数组 |
| `lens` `ortho` `ortho_scale` | 焦距 mm（默认 50）/ 正交开关 / 正交尺度（贴长边） |
| `view_size` | `"宽x高"`，如 `"1280x720"`；默认按 `max_size` 出 16:9 |
| `shading` `overlays` | 临时切换着色（WIREFRAME/SOLID/MATERIAL/RENDERED）/ 覆盖物，出图后还原 |
| `view_mode` | `viewport`（默认，零场景改动）/ `render`（临时相机 + Workbench 快渲） |
| `session` / `auto` | `session="s1"` **直接走持久无头 worker**（不探 GUI）；`auto`（默认 true）= GUI 不可用时自动降级到无头 see |

```text
blender_rt_see(max_size=560)
blender_rt_see(from="9,-9,6", look_at="0,0,1", lens=35)
blender_rt_see(from="0,0,12", look_at="0,0,1", ortho=True, ortho_scale=12, shading="MATERIAL", view_size="1024x1024")
blender_rt_see(full=True, area=0)     # 整个 Blender 窗口
```

注意：`viewport` 模式渲染的是"视口观感"，**不是** Cycles 成品图；要成品图用 `blender_rt_headless`。
无 GUI 时：`blender_rt_see(session="s1", from=…, look_at=…)` 走 worker 的 Workbench 离屏帧（自定义视角参数同样适用；`full` 整窗截图必须 GUI）。

### ② `blender_rt_do` —— 做（+ 顺手看）

```text
blender_rt_do(code="K.n = getattr(K, 'n', 0) + 1
bpy.data.objects['Cube'].rotation_euler.z += 0.4", see=True)

# 无 GUI：显式 session（同一名字复用同一 blender -b 进程，K 跨调用保留）
blender_rt_do(session="s1", preload="audit,assembly", code="…", see=True)
```

- 代码在 **Blender 主线程**执行，预置 `bpy / math / mathutils / Vector`；
- **持久内核 `K`**：`execute_code` 每次是全新命名空间，跨调用状态必须挂 `K`；
- `see=true`（默认）会顺带回一帧，GUI 整步 ≈105 ms；
- **P0 无头交互**：GUI 不在线或传 `session` 时，自动降级到持久无头 worker（`exec` + Workbench `see`，同一热路径、不是 job/异步）；第一次冷启动 ~2 s，之后每步 **50–150 ms**；`session` 名固定即复用同一 Blender 会话，`auto=false` 可禁用降级。

### ③ `blender_rt_watch` —— 连续观察

```text
blender_rt_watch(code="bpy.app.timers.register(tick)", seconds=2.5, fps=4, max_size=420)
```

返回 ≤6 帧 + **逐帧 hash**：hash 全相同 = 画面没变（动画没跑起来 / 参数没生效）。`fps` 别开太高（每帧占主线程 ~55–100 ms，会卡人）。
**无头**：传 `session="s1"` 直接走 worker 的 `_watch`（逐帧 Workbench 离屏 + hash）；不传 `session` 时 GUI 全帧失败也会自动降级。

### ④ `blender_rt_loop` —— 内环搜索（最核心的一个）

```text
blender_rt_loop(op="start", spec={
  "setup":  "import random\nK.ob = bpy.data.objects['Cube']",
  "step":   "px = ns['i'] % 7; ns['params'] = {'sx': 1 + px * 0.1}",
  "measure":"ns['score'] = abs(bpy.data.objects['Cube'].dimensions.x - 2.0)",
  "iterations": 3000, "budget_ms": 20000, "interval": 0, "measure_every": 5,
  "minimize": True, "top_k": 20, "group_key": None
})
blender_rt_loop(op="status", history=12)
blender_rt_loop(op="board", limit=10)
blender_rt_loop(op="export", path="/tmp/best_fit.py", top=3)
blender_rt_loop(op="stop")            # 急停
```

- `setup/step/measure` 源码共享命名空间 `ns`；`measure` 必须写 `ns["score"]`，可写 `ns["params"] / ns["metrics"] / ns["violations"]`；
- 预置：`bpy / K / math / random / numpy(np) / i / frac / penalize / anneal / record`；
- **必须给 `iterations` 或 `budget_ms`**（安全阀）；`interval=0` 最快；`redraw_every=0` 不重绘最快；
- 多目标：`ns['score'] = penalize(errors_dict, violations, weights, lam)`；步长退火：`anneal(v0, v1, ns['frac'])`；
- `top_k + group_key` = 候选表（跨对象批量时按对象分组各留最优）；
- **无头**：`target="session"`（可选 `session` 名）走 worker 的 `dsh_loop_sync` 阻塞内环，不依赖 GUI timers；工具会自动起 `preload="runner"` 的 worker（实测 20 次迭代 56 ms）；
- `op=help` 打印完整契约。

### ⑤ `blender_rt_cmd` —— 透传 addon 任意命令

```text
blender_rt_cmd(name="ping")
blender_rt_cmd(name="get_object_info", params={"name": "Cube"})
blender_rt_cmd(name="get_scene_info")
```

⚠️ **按 addon 真签名传参**：`get_scene_info()` 无参、`get_object_info(name)` 用 `name`。直连没有 schema 层替你改名，传错就是 `unexpected keyword argument`。

### ⑥ `blender_rt_commands` —— 命令面与集成状态

返回：可用命令列表（常驻 + 受集成开关门控的）、5 个集成开关状态与消息。**调 `blender_rt_cmd` 之前先问它。**

### ⑦ `blender_rt_perf` —— 渲染性能

```text
blender_rt_perf(op="status")     # 现状（引擎/设备/采样/降噪/persistent/对象数）
blender_rt_perf(op="analyze")    # 差分实测：每轮 CPU 侧同步 vs 每采样 GPU 成本（占主线程十几秒）
blender_rt_perf(op="apply")      # 预设：persistent_data + 降噪器自动判定 + auto_tile off + 采样上限
blender_rt_perf(op="revert")     # 还原 apply 之前（自动存快照）
```

经验值（作者机器，2318 对象）：**每轮 CPU 同步 ≈4.2 s，persistent_data 让重复渲染 14.6 s → 0.79 s**；砍采样对 CPU 侧几乎无帮助。

### ⑧ `blender_rt_opt` —— 对象精简

```text
blender_rt_opt(op="analyze")
blender_rt_opt(op="join", args={dry_run=True})                      # 先空跑看报告
blender_rt_opt(op="join", args={dry_run=False, save_before="/tmp/pre_join.blend"})
```

合并规则（安全）：同集合 / 同材质 / 同父级 / 无修改器 / 无动画 / 无形态键 / 无自定义属性 / 无实例 / 非库链接 → **几何零损失**（面数顶点数不变）。务必先给 `save_before`。

### ⑨ `blender_rt_headless` —— 无头进程

| 参数 | 说明 |
|---|---|
| `script` / `script_file` | Python 源码 / 直接跑一个 .py 文件（后者自动注入 `__file__` + sys.path，多文件工程更省事） |
| `file` | 打开的 .blend（WSL 或 Windows 路径都行，自动映射） |
| `outdir` / `out_json` | 产物目录 / 结构化结果落盘路径（都接受 WSL 路径） |
| `preload` | 预载 runtime 模块（逗号分隔）→ `K.dsh_*_api`，如 `"audit,qc,qc_render"`、`"assembly,audit,contract,clearance,gate,mesh_fix,geo,txn"`、`"imgtools"` |
| `engine` | `eevee`（默认，带光追前导）/ `cycles` / `keep` / `none`（纯 numpy/图像任务省 1–1.5 s） |
| `shots` | 多视角一体化出图（见 §7.2），可配 `attach_images` 附图 |
| `attach_images` | `true` = 最多附 3 张 `shots` 图；`"sheet"` = 只附拼图 |
| `as_job` / `wait_s` | 立刻后台化 / 后台化后最多再等几秒；预期 >100 s 的活直接用 |
| `timeout_ms` | 默认 180000，上限 1800000（超时 SIGKILL） |
| `factory_startup` | 默认 true（干净、快、不与运行中的 addon 抢 9876）；要用用户偏好/启动文件设 false |
| `use_user_config` | 透传 `BLENDER_USER_CONFIG/SCRIPTS`（配合 `factory_startup=false`） |
| `bootstrap` | 默认 true（注入 `K`）；false 时脚本原样跑 |
| `env` / `args` / `workdir` | 子进程环境变量 / 额外命令行参数（引号成对不拆：`--flag "a b"`）/ 脚本内 chdir + sys.path 首位 |
| `expect` | 断言（如 `{"minNewObjects":1}`）：空跑即失败 |
| `include_noise` | 产物清单是否含 `__pycache__` / `*.blend1`（默认过滤） |

约定：脚本里 `print("HEADLESS {json}")` → 工具把最后一行解析成 `result`。**无头不需要 GUI，也不占 9876。**

> **长活边界**：单次调用上限 = `timeout_ms`（默认 180 s、上限 30 min）。
> **超过 ~100 s 的活直接 `as_job:true`**：等待窗口（默认 100 s）到点会回 `{kind:"promoted", jobId}` —— 子进程照跑，用 `blender_rt_job(op="wait"/"collect")` 收结果，**超时 ≠ 失败**。批量/整晚任务用 `blender_rt_job`。

```text
blender_rt_headless(file="D:\\work\\scene.blend", outdir="D:\\work\\out", timeout_ms=600000,
  preload="view",
  script="import json,bpy;bpy.ops.render.render(write_still=True)" +
         "\nprint('HEADLESS ' + json.dumps({'objs': len(bpy.data.objects)}))")
```

### ⑩ `blender_rt_job` —— 作业层（长活/批量）

```text
blender_rt_job(op="start", script_file="/home/me/proj/tools/build.py", args="--part hull",
               env={"STAGE": "qc"}, outdir="/home/me/proj/out", timeout_ms=1200000)
blender_rt_job(op="status", id="run-…")            # stage / idleMs / pidAlive / lines
blender_rt_job(op="wait",   id="run-…", timeout_ms=600000)   # 阻塞到完成或超时，返回结构化回执
blender_rt_job(op="collect", id="run-…")          # 收集最终结果（stdout 尾 + resultJson + 产物）
blender_rt_job(op="kill",   id="run-…")           # 幂等：已结束/不存在也回 ok
blender_rt_job(op="list")                          # 全部作业
```

- `start` 与 `blender_rt_headless` **同形**参数（`script_file/args/env/factory_startup/bootstrap/workdir/outdir/include_noise/engine/preload`）；
- **`run-…` 与 `job-…` 同一 id 空间**：`status / wait / collect / kill` 都收两种前缀；
- 作业不占客户端连接、不会被工具超时掐断；后端重启后从磁盘台账恢复状态（stale running 会收敛成 `stale`）；
- 回执与 headless 同构（单行 JSON 信封 + 人读摘要），脚本里的 `dsh_stage("building")` 心跳会进 `status.stage`。

### ⑪ `blender_rt_plan` —— 判定 / 验收 / 导出 / 造型的唯一入口

> 当前 **34 个 family / 228 个 op**。不确定用哪个先 `op="catalog"`；单族 `args={family:"audit"}`；算子细节 `<family>_help`。

#### 多视角渲染 harness —— 一条命令出 N 张 + jsonl + 预算判定

```text
blender_rt_plan(op="qc_render_views", args={
  views: ["iso","front","right"],        # 具名视角 / "az=35,el=20" / {name, from, look_at, lens, ortho}
  res: [512,512], samples: 64,           # 采样同时写 EEVEE taa_render_samples 与 Cycles samples
  budget_s: 120,                         # 别名 thr；累计渲染超了立即停，已出的图保留
  outdir: "D:/DSH/blender/out/qc_render_p21",
  ref_path: "D:/work/ref_front.png", ref_box: [9,38,444,545]   # 可选：逐张走 qc_compare（默认固定对齐）
})
```

- **自动取景**：合并所有可见 mesh 的 AABB（`targets:[名字]` 可限定）→ 逐角解算相机距离 + `margin`（默认 1.12）；
  给了 `from`/`look_at` 就按显式机位，不再自动取景。
- **固定三点光**：SUN key 3.2 / fill 1.0 / rim 2.4，角度固定且相对相机方位角（+35°/45°、-50°/8°、+165°/30°）；
  **只在本进程内临时建**，出图后删除并把 scene 渲染设置全部还原（`lights_mode:"only"` 可临时屏蔽场景里的灯，也会还原）。
- **产出**：`<outdir>/<tag>_<view>.png` + `<outdir>/render_views.jsonl`，每行 = 一张图
  （`{view, ms, bytes, hash, path, res, engine, samples, camera, frame{bbox, margin_px, coverage, pred_bbox_px, proj_err_px}}`）。
- **预算**：`within_budget=false` + `stopped_early` + `skipped_views`；已完成的行/图**不删**。
- **长活**：`args.asJob=true` 转作业层（无头进程天然隔离场景），用 `blender_rt_job(op="collect", id=...)` 取结果；
  也可以在无头里直接跑：`blender_rt_headless(file=..., preload="qc,qc_render", script="print('HEADLESS ' + K.dsh_qc_render_api['render_views']({...}))")`。
- **不改场景**：GUI 进程里默认拒绝打开别的 `.blend`（要开就传 `allow_open_file=true`）；临时相机/灯用完即删。
- 自检：`blender_rt_plan(op="qc_render_help")` 出参数速查；`K.dsh_qc_render_api["selftest"]()` 跑取景/投影自检。

实测（350 可见 mesh / 512×512 / 64 采样 / EEVEE+RT）：3 视角 2124 / 798 / 565 ms、共 3487 ms、jsonl 3 行、
512 画幅四边余量 36 px（预测 bbox 与实出 alpha bbox 差 ≤2 px）；预算 1.0 s 的对照跑只出 1 张即停且图保留。

### ⑫ `blender_rt_worker` —— 交互式无头会话 / 热 worker

常驻的 `blender -b` 进程：**反复迭代 / 无 GUI 交互**时省掉每次冷启动与重复导入/重建。

```text
blender_rt_worker(op="start", name="s1", preload="audit,assembly,imgtools")  # preload 注入 K.dsh_*_api；warmup 默认 true
blender_rt_worker(op="exec", name="s1", code="K.i = getattr(K, 'i', 0) + 1\nprint('HEADLESS {"i": K.i}')")
blender_rt_worker(op="see",  name="s1", from="7,-7,5", look_at="0,0,1", view_size="560x315")  # Workbench 离屏帧
blender_rt_worker(op="reset", name="s1")            # 清场景（换任务时）
blender_rt_worker(op="status", name="s1")           # uptime / calls / objects / idleMs / 已加载的 K.*_api
blender_rt_worker(op="list")                        # 所有热会话
blender_rt_worker(op="stop", name="s1")             # 干净退出（restart = stop+start 换干净进程）
```

语义：

- `preload`（start 时）：把 `audit/qc/qc_render/runner/assembly/blockout/imgtools/...` 注入 `K.dsh_*_api`；**preload 失败 `start` 直接报错**（不静默少模块）。`warmup=true`（默认）预热渲染器；
- **空闲回收**：worker 池默认 **15 min** 无请求自动回收（`DSH_WORKER_TTL_MS` 可调，0=关闭；见 [配置参考.md](配置参考.md)）；`status` 与回执带 `idleMs`；
- 限制：**串行**（长代码会占住 worker）；**无窗口**（依赖 GUI 上下文的 `bpy.ops` 可能失败，用 `temp_override` 或改走 GUI 通道）；与 GUI 通道互不干扰（独立进程，不占 9876/9877）；
- `rt_do` / `rt_see` / `rt_watch` 的 `session`、`rt_plan` 的 `session="auto"`、`rt_loop target="session"` 都复用这套 worker（同一会话名 = 同一 Blender 进程 + 持久 `K`）。

配套语义：

- `blender_rt_headless` 默认注入 **GPU 前导**（`gpu:"auto"`）并回传 `gpu` 字段 —— 无头进程读不到用户偏好，Cycles 会静默回落 CPU（实测 15.4×）；
- 失败时给**结构化**信息：`logs`（全量日志路径）、`lastException`、`traceback`、`reason`；
- `outdir` 产物默认**过滤** `__pycache__ / *.pyc / *.blend1|2 / tmp*`；
- **客户端超时 ≠ 任务失败**：服务端子进程继续跑完、产物仍落盘（>100 s 请用 `as_job` / 作业层 / 热会话）；
- `/headless` `/worker` `/txn` `/preset` 每 15 s 一行流式心跳，客户端按行取末条 —— 长调用不会显示 `exit=undefined`，回执完整。

### ⑬ `blender_rt_txn` —— 事务 / 回滚

```text
blender_rt_txn(op="snapshot", label="before_join")   # 文件级：存 <out_dir>/snapshots/before_join.blend
blender_rt_txn(op="mark", label="iter7", objects="Cube,Wheel_L")   # 对象级：记 transform/材质/可见性
… 改动 …
blender_rt_txn(op="revert", label="iter7")          # 就地回滚（拓扑变过的对象会跳过并报告）
blender_rt_txn(op="list")                              # 快照 + mark 清单
```

边界：对象级**不含拓扑/UV/顶点级改动**（Boolean/合并/删面之后回不去）→ 用文件级 `snapshot/restore`（会丢掉当前未保存状态，但 `restore` 默认先替你备份一份）。

`restore(label, into="auto", backup=True)` 的 filepath 口径：默认 `into="auto"` 载入快照后**把会话放回快照的出处文件**（保存落回自己的工程，不再写进快照目录）；`into="snapshot"` 非破坏（只看一眼，不写原文件）；`into="original"` 要求必须能回写，否则 `ok:false`。`backup=True` 先留 `_pre_restore_*` 快照，会话脏且要覆盖原文件时另留磁盘副本 `_pre_restore_file_*`。

另外：异常会回传 partial stdout/traceback；脚本内可用 `K.win_path / K.wsl_path / K.blend_path / K.out_dir`；`rt_do(file=...)` 可直接跑工作区脚本；**QC** 用 `blender_rt_plan(op="qc_compare")`（IoU/Dice/缺面积/多面积/边界距离 + 对照图）。

### ⑮ `blender_rt_preset` —— 配方库

把「参数组合」变成可保存、可套用、可分发的资产（与领域无关：材质 / 对象 / 场景 / 自定义 JSON）。

```text
blender_rt_preset(op="save", name="硬表面金属", kind="material", tags="metal,hard", \
                  data='{"inputs.Metallic": 1.0, "inputs.Roughness": 0.25}')
blender_rt_preset(op="list")                                  # 清单（可按 kind/tag 过滤）
blender_rt_preset(op="apply", name="硬表面金属", targets="MAT:钢_外壳,MAT:螺栓")   # 实际写入
blender_rt_preset(op="apply", name="硬表面金属")              # 不给 targets → 只预览（dry_run）
blender_rt_preset(op="export")                                # 单个 bundle 便于分享给别的机器
blender_rt_preset(op="import", path="D:/DSH/blender/tmp/presets/presets_bundle_x.json")
```

要点：data 用**点路径**；`targets` 支持 `MAT:名` / `OBJ:名` / `SCENE`；回执给 `applied / skipped / errors`（路径不存在只报错不静默）。
实测：存 `{"render.resolution_x":640}` → `apply targets="SCENE"` → 场景分辨率 720 → **640** 真实生效；dry_run 预览不写盘。

> 工具分工速记：blender_rt_headless 的 file 是 .blend 工程；执行 .py 脚本请用 blender_rt_do(file="//x.py")（内部 K.run，会回收 stdout）或 headless(script=...)。
> `qc_compare` 判据：`iou` 是**固定对齐**（诚实值），搜索对齐另给 `iou_search`；**尺度漂移 >5%** 与**搜索吸收 >0.05** 都会告警；`ref_box` 可省略（默认整图）；auto 掩膜在前景占比 >80%/<2% 时自动回落阈值口径并写明原因。

## 3. 七个实战配方

### 配方 1：改一步看一眼（最常用）

```text
blender_rt_do(code="ob = bpy.data.objects['Truck']; ob.location.z += 0.05", see=True)
```
节奏建议：连续做 10–30 步再停下来看整体；每步都取帧会把主线程占满（每帧 55–100 ms）。

### 配方 2：多角度验收（不打搅用户）

```text
blender_rt_see(from="9,-9,6", look_at="0,0,1", view_size="900x506")     # 右前上
blender_rt_see(from="-9,-9,5", look_at="0,0,1")                          # 左前上
blender_rt_see(from="0,0,14", look_at="0,0,1", ortho=True, ortho_scale=14)  # 正交顶视
```
同一组参数**重复出图 md5 相同**（作者机器实测 hash `3a7bee2a`）→ 可以当"验收指纹"：模型说改完了，重出同样角度，hash 不变就是真没变。

### 配方 3：内环拟合（让搜索跑在 Blender 侧）

目标：把 6 个尺寸参数调到目标包围盒（示意）。

```text
blender_rt_loop(op="start", spec={
  "setup": "TARGET=(3.2,1.4,1.1)\nK.target=TARGET",
  "step": "import random\nns['params']={'w':round(random.uniform(2.6,3.8),3),'h':round(random.uniform(0.9,1.9),3)}",
  "measure": "bpy.data.objects['Cube'].dimensions=ns['params']['w'],ns['params']['h'],1.0"
             "\nerr=[abs(bpy.data.objects['Cube'].dimensions.x-K.target[0]),abs(bpy.data.objects['Cube'].dimensions.y-K.target[1])]"
             "\nns['metrics']={'ex':err[0],'ey':err[1]}"
             "\nns['violations']={'ratio':max(0.0, 1.6-bpy.data.objects['Cube'].dimensions.x/max(1e-6,bpy.data.objects['Cube'].dimensions.y))}"
             "\nns['score']=penalize({'ex':err[0],'ey':err[1]},{'ratio':ns['violations']['ratio']},lam=5.0)",
  "iterations": 5000, "budget_ms": 30000, "measure_every": 1, "top_k": 20, "interval": 0
})
blender_rt_loop(op="status")   # 看 best / tps / history
blender_rt_loop(op="board")    # 候选表
blender_rt_loop(op="export", path="/tmp/fit_best.py")   # 落成可复用脚本
```

**更省事的路（声明式）**：同一件事也能一次调用交给 `blender_rt_plan(op="shape_search", …)` —— `objective`（`silhouette_iou` / `profile_err` / `aabb_err`）+ `params` 区间 + `apply`（每轮把 `ns["params"]` 落到场景的代码，改完记得 `view_layer.update()`）。它自动选 grid / random、托管 start → 轮询 → board → export，并把场景落到 best（内环自己会停在"最后一次迭代"）；先 `dry_run=true` 可只校验并回 spec（不启动内环、不需要 Blender 连着）。要 `penalize` / `anneal` / 多目标 / `group_key` 分批，仍回到上面手写 spec。**它也能无头跑**：`blender_rt_plan(..., session="auto")` 会走 worker 的同步内环（`dsh_loop_sync`，不依赖 GUI timers）；手写 `rt_loop` spec 时则传 `target="session"`。

**收敛后必须换一条通路复核**（例如用 `blender_rt_do` 重新量一遍包围盒/体积/渲染），因为内环只优化你写的 `score`。

## 3.5 P0–P2 新链路速查（v2.6.0）

> 一句话：**装配是否成形**、**改了多少**、**判定会不会过期**、**参考图能不能量**、**白模/交付能不能一键跑** —— 现在都有判据与入口。

### 3.5.0 边界与验收（先读）

- **验收唯一判据**：`/doctor`（或 `blender_viewport(op="doctor")`）返回 `kind=ok`；其它自检只定位单项功能。
- **明确不覆盖 / 默认未装依赖**（不要当已支持用）：
  - **人脸/landmark 检测**：不自带人脸检测 —— `face_*` 要你提供 landmarks（自己标或外部 MediaPipe/EMOCA 出）；本机无 cv2/MediaPipe；
  - **OCR**：不支持；
  - **DXF**：不支持（导入/导出都没有）；
  - **外部第二通路**：`ext.gltf_validate` / `ext.ext_mesh_check` 依赖 `runtime/ext/` 下本地安装的 glTF-Validator / Open3D（默认部署未装，提示里会给安装命令；未装时明确 `ok:false`）；manifold3d 也未安装。
- 所有"新能力"都遵守三态纪律：`degraded`（证据不足/降级）**不等于通过**；`unresolved` 不猜。

### 3.5.1 交互式无头（P0 备用；默认 GUI 优先）

```text
blender_rt_worker(op="start", name="s1", preload="audit,assembly,imgtools", warmup=True)
blender_rt_do(session="s1", code="…", see=True)          # exec + Workbench 离屏帧，50–150 ms/步
blender_rt_see(session="s1", from="7,-7,5", look_at="0,0,1")
blender_rt_plan(op="asm_scan", session="auto", args={…}) # 自动起 worker + preload，同步返回
blender_rt_watch(session="s1", code="…", seconds=2)      # 逐帧 hash，≤6 帧
blender_rt_loop(op="start", target="session", spec={…})  # 同步内环，不依赖 GUI timers
```

- 同一 `session` 名 = 同一 `blender -b` 进程 + 持久 `K`；**worker 空闲 15 min 自动回收**（`DSH_WORKER_TTL_MS`，0=关闭），`status` 带 `idleMs`；
- 实测（作者机器）：worker `start` 2.24 s（含首帧初始化 ≈1.1 s）→ `exec` 0–2 ms、`see` 53–85 ms（320×180）；`rt_plan session="auto"` 首次冷启动 ~2 s、之后同步复用；无头 watch 3 帧动画 distinct=3/58 ms；
- GUI 通道**只**在"看用户视口/整窗截图（`full`）/ 吃 GUI 上下文的 `rt_cmd`、`gui_*`、用户手上活场景"时才必需。

### 3.5.2 参考图量具（img_digest / img_probe / img_measure / img_calib）

协议：**看图必须产出数字**（写进 spec.py），否则算白看；每次 ≤2 张图且带明确问题。

```text
blender_rt_plan(op="img_digest", args={path:"D:/ref/front.png", known_len:{mm:2000, px:320}})
  # → 轮廓/bbox/对称/直线/特征/比例尺/可读性 + 原生裁剪图册 + 标注总图 + verdict（ready_for_spec / needs_scale / needs_views / unreadable / degraded）
blender_rt_plan(op="img_probe",  args={image_id:"…", op:"scan_y", y_px:420})        # 亚像素边缘/宽度/圆孔/距离/灰度剖面
blender_rt_plan(op="img_measure",args={image_id:"…", px_per_mm:0.16, targets:[{key:"width", feature:"bbox_w", expect_mm:2000, tol_pct:2}]})
blender_rt_plan(op="img_calib",  args={views:[…], shared:[{key:"width", views:{"front":640,"side":638}}]})   # 多视逐视标定 + 跨视一致性
```

- 没有 `known_len` ⇒ 所有 mm 字段为 `null`（**绝不编**）；px 是 loaded 尺度，回执给 `native_px / loaded_px` 换算；
- `img_digest` 一次给"可确认数字表 + 原生裁剪图册 + 可读性 + 下一步"；`img_probe/img_measure` 按需量测；`img_calib` 输出每视 `px_per_mm` 与跨视偏差；
- 判"像不像"用 `img_diff` 的 IoU（L2 证据），不靠肉眼估。

### 3.5.3 装配（asm_scan / manifest / merge / repair / export / gate）

```text
blender_rt_plan(op="asm_manifest", args={action:"init", path:"D:/proj/assembly.json", assembly:"Aurora"})
blender_rt_plan(op="asm_manifest", args={action:"add_part", path:…, part:{id:"P1", file:"…/part_a.blend", objects:["GEO_A"]}})
blender_rt_plan(op="asm_manifest", args={action:"seal", path:…})
blender_rt_plan(op="asm_scan",     args={manifest:"D:/proj/assembly.json"})     # clash/contained/float/unresolved 全对全
blender_rt_plan(op="asm_merge",    args={manifest:…, dry_run:true})              # 先看 append 计划
blender_rt_plan(op="asm_merge",    args={manifest:…, out_blend:"D:/proj/merged.blend", dry_run:false})
blender_rt_plan(op="asm_repair",   args={manifest:…, dry_run:true, policy:"safe"})   # 规划；dry_run=false 才动手（先 snapshot，复扫）
blender_rt_plan(op="asm_gate",     args={manifest:…})                            # export_allowed 仅 verdict=pass
blender_rt_plan(op="asm_export",   args={manifest:…, out_dir:"D:/Blender/proj", name:"proj", merge:true})
```

- **asm_repair policy**：默认档（safe 行为）自动只做 **translate / snap**；**显式 `policy="safe"` 硬禁布尔/scale**；`policy="manual"` 只规划不执行（`dry_run=false` 也只回只读计划）；`policy="aggressive"` 保留布尔路径（仍需 `allow_boolean=true`，布尔改拓扑且必须有文件级 snapshot）。`plan[].risk` / `blocked[].blocked_reason` 逐条可读。⚠ 兼容旧调用：不传 policy 时 `allow_boolean=true` 仍视为显式授权。
- **asm_export**：`merge=true` 先 `asm_merge`（gate+snapshot，不过门不导出）；GLB/FBX/OBJ 官方导出器（自动 enable `io_scene_gltf2`/`io_scene_fbx`）；`dry_run=true` 只回计划不写盘；`manifest_md5` + 逐文件 md5 + append-only ledger；**全部格式失败 `ok:false`**。
- **判据**：`hidden_ok` = 声明内隐藏交叠（不过报）；`clash` = 真穿模；`contained` = 完全包含（旧全对全漏判的补丁）；`unresolved` = 证据不足；`asm_gate` 用 manifest 连接图判浮空。

### 3.5.9 仍有效的既有能力（速查）

> 评估表：`docs/Procedura-融合分析.md`；历史版本说明见 `CHANGELOG.md`（仅作历史，操作以本文为准）。

#### 3.5.9.1 网格体检与装配门（`blender_rt_plan`，op 前缀 `audit_`）

```python
blender_rt_plan(op="audit_scene")                       # 全场景：哪几个对象最脏（只读）
blender_rt_plan(op="audit_connectivity")                # 连通分量：这堆对象连成几块？谁跟谁不挨着？（只读）
blender_rt_plan(op="audit_connectivity", args={"micro_gap_mm": 2.0})   # 口径：带设计间隙的装配件按工艺给
blender_rt_plan(op="audit_gate")                        # 出厂门：连通 + 包络 + 三态（未确认 → degraded，不给通过）
blender_rt_plan(op="audit_drift", args={"a": "objA", "b": "objB"})     # 形状漂移（对称 Chamfer，BVHTree 点到曲面）
blender_rt_plan(op="audit_measure", args={"scope": "Cockpit", "k": 4}) # 测量包：bbox + 逐轴间隙/重叠 mm/% + 邻居
blender_rt_plan(op="audit_snap_floaters", args={"scope": "Cockpit"})   # 浮块贴到最近邻（默认 dry_run，只报告）
blender_rt_plan(op="montage", args={"paths": [], "cols": 4})           # 拼图（证据分级 L2）
```

判据（`audit_help` 里也有）：

- **可见浮块** = 分量最长 bbox 边 ≥ 全模型最长边 **1%**（严重度只看它，不看体积）。
- **相接口径** `micro_gap_mm`：默认 **0.3 mm**（单一实体 / 3D 打印口径）；带设计间隙的装配件按工艺给（1–2 mm 常见）。
  口径与间隙分布随返回回传（`gate_caliber` / `gap_histogram` / `floater_gap_range_mm`）。
- 判据**不再是**「最大分量=主体、其余都是浮块」（两个等大零件会随机挑一个当浮体），而是**每个分量都问「你有没有跟别的分量相接」**。
- bbox 间隙在多对象装配里恒为 0（普遍重叠）→ micro 判定要过**网格级复核**（BVH + 面上采样）；
  **默认不设面数上限（全跑，验收不随规模退化）**；只有显式设 `DSH_*` env 或 `max_tris` 参数才启用上限 —— 那时超限会跳过复核 → `attached=null` → **门降级（ok=null）**，未确认绝不当成已通过。
- `audit_drift` 量的是**形状漂移**：归一化会消除平移与整体缩放，所以位移不看它 → 看 `bbox_delta.moved_mm`。
  0.05 ≈ 最长边 2.5%；同网格读 0。
- 实测参考（COCKPIT_DELIVERY，14 对象 / 97,438 面）：0.3 mm 口径 → 178 浮块（与最近邻相距 0.33–1.14 mm）+ 970 相接；2.0 mm → 63 浮块。

## 4. 安全与并发（务必读一遍）

1. **写操作前先留回退点**：`bpy.ops.wm.save_as_mainfile(filepath="...")` 或 `opt join` 的 `save_before`。
2. **内环必须有安全阀**：`iterations` / `budget_ms`；跑飞了用 `blender_rt_loop(op="stop")` 急停（它会在下一个 tick 退出）。
3. **不要连续调 `render.render()`**（GUI 会话里容易撞 CUDA context，且全程占主线程）→ 改 `blender_rt_headless`。
4. **GPU / 驱动相关操作必须在主线程**：addon socket 线程里调 `cycles.preferences.get_devices()` 会直接崩 Blender（作者机器崩过一次）；需要排线程就用 `bpy.app.timers`。
5. **租约语义**：写路由 = `/act /cmd /loop /perf(写 op) /opt(join) /headless`；只读 op 豁免。
   - 单 agent：插件自动带 `holder`，无感；
   - 多 agent：收到 `409 leased {holder, expiresInMs}` → 要么等，要么 `blender_viewport {op:"lease", force:true}` 接管；
   - `/who` 看当前持有者与剩余时间。
6. **`execute_code` 是万能通道**（有意保留）：它等于在 Blender 进程里执行任意 Python。
   - 通道只监听 `127.0.0.1`（别改成 `0.0.0.0` 暴露到公网）；
   - 别把 API key / 私有数据写进会被日志记录的字符串；
   - 只在可信的 Blender 工程与可信的模型侧使用。

## 5. 排错速查

### 5.1 三级诊断（`/doctor` 的 `kind`）

| kind | 含义 | 处置 |
|---|---|---|
| `ok` | TCP + ping + bpy 往返都通 | 无需处理 |
| `blender-unreachable` | `127.0.0.1:9876` 没人监听 | **一键：`blender_viewport op=launch`（§8）**；人工：启动 Blender → N 面板 →「DSH Blender Bridge」→ Connect |
| 写操作 409 `leased` 但对方会话其实已经关了 | `blender_viewport op=who` 看 `holderAlive` | **会自动回收死会话的租约**（`holderAlive:false`）；`null` = 判不了存活 → 用 `op=lease force=true` |
| `main-thread-busy` | addon 活着（ping 通），但 bpy 命令超时 | Blender 在渲染 / 模态操作 / 跑重活 → 等它空下来；长渲染改 `blender_rt_headless` |
| `addon-thread-stuck` | 端口通但 ping 也不回 | 上一条长命令还在 addon 线程里；不要连发，等结束；必要时重启 Blender |

### 5.2 高频坑（按代价排序）

| 坑 | 现象 | 做法 |
|---|---|---|
| 帧 / 脚本路径两端不互通 | 出图报"文件不存在" / 工具读不到 | 用 `doctor` 的 `config.workDir` 核对；改成两端都能读写的目录 |
| 往 UNC（`\\\\wsl.localhost\\...`）写文件 | "返回成功但没有文件" | 写盘一律用 Windows 盘符路径（`D:\...`） |
| `execute_code` 无状态 | 上次的变量读不到 | 跨调用状态挂持久内核 `K` |
| addon 面板重启后没 Connect | 命令全超时 | 重新 Connect；把需要的开关存进 startup |
| 参数名按 MCP 文档写 | `unexpected keyword argument` | 按 addon 真签名（`get_object_info(name)`） |
| 后端起不来 / 端口被占 | 工具报"后端不可用" | `blender_viewport op=restart`；或改 `httpPort` |
| 找不到 blender.exe | `blender_rt_headless` 报 `blender-exe-missing` | 三种配置方式见 [配置参考.md](配置参考.md) §4 |
| `rt_plan ... session="auto"` 无头执行失败 | 报"无头执行失败" | 该 op 没有无头映射（先 `op="catalog"` 查）或 worker 起不来；先 `blender_rt_worker(op="start", name="…", preload="…")` 手动验证，或 `blender_viewport(op="doctor")` |
| GLB / FBX 导出失败 | `asm_export` / `deliver_export` 某格式 `ok:false` | 看 `exports[].error`；GLB 需 `io_scene_gltf2`、FBX 需 `io_scene_fbx`（工具会自动 enable）；OBJ 用 `wm.obj_export` |
| worker 越开越多 / 内存涨 | `blender_rt_worker op=list` 见多个热会话 | 默认 15 min 空闲自动回收（`DSH_WORKER_TTL_MS`，0=关闭）；可显式 `op=stop` |
| `asm_export` 导出被拒 / 不写盘 | `ok:false` + merge/gate 回执 | `merge=true` 时先过 `asm_merge` 内部 gate（不过门不导出）；看 `merge.gate` 与 `blocked/error` |

## 7. 路径选择：GUI 优先，无头备用（当前）

> 路线决定与证据：[`docs/headless优先-路线决定.md`](headless优先-路线决定.md)。
> 一句话：**默认先开 GUI Blender + Connect**；只有无 GUI / 批处理 / 长活 / 不需要人看画面时才走无头；无头也能 rt_see，不会失明。

### 7.1 三十秒判定

| 你的情况 | 默认走 | 第一句怎么写 |
|---|---|---|
| 改一步看一眼 / 用户 live 场景 / 需要人看画面判断 | **GUI（默认）** | `blender_rt_do(code=…, see=True)` / `rt_see` |
| 看用户视口 / 整窗截图 / 依赖屏幕/模态的 `bpy.ops` | **GUI（默认）** | `rt_see`（视口/`full`）/ `rt_cmd` / `gui_*` |
| 无 GUI、批处理、长活、数据探针 | **无头备用** | `blender_rt_headless(preload="audit", script="…")` |
| 无 GUI 但仍要交互看图 | **worker + session（备用）** | `blender_rt_worker(op="start", name="s1", preload="…")` → `rt_do(session="s1", see=True)` |
| plan 判定/验收/导出（无 GUI） | **plan + `session="auto"`（备用）** | `blender_rt_plan(op="asm_scan", session="auto", args={…})` |
| 多视角 QC / 成品渲染（分钟级） | **无头 + `shots` + `as_job`（备用）** | `blender_rt_headless(file=…, shots=[…], as_job=True)` |
| 参考图对拍 / 交付导出 / 生成器复现 | **无头 + `preload`（备用）** | 见 §7.3 骨架 C |

**默认先开 GUI。** 只有明确「无 GUI / 批处理 / 长活 / 不需要人看画面」时才走无头；无头不是默认路线，但也能 rt_see，不会失明。需要 live 场景/视口/屏幕上下文时，必须走 GUI。

#### `blender_rt_headless` 关键参数

#### 等待窗口 / 作业层（结果永不丢）

| 项 | 值 |
|---|---|
| 客户端等待窗口 | 默认 **100 s**，可用 `DSH_HEADLESS_WAIT_MS` 调（[配置参考.md](配置参考.md) §11） |
| 窗口到点还没跑完 | 回 `{kind:"promoted", jobId:"run-…"}`（**不是失败**：子进程照跑，结果可收） |
| 怎么收结果 | `blender_rt_job(op="wait")` 阻塞等 / `op="collect"` 收集 |
| id 空间 | **`run-…` 与 `job-…` 同一个 id 空间**：`status / collect / kill / wait` 都收两种前缀 |
| 自动转作业 | `DSH_HEADLESS_AUTO_JOB_MS`（默认 0=关）：预计预算 ≥ 它时不等窗口，直接后台化 |

```python
# 预期 > 100 s：别赌，直接 as_job
r = blender_rt_headless(script_file="/mnt/d/work/aurora/tools/preview.py",
                        args="--part hull_aft", timeout_ms=900000, as_job=True)
# r 的信封里 kind="promoted"、jobId="run-…"（或已完成的 status="finished"）
blender_rt_job(op="collect", id=r.jobId)
```

> 内层 `timeout_ms`（默认 180 s、上限 30 min）与外层 `run_code` 的 deadline 仍是**两套预算**：
> 现在到点不会丢结果，但仍建议**外层 deadline > 内层 `timeout_ms`**，少一次 `collect` 往返。

#### `blender_rt_job`（作业层）

| 项 | 行为 |
|---|---|
| `op="start"` 参数 | 与 headless **同形**：`script_file` / `args` / `env` / `factory_startup` / `bootstrap` / `workdir` / `include_noise` / `engine` / `preload` |
| `op="wait"` | 阻塞到完成或超时，返回结构化回执（不用循环 `op=status` 撞 repeated-call 检测） |
| `op="status"` | `stage` / `stageAt` / `lastOutputAt` / `idleMs` / `lines` / `pidAlive`；后端重启后的 stale running 会被收敛成 `stale` 并说明 |
| `op="kill"` | 对未知 id 幂等：返回「已结束 / 不存在」，调用方流程不中断 |
| `op="collect"` / `op="list"` | 收集最终结果 / 列全部作业 |

```python
blender_rt_job(op="start", script_file="/mnt/d/work/aurora/tools/preview.py",
               args="--part hull_aft", env={"AURORA_STAGE": "qc"},
               outdir="/mnt/d/work/out/hull_aft", timeout_ms=1200000)
blender_rt_job(op="status", id="run-abc123")                  # stage / idleMs / pidAlive / lines
blender_rt_job(op="wait",   id="run-abc123", timeout_ms=600000)   # 阻塞到完成或超时
blender_rt_job(op="kill",   id="job-不存在")                    # 幂等：回「已结束 / 不存在」
```

#### 回执结构化：两个 text block

| block | 内容 |
|---|---|
| 第 1 个 | **单行 JSON 信封**（可直接 `JSON.parse`）：`status` / `kind` / `runId` / `jobId` / `resultJson` / `resultPath` / `resultTruncated` / `stdoutTail` / `stderrTail` / `artifacts` / `inputFile{path,size,mtime,md5}` / `stage` / … |
| 第 2 个 | 人读摘要（前言 + 日志尾 + 修法建议） |

**不要再写 `result: (\{.*?\})` 这类正则**（双层转义 + 截断时会抛异常）。取信封的稳健写法：

```ts
// run_code 里：找第一个能 parse 成对象的 text block
function envelope(res: any) {
  for (const b of res?.content ?? []) {
    if (b?.type !== "text") continue;
    try { const j = JSON.parse(b.text); if (j && typeof j === "object") return j; } catch {}
  }
  return null;
}
const env = envelope(await tools.blender_rt_headless({ script: "print('HEADLESS {\"a\": 1}')", as_job: true }));
const done = env.kind === "promoted"
  ? envelope(await tools.blender_rt_job({ op: "collect", id: env.jobId }))
  : env;
console.log(done.resultJson.a);                  // 1 —— 解析好的 HEADLESS JSON，无需正则
console.log(done.resultTruncated, done.resultPath);   // 大结果落盘路径（截断时必有）
```

```python
  shots=[{"name": "iso", "from": [9, -9, 6], "look_at": [0, 0, 1], "res": [1920, 1080], "samples": 256},
         {"name": "front", "from": [0, -14, 2], "look_at": [0, 0, 1], "res": [1920, 1080], "samples": 256}])
# 回执 res.shots 每张都有 path / ms / md5 / coverage_estimate
```

**骨架 C · 无头直调 QC / 交付（`preload` 对照表）**

| 要做的事 | preload | 调用 |
|---|---|---|
| 剪影对拍（IoU / Dice / 剖面差 + 对照图） | `qc` | `K.dsh_qc_api["compare"](ref, ref_box, render, label=…, out_dir=…)` |
| 多视角渲染 harness | `qc,qc_render` | `K.dsh_qc_render_api["render_views"]({views:[…], res:[…], outdir:…})` |
| 拼图（L2 证据） | `montage` | `K.dsh_montage_api["montage"]({paths:[…], cols:4, tile:420})` |
| 交付导出 / 核对 | `deliver` | `K.dsh_deliver_api['export']({dir:…, scope:…, name:…})` / `['verify'](dir)` |
| 网格体检 | `audit` | `K.dsh_audit_api('mesh', {objects:[…]})` |
| 机构 / 生成器 / 契约 / 规划器 | `motion` / `generator` / `contract` / `planner` | `K.dsh_<name>_api(...)` |

> `K.dsh_<name>_api` 两种写法都行：`api["fn"](...)`（返回字符串）/ `api("fn", {...})`（返回已解析 dict）。

### 7.4 路径空间：`outdir` / `out_json` 吃 WSL 路径

| 参数 | 当前行为 |
|---|---|
| `outdir` / `out_json` / `file` | **接受 WSL 路径**（`/home/…`、`/mnt/…`），内部映射；回执给**真实写入路径**（Windows 形态 + WSL 可见形态） |
| 脚本里把 WSL 路径交给 Windows API | 检测到「Windows API 收到 `/home/…` 或 `/mnt/…`」→ **显式报错**，不再静默漂移 |

```python
blender_rt_headless(outdir="/home/sixtyseven67/DSH/测试/建模/aurora/out",   # ✅ 直接给 WSL 路径
  script="import os, json; open(os.path.join(K.out_dir, 'probe.txt'), 'w').write('ok'); "
         "print('HEADLESS ' + json.dumps({'out': K.out_dir}))")
# 回执里给出真实写入路径；bash 里 ls 该 WSL 路径应当看得见文件
```

> 仍要注意：`/mnt/c|d|e|f` 是**只读挂载**（写不进去），且产物落在只读挂载时 `read_image` 打不开 →
> 临时产物一律落**工作区**（§7.5），成品再按归档约定拷走。

### 7.5 陷阱 E3：bash 沙箱的 `/tmp` 与 fs 工具**不共享**（每次 bash 调用即焚）

**现象**（本机 web profile 实测复现）：

```bash
# 同一次 bash 调用里：看得见
echo hello > /tmp/dsh_probe.txt && ls -la /tmp/dsh_probe.txt      # ✅ 有文件
```

```bash
# 紧接着的**下一次** bash 调用：没了
ls -la /tmp/dsh_probe.txt     # ❌ No such file or directory
```

而 `read` / `read_image` 等 fs 工具**从来就看不到** bash 的 `/tmp`（`not found`）。
本轮 engine / hull_aft / gear-arms 各为这个坑浪费 1~2 轮（engine 原话：「同一 bash 调用里 `ls` 看得见，
紧接着 `read_image` 报 not found，另起一次 `ls` 是空目录」）。

**规则：临时文件必须落工作区**（或任务约定的产物目录），不要落 `/tmp`、`/var/tmp`、`$TMPDIR`。

```bash
# ✅ 正确：工作区下的临时目录，跨 bash 调用与 fs 工具都可见
mkdir -p /home/sixtyseven67/DSH/.tmp/<task> && python3 probe.py > /home/sixtyseven67/DSH/.tmp/<task>/probe.json
```

```python
# ✅ Blender 侧同理：产物目录给两端都能读写的路径（不要给只读挂载，也不要给 bash 的 /tmp）
blender_rt_headless(outdir="/home/sixtyseven67/DSH/.tmp/hull_aft",
  script="import os, json; print('HEADLESS ' + json.dumps({'dir': os.getcwd()}))")
```

| ❌ 别这么写 | ✅ 改成 |
|---|---|
| `bash: … > /tmp/x.json` 然后 `read` 它 | 写 `<工作区>/.tmp/<task>/x.json` |
| `blender_rt_headless(outdir="/tmp/out")` | `outdir="<工作区>/.tmp/<task>/out"` |
| 产物落 `/mnt/d/...` 再 `read_image` | 落工作区；归档阶段再按约定拷到 `D:\Blender\<项目>\` |
| 手拼 `\\wsl.localhost\Ubuntu\…` UNC | 直接给 WSL 路径（§7.4） |

### 7.6 常见误用（照这张表自查）

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 外层 `run_code` 不传 `timeoutMs`，跑 >100 s 的 headless | 回 promoted 信封，但白等 100 s | 预期 >100 s 直接 `as_job=True` |
| 循环 `op=status` 轮询 | 撞 harness 的 repeated-call 检测 | `op="wait"` 一次拿结果 |
| 手写正则抠 `result:` | 双层转义 + 截断时抛异常 | 解析第 1 个 text block（§7.2） |
| 大输出靠 stdout 回传 | 中段被省略（`…[中间省略 N 字符]…`） | 给 `out_json=`；截断时看 `resultTruncated` + `resultPath` |
| 用 `scene.ray_cast` 批量逐像素射线 | 逐像素带 depsgraph → 撞 120 s / 600 s 上限 | `BVHTree.FromPolygons + bvh.ray_cast`（[证据分级与读图纪律.md](证据分级与读图纪律.md) §6） |
| `image.pixels` 直接和 PIL/cv2 对拍 | 上下颠倒 → IoU 假低（0.463 vs 0.955） | 先 `[::-1]`（同上 §6） |
| 每个建模方自写相机 / 灯光 / AgX 样板 | 50~60 行 × N 人 | `shots=[…]`（§7.2） |
| 并行跑 EEVEE 各造一把渲染锁 | 抢 GPU，有人等锁 48 s | 用内置 `render_lock`（`qc_render_views` 自动 acquire） |

## 8. 一键启动 Blender（需要 GUI 时）：`blender_viewport(op="launch")`

> 背景：GUI 通道需要"Blender 开着 + addon 已 Connect"，而 agent 没有人手按 N 面板。
> `launch` 把「写 boot 脚本 → 拉起 GUI Blender → 等 addon 端口 → doctor 体检」固化成一次调用；
> **纯无头任务不需要它**（用 `blender_rt_headless` / `blender_rt_worker` 即可）。

### 8.1 一条命令

%%%json
{ "op": "launch" }                                  // 最简形态（等 90s，自动探测 addon）
{ "op": "launch", "file": "/mnt/d/Dsh/…/tank.blend" }   // 顺手打开一个工程
{ "op": "launch", "wait_ms": 180000 }                // 冷启动慢（机械盘 / 首次加载插件）就调大
{ "op": "launch", "dry_run": true }                  // 只看将要执行的命令，不启动
%%%

它内部做的事：写 boot 脚本（GUI 里 enable addon → 起 socket server）→ `detached spawn blender.exe`
→ **轮询 9776…9876 端口** → 端口开了顺手跑一次 `doctor` 回诊断。
判据是**端口真的开了**，不是"进程起来了" —— 后者正是手工流程最容易停下的半成品状态。

### 8.2 幂等与并发

- **已在监听** → 回 `already: true`，**不会**再起一个 Blender（多 agent 反复调用安全）。
- 多个 agent 同时调用：后到的看到 already（或短暂竞争后同样 already）。
- 想重启：先关掉那个 Blender（或 `op=restart` 只重启**后端**，不是 Blender；两者别搞混）。

### 8.3 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `wait_ms` | 90000 | 等 addon 端口的上限（Blender 冷启动 + 加载插件要几十秒） |
| `file` | — | 启动时要打开的 .blend（WSL / Windows 路径都收） |
| `exe` | 配置链 | 显式指定 blender.exe（覆盖 `DSH_BLENDER_EXE` / `dsh-blender.config.json` / 自动探测） |
| `addon_module` | 自动 | 要 enable 的 addon 模块名（逗号分隔）；默认扫"模块名里带 mcp"的 |
| `addon_file` | — | 直接按文件 import 的 addon .py 绝对路径（Blender 5.x extension 布局下 `addon_utils` 扫不到老 `scripts/addons` 时的兜底） |
| `dry_run` | false | 只回报将要执行的命令 |

### 8.4 回执怎么读

%%%
LAUNCH ok · 已 spawn pid=12345 · addon 端口 9876 · 等待 8123ms
blender.exe：/mnt/d/SteamLibrary/steamapps/common/Blender/blender.exe（来源 config）
提示：GUI Blender 已起来且 addon 已 Connect（端口 9876）—— 现在可以用视口 rt_see / rt_cmd 了（写操作记得 blender_viewport op=lease 拿租约；纯无头任务本就可以不开 GUI）
· 已 spawn …（detached，与后端进程解耦）
· addon 端口 9876 已监听（8123ms）
boot 结论（GUI 侧自己写的 launch-status.json）：loaded_by=addon_utils:dsh_blender_bridge · server_running=True · enabled=["dsh_blender_bridge"]
启动后体检：通道健康：TCP + ping + bpy 往返都通
boot 脚本：\\wsl.localhost\Ubuntu\…\dsh_headless_xxx.py（想手工排查就直接跑它）
%%%

- `statusFile` 指向 `<workDir>/launch-status.json`：**GUI 进程的 stdout 我们拿不到**，所以让 boot 脚本
  自己把结论（enabled / loaded_by / errors / addon_modules_seen / env）写盘。
- 失败时看 `boot.errors`：常见是"addon 没被扫到"（→ 试 `addon_file`）或"background 模式"
  （addon 明确拒绝在 `-b` 下起 server，要用 GUI）。

### 8.5 与 headless 的关系（别混）

- `op=launch` 管的是 **GUI Blender**（要点亮 9876，为了视口截图 `rt_see`、`rt_cmd` 与"改用户手上活场景"的交互回路）。
- `blender_rt_headless` / `blender_rt_job` / `blender_rt_worker` **不需要** GUI，也不占 9876（独立进程 `blender -b`）；`rt_do / rt_see / rt_watch` 传 `session`、`rt_plan session="auto"` 也不需要。
  **多 agent 并行批处理请走 headless / worker**；GUI 只有"看用户视口 / 改用户手上那个活场景 / 吃 GUI 上下文"才需要。

### 8.6 回执报 `value is not lossless JSON` 怎么办

宿主门拒收回执（常见于插件版本与宿主/DSH 加载的旧模块不一致）。**升级到当前 v2.6.2 并重启 DSH**（插件是 DSH 启动时加载的模块）；
期间结果本身不丢：用 `blender_rt_job(op="start")` 提交，然后读 `jobs/<id>/stdout.log` 里的 `HEADLESS {…}` 兜底。

## 9. 宿主集成（`@` 提及 + 原生选中）

> **DSH 侧的「Blender 视口」面板、点击进消息、模型请求点选（`blender_rt_pick`）与 TUI 侧栏面板均已删除。**
> 选中的入口改到 Blender 侧：原生选中 → N 面板发送（见 §10）；只读的视口截图仍由模型工具 `blender_rt_see` 负责。
> 后端 `/host/view/*`、`/host/pick*`、`/host/ready` 路由**同步删除**；现存宿主路由只有
> `/host/selection`（+ `/latest`、`/consume`）、`/host/scene-items`、`/host/jobs`（+ `/log`）。

宿主集成是**用户侧**能力（你操作 → 进你自己的消息），**不是模型工具**：它走独立 HTTP 路由 `/host/*`，
**不进** op 目录、**不加**模型工具 ⇒ 15 个工具 / 217 个 op 的能力面**零变化**。

### 9.1 还在的能力：`@` 提及

输入框敲 `@` 出对象 / 材质 / 集合候选（引用带前缀 `object:<name>` / `material:<name>` / `collection:<name>`）；
选中后由 `codec` 拆掉前缀、序列化成 `<blender-object>Cube</blender-object>`，模型拿到确切名字，不用猜。
候选来自 `GET /host/scene-items?q=`（只读后端缓存，**不占** Blender 主线程）。

### 9.2 前置与端口

| # | 条件 | 怎么确认 |
|---|---|---|
| 1 | 后端在跑（`127.0.0.1:9877`） | `curl -sS http://127.0.0.1:9877/health` |
| 2 | Blender 开着且 addon 已 Connect（`127.0.0.1:9876`） | `curl -sS http://127.0.0.1:9877/doctor` → `kind=ok` |
| 3 | `lib/client.js` 已构建，且 **DSH 已重启** | `node tests/client_bundle_selftest.mjs` |
| 4 | addon **v1.10+ / protocol 11**（原生选中/集合/子元素/暂停 AI） | `blender_rt_cmd get_addon_info` → `addon_version [1,10]`、`protocol_version 11` |

端口一览：addon `9876` · 后端 `9877` · DSH GUI `3080`（都只监听本机，**不要**对外暴露）。

`/host/*` 的 CORS 只对 **HTTP loopback** 与**精确的 `dsh-app://app`** 回显 Origin（其他来源不带 `Access-Control-Allow-Origin`）。
这不是请求身份验证，也不是服务端 403 拒绝。

### 9.3 改完/升级完必须重启 DSH

客户端半边（`lib/client.js`）是 DSH 启动时加载的模块；只改后端才用 `blender_viewport(op="restart")`。
升级本插件后**必须重启 DSH**，否则 `@` 提及与原生选中桥都不会更新。

### 9.4 自检

```bash
node tests/client_bundle_selftest.mjs     # bundle 形状 + @ codec + 选中文本/插入路径
node tests/selection_store_selftest.mjs   # 后端选中存储（消毒/seq/consume）
```

## 10. Blender 原生选中 → DSH（addon v1.10+）

### 10.1 这是什么

"选中物体"不再必须去 DSH 的视口面板里点低清截图：**在 Blender 原生选区里选**，按 N 面板的按钮，
选中的对象名就会进 **DSH 当前会话的输入框**（草稿，**不自动发送**，发不发你决定）。

同时 Blender 侧给出统一的 **activity 判定**（人 / AI / 空闲 / 同时），面板实时显示，模型也能查 ——
AI 不会在你拖拽、变换、进编辑模式或刚撤销时把中间态当最终态。

### 10.2 三步用起来

1. **addon v1.10+**：用本仓 [`addon/dsh_blender_bridge.py`](../addon/dsh_blender_bridge.py)（或重新安装/启用一次），
   **重启 DSH**（客户端半边是启动时装载的）。
2. 在 Blender 视口里选物体：点选 / 框选 / Shift 加选都行；多选会发全部名字（上限 200）。
   进**编辑模式**选顶点 / 边 / 面，或**姿态模式**选骨骼，也会一起发送（`selection.sub`）。
3. 3D 视图按 `N` →「DSH Blender Bridge」→ **Selection → DSH**：
   - **多选模式**：选中若干物体 → 点「对象列表（N）▸」展开（默认折叠；带滚动条）→「发送选中到 DSH」；
   - **集合模式**：在「集合」下拉里选一个集合（或点旁边的 ⟳ 从选中对象自动推断）→ 点「成员列表（N）▸」展开查看
     →「发送集合到 DSH」（几百个零件不必逐个选）。
   - 展开后拖动「高度（行）」滑杆即可调整列表可见高度（3–30 行，默认 8），内容多了用列表自带滚动条。
   - **子元素**：编辑模式选点/线/面时，展开列表会多出「顶点 12 / 边 3 / 面 7」这类行；
     草稿会写成「Blender 编辑模式（网格）「Cube」：已选 12 顶点 / … 顶点索引：…」，
     模型按索引用 `bmesh` 精确改；骨骼则在姿态模式选，草稿给骨骼名。
   - 后端地址 / 覆盖项在折叠的「后端 / 高级」里。

然后回到 DSH：当前会话输入框里出现一行
`Blender 选中：Cube、Camera。活动对象：Cube。模式：OBJECT。用户说"这个/这些"时指它们；对象名在 bpy.data.objects 里可直接用。`

> 发送成功可在面板看到「最近发送：成功（seq N）」；DSH 侧插入成功与否可用
> `curl -sS http://127.0.0.1:9877/host/selection/latest` 的 `last_consume` 核对（`{ok:true, how:"actions"}` = 已进草稿）。

### 10.3 activity 四态

| `state` | 含义 | 触发 |
|---|---|---|
| `idle` | 空闲 | 两个窗口都没有信号 |
| `human` | 人在操作 | 模态操作（`window.modal_operators`：拖拽/变换/菜单等）**或** 1.5 s 内有人类操作符 / 撤销 / 选区变化 |
| `agent` | AI 在操作 | agent 命令执行中，或最近一次命令结束 ≤1.5 s |
| `both` | 同时 | 两个信号都在 |

- 面板**顶部**直接看活动状态；`agent` / `both` 时显示红色警告「AI 正在操作 Blender」。
  最近人类动作会显示成 `selection` / `undo` / `modal:transform.translate` 之类。
- **暂停 AI 操作**：面板顶部按钮；暂停后 socket 只放行只读查询（`get_*` / `ping` 等），
  `execute_code`、资产下载 / 模型生成 / 导入等写操作返回 `AI_PAUSED`；恢复只能在 Blender 里点「继续 AI 操作」。
- 模型侧查同一状态：`blender_rt_cmd get_activity_state`（**查询自身不计入 agent**）；
  查原生选中：`blender_rt_cmd get_selection`。
- 这个判定**与遥测同意无关、不上传任何数据**；和 `drain_human_activity`（同意后才有事件缓冲）是两回事。

### 10.4 排错

| 现象 | 原因 / 处置 |
|---|---|
| 按钮是灰的 | 当前没有选中物体（Blender 里选一个再点） |
| `发送失败：Connection refused` / timeout | DSH 插件后端没跑（先重启 DSH / 看 9877）；或 Blender 与 DSH 不在同一网络命名空间。可设环境变量 `DSH_BLENDER_BACKEND_URL` 或在场景属性 `dshbb_backend_url` 填可达地址（留空默认 `http://127.0.0.1:9877`） |
| 后端有 `seq`，但 DSH 输入框没字 | ① 升级后**没重启 DSH**（旧客户端半边不认识 `/host/selection`）；② 看 `/host/selection/latest` 的 `last_consume.reason`（草稿锁/备用通道非空/TUI）；③ 当前会话不是你要写入的会话时，切到目标会话再点一次 |
| activity 一直 `agent` | 正常：agent 命令刚结束的 1.5 s 窗口内；等一会儿再查。`get_activity_state` 已排除查询自身 |
| 工具报 `AI_PAUSED` | 面板顶部「暂停 AI 操作」被按下了：让 AI 停手后，在 Blender 面板点「继续 AI 操作」 |
| 找不到环境/模型 API 面板 | 在 N 面板底部「环境与角色模型API调用」；父面板与「环境生成 / 模型生成」子面板默认都折叠，点开再配置 |
| 人明明在操作但显示 idle | addon 版本低于 v1.10；或操作是"纯视图导航"之外的输入且未触发操作符/选区变化（极少见）——把现象连同 `last_human_kind` 报回来 |
| TUI 里收不到 | 草稿桥只在 **Web 客户端**（`conversation.input.dock`）；TUI 的 `sendToChat` 未授权，这是既有边界 |

### 10.5 验收命令（可复跑）

```bash
# 1) addon 版本与命令
```
