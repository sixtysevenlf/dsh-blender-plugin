# 给第三方的安装清单（照着走就行）

> 目标：**从零**把 `dsh-blender-plugin` 装到自己的机器上并完成验收。全程约 10–15 分钟。
> 验收判据：**GUI 路线 = `curl -sS http://127.0.0.1:39877/doctor` 回 `kind=ok`**；
> **纯无头路线**（不装 addon）= `blender_rt_worker(op="start")` + `op="see"` 回一帧图（doctor 的 bpy 往返不可达属预期）。
> 每一步都有**自检命令**：卡住就先跑自检，再往下走。

> **当前版本口径（2026-11-05）**：插件 **v3.0.6** · **15 个模型工具** · plan catalog **34 family / 228 op** ·
> Blender 侧 addon **v2.0.0**（protocol **12**）· Gateway `127.0.0.1:39877` · addon 主动连接（无入站端口）。
> **GUI 首选**：有 GUI 最方便；没有 GUI 时用交互式无头（`blender_rt_worker`：start/exec/see/watch/reset）同样能建模、看图。

## 0. 前置（5 条，缺一不可）

| # | 需要什么 | 怎么确认 |
|---|---|---|
| 1 | **DSH**（本插件是 DSH 插件，装在 DSH 的 profile 里） | `dsh --version` 有输出 |
| 2 | **Blender 4.2 LTS**（已验证；4.x 可能可用，5.x 未验证）（GUI 版最方便；无 GUI 时交互式无头也可用） | 能打开 Blender 窗口，或能跑 `blender -b` |
| 3 | **Blender 侧 addon** —— 只支持本仓 [`dsh_blender_bridge.zip`](https://github.com/sixtysevenlf/dsh-blender-plugin/releases/latest)（**v1.11+ / protocol 11**） | 见 §2（旧单文件与旧 `MCP for Blender` 均不再支持） |
| 4 | **Node（仅源码构建需要）** | npm 安装不需要单独 Node；`node -v` 只在从源码构建时检查 |
| 5 | 端口 **39877**（Gateway）空闲；addon 无入站端口 | 见 §5 排查 |

## 1. 拿到插件

普通用户从 npm 安装，不需要 clone 或构建：

~~~bash
dsh plugin --profile <profile> add dsh-blender-plugin@3.0.6
~~~

> **只有从源码开发**才需要 clone + `npm ci --legacy-peer-deps` + `npm run build`。
> npm 包自带构建后的 `lib/`，装完即可用。

## 2. 装 Blender 侧 addon（二选一）

**A. 本仓附带版（唯一支持）**

1. 从 [最新 GitHub Release](https://github.com/sixtysevenlf/dsh-blender-plugin/releases/latest) 下载 `dsh_blender_bridge.zip`，Blender → `Edit ▸ Preferences ▸ Add-ons ▸ Install...` → 选这个 zip
2. 勾选启用 **DSH Blender Bridge**（addon **v1.11** / protocol 11）
3. 3D 视图按 `N` →「DSH Blender Bridge」面板 → **Connect**（addon 主动连接 Gateway，默认 39877）

> **自检**：`blender_rt_cmd(name="get_addon_info")` → `addon_version=[1,11]`、`protocol=11`、capabilities 含
> `get_activity_state / get_selection / get_collections / send_*_to_dsh`。

## 3. 装进 DSH

1. 从 npm 安装到目标 profile：
   ~~~bash
   dsh plugin --profile <profile> add dsh-blender-plugin@3.0.6
   ~~~
2. 预演配置：`dsh --profile <profile> --dump-config`（能看到 `dsh-blender-plugin` 即成功）
3. **重启 DSH**（插件是启动时装载的模块）
4. 重启后**会话技能目录会自动多出 `blender-modeling`**（v2.2.0 起随包注册为 bundled skill，无需下载 / 软链）；让模型用 `skill` 加载它即可确认
5. **（v2.3 起，建议）Blender 原生选中 → DSH**：确认 addon 是 **v1.11+**（`blender_rt_cmd get_addon_info` 看 `addon_version`），
   在视口里选中物体 → `N` ›「DSH Blender Bridge」› **Selection → DSH** ›「发送选中到 DSH」→ DSH 当前会话草稿应出现对象名。
   回执排错看 `curl -sS http://127.0.0.1:39877/host/selection/latest` 的 `last_consume`。
6. **（addon v1.11 起）暂停 AI 操作**：N 面板顶部按钮；暂停后写操作被拒绝、只读仍可用，恢复只能在 Blender 里点。

## 4. 起 Blender 并验证（**验收判据**）

> **GUI 路线**：`doctor` → `kind=ok` 是唯一判据；**纯无头路线**（不装 addon）：`rt_worker(start)` + `see` 出图即可。

~~~bash
# 推荐：一键拉起 GUI Blender + 自动启用 addon（幂等）
blender_viewport(op="launch")

# 验收（全绿才算装好）：
curl -sS http://127.0.0.1:39877/health      # 后端活着
curl -sS http://127.0.0.1:39877/doctor      # ⭐ GUI 路线判据：kind=ok
blender_rt_plan(op="catalog")              # 34 family / 228 op
blender_rt_commands()                      # addon 38 条命令 + 5 个集成状态
~~~

> **没有 GUI 也能验收**（交互式无头；不依赖 Blender 窗口；此时 doctor 的 bpy 往返不可达属预期）：
> ~~~text
> blender_rt_worker(op="start")            # 持久 blender -b（冷启动 ~2s）
> blender_rt_worker(op="see", from="4,-4,3", look_at="0,0,1")   # 出图 ~50–100ms
> ~~~
> v2.3 起 DSH 侧**视口面板已删除**（改用 Blender 原生选中 + N 面板发送；见 §3 第 6 步）。

## 5. 卡住了先看这张表

| 回执 / 现象 | 含义 | 处置 |
|---|---|---|
| `blender-unreachable` | Blender 没跑，或 addon 没 Connect | `blender_viewport(op="launch")`；或人工按 `N` → Connect；纯无头改用 `blender_rt_worker` |
| `blender-unreachable`，且 `/doctor` 的 `addon.kind` 不是 `ok` | addon 不是本仓 v1.11+（旧 `MCP for Blender` / category-action 自 v2.3 起不支持）。**自 v2.3 起不再做协议探测**，所以没有 `handshake-stale` 这种「缓存成 fallback」的状态 | 停用旧 addon → 启用本仓附带 addon（v1.11+）；必要时 `blender_viewport(op="restart")` |
| `main-thread-busy` | 主线程被渲染 / 模态操作占住 | 等它空下来，或改走无头 |
| `addon-unresponsive`（`/doctor` 的 `addon.kind`） | Gateway 有 addon 实例，但 addon 在预算内（3s）没回 `execute_code` 的 bpy 往返（超时） | 确认 Blender 在运行且「DSH Blender Bridge」已 Connect；等长命令/渲染结束，必要时重启 Blender；`op=start` 只修 39877 Gateway 进程 |
| `addon-error`（`/doctor` 的 `addon.kind`） | addon 明确回了错误（非超时，如「AI 操作已暂停」/ 脚本报错 / `BUSY_RENDER`） | 按报错修；渲染中则等渲染结束或用 `render_wait`；不是主线程忙，不用反复重试 |
| Gateway 不可用（39877 连不上） | Gateway 进程没起来 | `blender_viewport(op="start")` |
| 写操作 409 `leased` | 别的会话持有写租约 | `blender_viewport(op="who")`，别强抢 |
| 工具数不是 15 / catalog 不是 34-228 | 插件版本旧或升级后没重启 | 安装 **v3.0.6** → **重启 DSH** → 复核 |
| `value is not lossless JSON` | 宿主与插件回执契约不匹配（旧版/未重载） | 升级到 v3.0.6 后**重启 DSH** |
| N 面板没有「Selection → DSH」 | addon 不是本仓 v1.11+ | 停用旧 addon → 重新安装/启用本仓附带 addon（v1.11）→ 重启 DSH |

## 6. 装完自检（可选，不需要 Blender）

~~~bash
npm test                              # 离线自检全绿
npx vitest run tests/integration/js/host-selection.test.ts tests/integration/js/host-jobs.test.ts tests/integration/js/host-scene-items.test.ts   # /host 路由 + selection 契约（v2.3 增补；测试自起 fake backend，无需 Blender）
~~~

## 7. 不在支持范围（请如实转达）

- **landmark / 人脸**：需要 cv2 / MediaPipe，**未安装**，不做人脸/关键点能力；
- **OCR、DXF**：未提供；
- **Open3D / manifold3d / glTF-Validator**：依赖未安装，相关校验/重建能力不可用；
- catalog 的「不覆盖声明」同时写明：生物/有机造型、电影级布光/体积/合成、角色动画绑定不在本插件覆盖范围。
