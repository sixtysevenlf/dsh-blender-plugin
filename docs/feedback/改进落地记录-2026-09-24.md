## 3. 口径偏差（重要，别按交接文档原文理解）

1. **D4.3「显式报错」→ 落成可审计告警**：脚本把 POSIX 路径交给 Windows API 时给 `pathWarnings`（含 `evidence` + `K.win_path()` 修法），
   **不中断脚本**。理由：脚本中途硬失败会把「已经渲好的图 / 已经写完的数据」一起丢掉；告警进信封与日志，可被批量核查。
2. **D1 的「转作业层」= 转成可回收的 run**：`promoted` 回执里的 `jobId` 形如 `run-…`（headless 的运行台账 id），
   与 `job-…` 同一 id 空间、同一套 `status/collect/wait/kill` 字段 —— 不必真的把进程挪进 job 目录。
3. **等待窗口默认 100 s（不是 120 s）**：外层 `run_code` 默认 deadline 120 s，留 20 s 给回执与状态查询。
   窗口到点后的 promoted 路径只是一次很快的 `/job` 查询（实测 <100 ms）。
4. **`op=wait` 上限 600 s/次**：一次调用等不完就再调一次（回执里带 `waitTimedOut` + `waitedMs`），不是失败。

## 5. 验收过程中额外发现并修掉的静默失败

| 现象 | 根因 | 修法 |
|---|---|---|
| `status` 在 addon 未连接时只剩一句错误，看不到版本/台账/工作目录 | `status()` 第一句 `addon.send` 就 throw | 本地信息与 addon 探测解耦（`addonError` 单独回传） |
| workDir 落在只读挂载上时，磁盘台账/日志**静默**写不进去 | `ledgerAppend` 的 catch 是空的 | `ledger.writable/workDir/lastError/hint` 自证 + `doctor` 直接打印修法 |
| workDir 用 WSL 路径时台账/results/trajectory 全落到一个 Node 打不开的串上 | `winToWsl()` 不认识 UNC，原样返回 | `winToWsl` 补 `\\wsl.localhost\…` → `/…` |
| `jobStart` 在 `engine="none"` 时仍注入 EEVEE 前导 | job 侧只特判了 `keep` | 与 headless 对齐 |
| `HEADLESS_WAIT_MS` 低于 5 s 被当脏值丢弃 | 守卫写成 `n >= 5000` | 下限放到 1000（验收要用秒级窗口复现 promoted） |
| shots 块内联 JS 字面量 `true` 到 Python | `JSON.stringify` 不是 Python 字面量 | 改走 `json.loads(<JSON 字符串>)` |


## 7. 头条 P0 的字面复现（§8.1 原文形态）

§8.1 写的是「跑一个 `sleep 200` 的 headless（外层 120 s）：返回值必须含可用 jobId；后续 `op=collect` 能拿到该次
HEADLESS JSON」。用**默认等待窗口**（100 s，不调环境变量）按原文跑了一遍（`tmp/acc_d1_literal.mjs` +
`tmp/acc_d1_collect.mjs`，脚本在 `timeout 120` 下执行 = 外层 120 s deadline）：

```
# ① 调用侧：外层 120 s 之内必须拿到句柄
ELAPSED_MS=102071          ← 102 s 返回（< 120 s），外层为 0
KIND=promoted              ← bash 通道同款 promoted 语义
JOBID=run-muflrgqcub4n     ← 可用句柄
STATUS=running             ← 服务端子进程照跑（不是失败）
COLLECT_STATUS=running
COLLECT_STAGE={"name":"preload-done",...}   ← 运行期就有 stage 心跳
COLLECT_LINES=6
OUTER_EXIT=0

# ② 200 s 之后：结果确实没丢
WAIT_STATUS=done
WAIT_EXIT=0 MS=201496
RESULT_JSON={"d1":"survived"}   ← 那次 HEADLESS JSON 原样收回
STDOUT_TAIL_HAS_HEADLESS=true
```

对照 v0.9.2：同一场景下图 ② 的这段 JSON 是不存在的 —— 外层 deadline 一到，客户端只拿到一行
`execution deadline reached (120000ms)`，结果留在服务端
（交接文档 D1 证据原文：`blender_rt_job(op=list)` 显示该任务仍为 `job-… · running · 148042ms`，客户端拿不到）。
