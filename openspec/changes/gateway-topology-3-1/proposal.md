# Proposal

## Why

3.0.x 的连接模型是 host → runtime(HTTP 9877) → addon(TCP 9876)：addon 必须监听，runtime 主动连 addon。这个模型能跑通单会话，但没有给多实例、虚拟显示、headless 作业队列和可验证的会话边界留位置；可用性诊断也只是散落在 status/doctor/worker 里的特例，而不是一条契约。

2026-11-04 的场景建模会话暴露了代价：模型可见的插件调用 5 次、任务级成功 0 次；`blender_op=start` 说“后端已在运行”，`doctor` 随后说“后端可能没起”；agent 在 90 秒内放弃插件，之后 67.6 分钟没有重试，改用 108 次 `blender -b` 和 104 次 `read_image` 完成交付。随包的独立评审把权重判为：配置/环境约 60–70%，错误契约/诊断约 20–30%，工具命名/数量约 0–10%；同时确认 `blender_see` 的 crop/zoom/像素采样有证据，但“亚秒级”只是推断，`blender_op` 尚无调用证据。

2026-11-06 又出现同一类故障的另一面：Blender 5.2.3 上 Blender Lab 的 MCP 扩展与 DSH addon 都以 SO_REUSEADDR 监听 127.0.0.1:9876，Windows 把新连接交给 MCP 扩展，插件 8/8 次调用全部超时（doctor 6.5–8.1s），而 addon 面板仍显示“已在监听”。固定默认端口 + 静默共存的代价是：TCP 连得上、通道不可用，模型只能反复超时。

v3.0.6（PR #75）已经修复了这组 P0：Windows Steam 探测、`blender_exe_missing` 预检、status/doctor 有界超时与诚实归因、`commands` 的 next_action。但修复仍是 3.0.x 拓扑内的补丁：addon 仍然监听入站端口，没有队列、没有 Gateway 管理的虚拟显示，15 个工具中仍有 `plan`/`do` 这类内部实现名泄漏。如果直接把队列和 virtual-gui 叠在 3.0.x 假设上，就会产生第二套连接路径和新的中间层。

现在 3.0.6 已发布、main 干净、重构终态治理已完成，是把这些能力收口成 3.1 契约的窗口：先把可用性、连接、会话、队列变成可验证的一等公民，再开放工具面。CLI 不再作为 3.1 的交付物；agent 的提效先靠 3.0.6 首调修复与 3.1 的可用性契约，不在本 change 承诺 batch/transaction 能力。addon 目前以 legacy zip 随 GitHub Release 分发，用户更新靠手动下载；3.1 同时把它收口为 Blender 4.2 extension，进入官方 Extensions Platform 的审核与更新通道。

## What Changes

- **BREAKING** **Gateway 单端点拓扑**：删除 runtime 作为“连 addon 的客户端”和旧 addon 的入站监听；Gateway 成为唯一 server，addon 作为 client 主动连接。host 与 tools 只连 Gateway；端口被占用时 fail closed；不做双栈兼容。Gateway 由 DSH host/plugin 拥有并管理生命周期（随插件启停，不 detached），不是 Blender 任务，也不由 job-queue 调度。
- **默认端口迁移与端口冲突 fail closed**：Gateway 默认端口从 9877 改为 39877（避开 Blender MCP 生态常用的 98xx 段与 Windows 动态端口段）；端口被占用时 fail closed 并报告占用者（port / pid / process），禁止与既有 listener 静默共存（不用 SO_REUSEADDR 共享）；doctor/status 必须区分“端口被他人占用”与“addon 未启动或卡住”。
- **单 host 单 Gateway，第二个 DSH host fail closed**：一个 DSH host 进程最多拥有一个 Gateway；Gateway 启动时记录 gatewayId / hostId / pid / endpoint。第二个 DSH host 发现该 Gateway 已存在时不得 attach、复用或共享，必须以 `GATEWAY_IN_USE`（stage=config）报出占用 host 与端口；同一 host 的插件重载不传递句柄：旧 Gateway 随旧插件实例停止，新实例重新启动 Gateway；旧进程必须先退出，不允许两个 Gateway 并存或留下孤儿。
- **会话归属、scope grant 与 presence**：一个 `user-gui` 同一时刻只属于一个 DSH session；owner 下主 agent 与 subagent 可同时 attach，其他 DSH session 只得到 `session_in_use`，owner 释放后才能重新 claim。同一 owner session 内的写操作按 `scope grant` 协调：`exclusive` 与 `collection:`/`prefix:`/`object:` 范围；互不重叠可并行，重叠返回 409 `scope_conflict`。只有 host 注入 `role=main` 的 main agent 可 grant/revoke，subagent 默认不继承。human 是 Blender UI 里的真人，不是 DSH caller，始终可直接编辑；N 面板 pause 阻止 agent 写，人改过的对象 revision 让 agent 写返回 `human_modified`，不做自动合并或 per-actor undo。Gateway 记录每个 agent 的观察位、选中对象、活动与持有的 scope，addon 在用户视口绘制带颜色的 agent 视锥/标签/选中框。
- **BREAKING** **addon 反向连接与握手**：addon 注册 `instanceId / kind / version / project / capabilities`；Gateway 按 instanceId 管理多实例、路由与断线重连；协议版本不匹配直接拒绝（负向测试覆盖旧 addon）。
- **可用性契约**：所有失败返回统一四问 `stage / root_cause / fix / fallback`（附 `evidence`，首调尤其）；`start` 与 `doctor` 不得互相矛盾；`/health` 通不等于 bpy 可用。3.0.6 已实测 `/status` 约 7.5s、`/doctor` 约 6.5s，作为 3.1 的预算基线；目标是在不牺牲诚实性的前提下收紧到评审建议的 P95 ≤3s；不把“无响应”写成“后端没起”。
- **会话与资源**：`user-gui`（用户拉起、一个 DSH session 归属、scope grant 协作、human pause、无上限）、`virtual-gui`（agent 专用、用户不可察；在现有 bundle 内是显式 feature gate，不拆第二个 bundle；Windows 自写 helper 通过 V0 后默认开启，Linux 为 preview、默认关闭；归属创建它的 DSH session，只有 owner 的 agents 可 attach）。`headless` 不属于 session：它是一次性 `blender -b` 无头任务，只通过 `job-queue` 提交。`virtual-gui` 必须启动真正的 GUI Blender（`bpy.app.background == False`），具备可用 GPU/GL、可截图/`blender_see`、可多实例、可清理；交互式视觉只属于 user-gui/virtual-gui。`worker` 的 Workbench see 从模型工具面移除：worker 只保留为内部执行器/CI 诊断，不暴露为模型工具。平台显示做成 `DisplayProvider` 抽象；V0 先做 provider bake-off：Windows 首选自写的隐藏 desktop helper（Win32，无第三方依赖，不需要驱动/管理员），签名 IDD 仅作为 fallback（需要用户安装驱动/UAC，不能静默）；Linux 首选 Xvfb+VirtualGL，Xvfb 软件渲染只能 `preview-only`。WSL/WSLg 路线不再考虑。V0 通过前不写死“Windows 原生 IDD 默认”，也不写死“默认 4 个 virtual-gui”；通过后才定 default/fallback、实例上限和安装前提。**Windows 自写 helper（W0，即本设计的 W1）通过 V0 即满足 3.1 GA 门禁；IDD 只是 fallback，W1 通过时不要求 W2，W2 失败不单独阻断。Linux preview 不阻塞 3.1 GA，但默认关闭；未通过自动化 `blender_see` 链路/能力门禁时不得宣称 Linux virtual-gui 可用，也不能退回 headless 冒充 virtual-gui。**
- **首调会话门与禁止静默降级**：会话级能力（`blender_session`、**执行型** `blender_op`、`blender_py`、`blender_see`）在解析不到 ready GUI session（`user-gui` 或本 DSH session 拥有的 `virtual-gui`）时不得自动启动 `virtual-gui`，也不得转给 headless/worker；`blender_op` 的 catalog/dry-run 等本地只读操作不要求会话。必须停下返回 `stage=session`，说明 Blender 没起来，并让用户选择“拉起 Blender 后 attach”或“用 virtual-gui 完成任务”。只有用户确认后才启动 virtual-gui，3.0.x 的自动降级路径删除。`blender_session` 的 `list`/`status`/`doctor`/`start`/`stop` 是 pre-session 例外：前三者只读，`start`/`stop` 管理 virtual-gui；`start kind=virtual-gui` 受宿主许可开关控制（插件配置 `allowVirtualGui` 默认 `false`，人类可在 DSH 的 Plugins → Blender 配置卡或 Blender Presence 面板打开；配置卡启用前检测依赖并询问安装，拒绝则保持关闭），未获许可时在 spawn 前返回 `stage=session` / `virtual_gui_not_allowed`，不创建会话。
- **headless 作业队列**：`blender_run` 提交两种作业：`kind=render`（声明式最终渲染，GPU slot 1；也承担相机关键帧动画预览，低分辨率/低采样即可）与 `kind=headless`（通用服务器侧无头任务：批量渲染/导出/几何处理/脚本，CPU slot 2；声明 GPU 时占 GPU slot）；队列容量 64；提交即返回 `jobId`；状态机 `queued → assigned → running → completed | failed | canceled`；有界队列满时返回 `QUEUE_FULL`；FIFO + 优先级 + 配额；JSON 持久化（`runtime/state/queue.json`，原子写）；支持取消与断线后 collect；render/headless 共用同一套 status/wait/collect/cancel/list、日志与产物清单，不设独立 job 工具。每个 virtual-gui 实例占 1 个 GPU slot；virtual-gui 占用 GPU 时 render 排队，不超卖。
- **BREAKING** **工具面 15→6 是等价迁移与改名，不是新增能力**：六个目标工具按用户意图命名（公共模型工具名统一带 `blender_` 前缀：`blender_session`、`blender_op`、`blender_py`、`blender_see`、`blender_run`、`blender_inspect`；内部 `session kind`、`headless`、capability/family 名称不带该前缀），直接替换旧工具面；旧工具定义、注册与旧名删除，不做新旧并存的 facade。括号内是它吸收的旧工具，能力先等价迁移，不新增建模/渲染语义。`blender_session`（viewport、txn；start/stop 只控制 virtual-gui，不控制 Gateway）、`blender_op`（plan/loop/opt/preset）、`blender_py`（do：在已 attach 的 GUI 会话内执行 agent 写的脚本与短 Python，是执行通道而不是建模引擎；没有会话时拒绝，不启动 headless；固定 `exclusive`，不接受更窄的 scope，同一时刻只有一个 `blender_py` 写者）、`blender_see`（see/watch；`viewpoint=viewport|camera|custom` 三种并列取景；`mode=frame` 单帧 / `mode=sequence` 有界多帧（仅 viewport/custom）；camera 只读当前帧、输出渲染比例，相机动画预览走 `blender_run`；viewport/custom 预览固定档位：支持 1:1/4:3/16:9，`max_size` 按比例取固定值，非法值报错；模型面不再接受 `view_size`）、`blender_run`（headless/job/perf：唯一作业入口，用 `kind=render/headless` 区分两类作业；早期叙事里的 `render` 工具名在本 change 统一为 `blender_run`）、`blender_inspect`（commands：只读查询；`blender_inspect` 的 help 只列它可执行的只读命令；写命令不再是命令面，调用已知写命令名返回 `wrong_tool` 并指向 `blender_py`/`blender_op`/`blender_run`/`blender_see`/`blender_session`；不存在 cmd 执行器或 `mode=execute`）；`worker` 不再作为模型可见工具（Workbench see 同步移除；内部执行器只服务 op/loop/CI，不暴露工具名）。`cmd` 不再是模型面执行器；写命令按迁移表分别归 `blender_py`/`blender_op`/`blender_run`/`blender_see`/`blender_session`，`blender_inspect` 不保留写模式。行为先等价迁移，再按 PoC 结果验收命名。
- **BREAKING** **addon 改为 Blender Extension**：addon 从 legacy zip 迁到 Blender 4.2+ extension：新增 `blender_manifest.toml`、删除 `bl_info`、zip 只包含一个顶层 `dsh_blender_bridge/` 文件夹，manifest、`__init__.py` 和模块都在该文件夹内（单文件夹布局）；模块名变为 `bl_ext.<repo>.dsh_blender_bridge`，偏好设置与内部引用统一走 `__package__`；host 的 addon 探测、自动启用、`get_addon_info` 版本校验不再依赖 `bl_info`/固定模块名；旧 zip 安装路径删除，只保留一个 extension 产物。addon 采用 `GPL-3.0-or-later`（官方平台要求），插件本体保持 BSD-3-Clause，保留上游 MIT 版权声明。
- **addon 版本与发布**：插件 3.1.0、addon 2.0.0、协议 12、extension manifest 2.0.0；官方 Extensions Platform 首次上架走人工提交/审核，后续版本由 CD 调 API 上传（`POST /api/v1/extensions/dsh_blender_bridge/versions/upload/`，token 走 secret）；`blender --command extension validate` 作为发布门禁，Blender 4.2 CLI 进入 CI；声明 `network`/`files` 权限并遵守 `bpy.app.online_access`；不承诺自动审核通过。
- **BREAKING** **addon 零遥测、零数据采集与无推广入口**：删除 telemetry consent 偏好与区块、`get_telemetry_consent` / `set_telemetry_consent` / `drain_human_activity`、consent-gated 人工编辑事件采集与缓冲；保留 `get_activity_state` 的本地 human/agent/idle 判定（仅内存，不落盘、不外发、不依赖同意）。删除 N 面板的 Discord / “Stay updated” 推广和 Preferences 的 Terms 链接；凭据帮助链接保留。addon 命令面从 38 registered / 39 wire 降到 25 registered / 26 wire（21 条只读 + 4 条内部传输，wire 另含 ping）；9 条写命令、3 条遥测命令和 1 条已注册但 catalog 未列出的 preview（`get_polyhaven_asset_preview`）从命令面删除，catalog、BEHAVIOR_MATRIX、contract tests、SECURITY/教程/接口契约同步。
- **迁移与文档**：一次性升级，插件与 addon 必须同步；协议版本 bump 到 12；addon 从 legacy zip 迁移到 extension，旧 zip 安装入口删除；删除“动态端口/兼容旧 addon”的表述，旧拓扑只保留在历史文件；CHANGELOG 与操作教程按 3.1.0 更新。

## Capabilities

### New Capabilities

- `blender/gateway`: Gateway 单端点、单 host 归属与第二 host fail-closed、addon 反向连接、握手身份、多实例路由、断线重连、版本匹配 fail-closed、addon 进程无监听 socket。
- `blender/availability`: 首调四问 envelope、分层探测、`start`/`doctor` 一致性、阶段预算、fallback 与 evidence。
- `blender/sessions`: user-gui / virtual-gui 的会话边界与生命周期、一个 user-gui 的 DSH session 归属、caller identity、intra-session scope grant、human pause、agent presence/用户可见视锥、实例上限与低资源降级；headless task 不属于 session，由 `blender/job-queue` 管理；交互式 `blender_see` 只属于 user-gui/virtual-gui，提供 `viewport`/`camera`/`custom` 三种取景；`mode=frame` 支持三种，`mode=sequence` 只支持 viewport/custom；camera 只读当前帧，相机动画预览走 `blender_run` render；worker 仅作为内部执行器，不作为模型工具。
- `blender/virtual-display`: virtual-gui 的 DisplayProvider 契约；Windows 自写隐藏 desktop helper、签名 IDD fallback，Linux Xvfb+VirtualGL；安装前提（隐藏桌面零驱动/零管理员，IDD 需驱动/UAC，Linux 需 Xvfb/VirtualGL/GPU 驱动）、GUI Blender/GPU/GL、截图 parity、多实例与清理；V0 选定的 default/fallback 与支持矩阵。
- `blender/job-queue`: `render` 与 `headless` 两类无头作业的 jobId 提交、状态机、有界队列与 `QUEUE_FULL`、优先级/配额、持久化、取消与 collect；render 是声明式渲染子类，也承担相机关键帧动画预览，headless 是通用服务器侧 `blender -b` 任务。
- `blender/addon-extension`: Blender 4.2+ extension 包格式（manifest、无 `bl_info`、extension 根布局）、`bl_ext.*` namespace 与 `__package__` 偏好、host 侧探测/自动启用、GPL-3.0-or-later、`network`/`files` 权限与 `bpy.app.online_access`、`extension validate` 门禁；官方 Extensions Platform 首次人工上架 + 后续 CD 版本上传，不保留 legacy zip；addon 默认零遥测、零数据采集，不提供社区推广或遥测条款入口。
- `blender/tool-surface`: 15→6 工具映射、六个入口的职责边界、`blender_inspect` 只读、写命令向 `blender_py`/`blender_op`/`blender_run`/`blender_see`/`blender_session` 的迁移、工具计数与 catalog 一致性。

### Modified Capabilities

无。项目当前 `openspec/specs/` 为空，3.0.6 的行为修复先作为本 change 的回归基线，不另建旧 spec。
