# Proposal

## Why

3.1 已经完成 Gateway 单端点、反向连接 addon、六工具面与作业队列，但"视觉"仍停在 Blender 进程内的截图与 NumPy：`img_*` / `qc_*` 每次分析都占 bpy，缺少 OpenCV 的轮廓、配准、光流与 DNN 能力；`blender_run` 的 render 作业也不产出 depth / normal / object_index 等 pass，无法做可复核的像素级判断。3.1 design 已经把逐像素分析明确留给后续的 `blender_op` vision change（`openspec/changes/gateway-topology-3-1/design.md:84`），现在 3.1.0-alpha.1 已落地，是补上这层能力的时候。

只补 2D 视觉也还不够。当前 `see` 只返回 8-bit RGB 预览，`img_*` / `qc_*` 只做单图或简单差分，`motion_*` 只做机构关节与 URDF；动画的 root motion、关节角/角速度、接触/脚滑、采样穿插和轨迹偏差，以及渲染 pass 的 depth/normal/object index 语义统计，仍只能靠目测。`openspec/future/vision-motion-analysis` 曾单独规划这部分，但它与本 change 重复声明 `blender/render-passes`，继续并存会让同一能力有两个事实源；现将其独有范围并入本 change，只保留一个 change。

不做这件事，3.1 的"see 看一眼"仍只能把 PNG 交给模型目测：没有稳定的 2D 量测、没有渲染与参考图的自动配准、没有序列运动与稳定性分析，也没有可复用的 GPU 渲染 pass 与 3D 动作证据。用户已经明确：视觉 worker 由 Gateway 管理，所有持久数据放在 `$DSH_HOME/dsh-blender/`，系统 Python 3.11+ 可接受，启用 DNN 时默认检测模型用 YOLOv5 v7.0，DNN 检测默认关闭、模型目录可由用户用 OpenCV 5 `models.yml` 扩展；渲染 pass 缓存默认 8 条 / 4 GiB 且可在 DSH 插件设置里改。本 change 把这些决定固化成可验收的契约，并让 DNN 配置可以在运行中安全热应用、在保存前做一次无副作用的可用性检测。

## What Changes

- **统一 home 与配置**：新增 `$DSH_HOME/dsh-blender/` 数据根（config、state、logs、jobs、sessions、queue、cache、vision），保留 `DSH_BLENDER_HOME` / 用户级 / 项目级覆盖顺序；插件激活时幂等创建目录，不上传、不打包用户数据。
- **Gateway 托管的视觉 worker**：Gateway 拉起一个私有 Python 子进程，stdin/stdout 私有管道通信，不监听端口，不占用 Blender Python；状态机覆盖 Python 发现、venv 创建、OpenCV 安装、校验与失败。用户不需要手动 pip，也不需要管理员权限。
- **OpenCV 自动安装**：默认 `opencv-python-headless==5.0.0.93` + `numpy>=2`，只装进 `$DSH_HOME/dsh-blender/vision/venv`；用户设置 `vision.venv` 时直接使用其自备环境，跳过托管 venv 的创建与 pip。系统 Python 支持 3.11/3.12/3.13，优先 3.13；没有可用 Python 时给出结构化 `vision_unavailable`（stage/root_cause/fix/fallback），不在系统 Python 里 pip，不把 cv2 装进 Blender。
- **`blender_op` 新增 `vision` 家族（8 个 op）**：`vision_status`、`vision_analyze`、`vision_compare`、`vision_detect`、`vision_track`、`vision_pass`、`vision_selftest`、`vision_help`。全部 host-local、read-only、不需要 GUI 会话；仍通过现有 `blender_op` 暴露，不新增第七个模型工具。
  - `vision_track` 在现有光流/轨迹摘要之外补序列稳定性（闪烁、抖动、跳变）与可选参考序列对比，覆盖 future 提案里的 2D 时序部分。
  - `vision_pass` 读取 render manifest，做 depth 分位/ROI、normal 角分布、object index 每对象可见覆盖率与前后顺序等语义统计；不返回原始深度/法线/索引数组，也不把 bbox 重叠说成精确遮挡。
- **新增 `animation` 家族（3 个 op）**：`animation_report`、`animation_selftest`、`animation_help`。`animation_report` 按帧求值 evaluated depsgraph（不读原始 F-Curve/Action.fcurves），从物体与骨骼的世界空间结果采样 root motion、局部关节角/角速度、接触/脚滑、采样网格穿插和可选参考轨迹偏差；关节链必须显式给 `bone_chains`，core 不推断 control/mechanism/deform 角色，只提供 `use_deform`/collections 事实与 `bone_filter`。该家族需要 GUI/虚拟 GUI 会话；`animation_report`/`animation_help` 走 session-read（要求会话但不取写租约），`animation_selftest` 才走写门；不新增 headless 入口，也不做动画编辑/重定向/物理仿真。
- **可选 DNN 与可扩展模型目录**：DNN 是默认关闭的 `features.dnn` feature flag；模型目录 `$DSH_HOME/dsh-blender/vision/models/` 用 OpenCV 5 `models.yml` 声明模型（key 即模型 id），用户可放入自己的 `.onnx` 并加一条配置来扩展，`vision_detect` 只接受模型 id。内置可下载预设仅 YOLOv5 v7.0 的 `yolov5n/s/m/l/x`（默认勾选 `yolov5n`），来源固定 URL + sha256、不随 npm 包分发（GPL-3.0）；是否下载由人在 DSH 插件设置里勾选确认，agent 不能下载或绕过。无可用 ONNX 时 `vision_detect` 返回 `dnn_no_model`，功能保持开启但禁止 agent 使用检测。
- **DNN 是实验性能力，默认 CPU-only**：插件设置中的 `features.dnn` 必须显示“实验性”标签，并在开关下方说明影响（YOLOv5/GPL-3.0、默认 CPU、结果可能不稳定）。默认推理后端是 OpenCV DNN CPU，插件不安装、不打包 `onnxruntime`。GPU 只作为用户自备环境的 DIY 扩展点：用户可设置 `vision.venv` 指向自己的 venv，安装 OpenCV/NumPy 与对应平台的 ONNX Runtime，再设置 `vision.dnn.backend=onnxruntime` 和 `vision.dnn.device=auto|cpu|gpu`；插件只校验 import/provider 并在不可用时显式报错，不自动安装、不静默回退、不承诺所有显卡/驱动。中英双语说明放在 `docs/vision-custom-backend.md`，模型目录同时放 `GPU-DIY.md` 快捷说明，配置卡提供 GitHub 链接。
- **DNN 配置热应用与可用性检测**：配置卡“保存并应用”时，宿主把候选 DNN 配置原子写入 `$DSH_HOME/dsh-blender/vision/runtime.json`（不含密钥），Gateway 在请求边界按 revision 读取，无需重启；worker 空闲时立即切换，忙时只登记 pending，新请求返回可重试的 `dnn_config_switching`，在途请求用旧 revision 跑完后再切换，绝不中途杀 worker。配置卡另有“检测可用性”按钮：用候选配置启动一次宿主侧、无副作用的 probe（不启动常驻 worker、不加载模型、不联网、不安装），逐项报告解释器/import/backend/provider/models.yml/模型。Gateway 不可达或切换失败时必须明确报告，不伪装已生效；`cache.render.*` 仍按原设计在下次 Gateway 启动生效。
- **渲染 pass 与缓存**：`blender_run(kind=render, passes=[...])` 新增 `beauty`、`depth`、`normal`、`object_index`、`alpha`（默认只出 beauty，保持旧行为）；每帧写 manifest（分辨率、dtype、值域、单位、坐标系、object index→对象名），不把 raw 数组塞进工具回执。新增 8 条 / 4 GiB / 7 天 LRU 缓存，按 scene + frame + camera + resolution + samples + engine + pass set 命中；单条超过 2 GiB 不缓存并给出 warning；缓存命中直接返回 completed job，不占 GPU slot。
- **DSH 插件设置**：`Config` schema 增加 `features.dnn`（默认 false，实验性）、`cache.render.*`（maxEntries / maxBytes / ttlDays）、`vision.python`、`vision.venv`（默认空，用户自备 venv）、`vision.model`（默认 `yolov5n`）、`vision.dnn.backend`（默认 `opencv`）与 `vision.dnn.device`（默认 `cpu`）等字段，由 DSH 插件设置 UI 编辑；未配置时使用上述默认值。DNN 分组提供“保存并应用”“检测可用性”“取消等待”入口和切换状态（idle/pending/switching/failed），显示在途 op 与 revision；`DSH_BLENDER_DNN` 设置时开关显示为 env 锁定。启用 DNN 且没有 `.onnx` 时，配置卡弹出带复选框的 YOLOv5 下载列表；拒绝只留下警告，不关闭 feature；下载完成后无需重启，下一次检测即可使用。缓存与视觉状态在 `doctor` / `vision_status` 中可读。
- **契约与计数**：catalog 从 34 family / 228 op 变为 36 family / 239 op（vision 8 + animation 3）；6 个模型工具、29 条 HTTP 路由、25 个注册 addon 命令和 protocol 12 不变。更新 `config/contracts.json`（vision 为 host family）、`config/routing.json` 与生成的 dispatch 表（animation 为 GUI 路由）、`config/plan-ids.json` / lock、behavior matrix 与文档。animation 作为新的 Python 领域加入 `runtime/py/modules.json`；`pyproject.toml` 的 import-linter layers 必须同步加入 `animation`，否则 boundary-governance 的 exhaustive 契约会失败。
- **非目标**：不新增模型工具；不改 3.1 Gateway/addon 拓扑；不做 CLI；不打包、不自动安装、不维护 GPU runtime（CUDA/DirectML/OpenVINO/MIGraphX）；GPU 只走用户自备 venv + ONNX Runtime 的 DIY 路径，按实验性支持，不承诺所有平台/驱动；不做通用 DNN 平台、模型市场或自动联网发现模型；本期只实现 `postprocessing: yolov5`，不做其他检测头/训练/模型转换；热应用只覆盖 DNN 相关配置，`cache.render.*`、`vision.python` 的托管安装和模型下载进度仍按既有生命周期，不热改缓存；不在本 change 重写既有 `img_*` / `qc_*` 的算法与 verdict（只新增 vision 契约；共享原语的替换在 golden parity 之后另开 change）；不做动画编辑、重定向、IK/物理仿真，不做修改器/Geometry Nodes/粒子动画分析，不做 Rigify 专用角色分类/适配（作为 future rig profile 另行评估）；不做图像反推 3D，不做连续时间碰撞保证，也不把 3D 分析当作 2D 分析的替代。

## Capabilities

### New Capabilities

- `blender/plugin-home`: `$DSH_HOME/dsh-blender/` 数据根、配置解析优先级、目录生命周期，以及 DSH 设置中暴露的缓存/视觉字段。
- `blender/vision`: Gateway 托管的 Python/OpenCV worker 生命周期、自动安装、8 个 `vision_*` op 契约、render manifest 的 pass 语义统计、2D 序列稳定性、可选 DNN feature、OpenCV 5 `models.yml` 模型目录（含用户自带 ONNX、YOLOv5 预设下载）、DNN 配置的运行时热应用与可用性 probe、默认 CPU-only 与用户自备 ONNX Runtime 的 DIY GPU 扩展点、错误与许可边界。
- `blender/render-passes`: `blender_run(kind=render)` 的 pass 集合、manifest、object index 映射与有界缓存，以及 manifest 对 pass 分析的可消费性。
- `blender/animation-analysis`: 从 evaluated 场景帧、物体与骨骼世界空间结果采样 3D 动作指标（root motion、局部关节、接触/脚滑、采样穿插、参考轨迹偏差）的 session-read 分析契约与预算；不读原始 F-Curve。

### Modified Capabilities

- `plan-op-dispatch`: catalog 新增 host-local `vision` 家族（8 op）与 session-bound `animation` 家族（3 op）；vision 必须在没有 GUI 会话时可解析并在 `contracts.json` 中登记为 host family，animation 必须走 addon Python dispatch，且不进入 host 短路；`animation_report`/`animation_help` 走 session-read，`animation_selftest` 走写门。

## Impact

- **代码**：`src/plugin.ts`（Config schema）、`src/client/index.js`（DNN 实验性开关、GPU DIY 说明/GitHub 链接、下载弹窗、保存并应用/检测可用性/等待状态）、`src/host/dnn-config.ts`（DNN 运行时快照与 `/dsh-blender` RPC 的 apply/status/cancel/probe 入口）、`src/host/dnn-probe.ts`（宿主侧一次性可用性 probe）、`src/host/dnn-download.ts`（人类触发的 YOLOv5 预设下载、sha256 校验与 models.yml 写入）、`src/host/dnn-pins.ts`（固定 URL/sha256/bytes）、`src/tools/op/read-only.ts`（仅 8 个 vision op）、新增 `src/tools/op/session-read.ts`（`animation_report`/`animation_help`）、`src/tools/op/execute.ts`（read-only/session-read/write 三种门）、`runtime/catalog/data.ts`（`PLAN_SESSION_READ_OPS`）、`runtime/http/routes/plan.ts`、`runtime/http/lease.ts` 与 `runtime/http/session-gate.ts`（session-read 只检查会话所有权，不取写租约）、`runtime/core/plan-dispatch.ts`（vision host-local 入口）、`runtime/execution` / `runtime/core/queue`（render passes + cache）、`runtime/home` / `runtime/config.ts`（home、设置与模型目录/GPU-DIY.md 创建）、新增 `runtime/vision/*`（含 `runtime-config.ts`、宿主侧 `models.ts`、`passes`、`worker/probe.py`、`runtime/vision/worker/*` 与 `worker/inference/{opencv,onnxruntime}.py`）、`runtime/vision/assets/GPU-DIY.md`、`docs/vision-custom-backend.md`、新增 `runtime/py/animation/*` 与 `runtime/py/modules.json` 领域登记、`config/routing.json` 与 `scripts/gen-routes.mjs` 生成的 animation 路由、`pyproject.toml` 的 import-linter layers、`scripts/vision_install.py` 或等价安装器。
- **依赖**：不新增 Node 运行时依赖（如需下载 standalone Python，仅用现有 Node 能力或明确登记的 helper）；Python 依赖由 worker 的 venv 在运行时安装，不进入 npm pack。默认不安装、不打包 `onnxruntime` 或任何 GPU runtime；自定义 GPU 环境由用户在自己的 `vision.venv` 中安装 OpenCV/NumPy 与对应平台的 ONNX Runtime，插件只做 import/provider 校验。3D 分析只依赖 Blender 自带的 bpy/mathutils 与 numpy，不需要 OpenCV。
- **API/契约**：`blender_op` 增加 8 个 vision op 与 3 个 animation op（36/239），`blender_run` 增加可选 `passes` 与 render 产物 manifest；无新工具、无新 HTTP 路由、无协议变更；DNN 热应用走现有 owner-only `/dsh-blender` RPC 通道新增 `dnn` 端点（apply/status/cancel-pending/probe），不新增 HTTP 路由。
- **配置/数据**：新增 `$DSH_HOME/dsh-blender/` 持久目录与 `vision/models/` 模型目录；新增 `features.dnn`、`cache.render.*` 与 `vision.{python,venv,model,dnn.backend,dnn.device}` 配置；新增 `vision/runtime.json`（宿主单写的 DNN 运行时快照）与 `vision/runtime-state.json`（Gateway 写的 active/pending/worker 状态），快照原子写、不含密钥；模型目录可由用户扩展，下载的预设写入 `models.yml` 与 labels；`vision/models/GPU-DIY.md` 在 home 初始化时缺失则创建、不覆盖用户文件；不写系统 Python、不写 Blender 安装目录。
- **文档/测试**：architecture、配置参考、操作教程、CHANGELOG、behavior matrix、catalog lock、contract parity、settings UI 冒烟测试、OpenCV/YOLO 许可说明、models.yml 扩展说明、动画指标单位/预算/session-read 说明、下载弹窗冒烟测试，以及 animation 的 unit/E2E 与 import-linter 回归。新增中英双语 `docs/vision-custom-backend.md`（CPU 默认、各平台 ONNX Runtime/Provider 组合、自备 venv 步骤、热应用/probe 语义、已知限制与排障）与模型目录 `GPU-DIY.md` 快捷说明，配置卡链接到 GitHub 文档；测试覆盖默认 CPU、custom venv 无效、backend/device 不可用、auto 回退与显式 GPU 失败，以及空闲/忙时热应用、pending 覆盖/取消、Gateway 不可达、probe 逐项结果与无副作用（不启动 worker/不加载模型/不联网/不安装）；animation 测试覆盖有效 fps、session-read 不取写租约、bones/collections 事实、bone_filter、局部关节、有符号接触、世界空间 BVH 与 reference 严格校验。
- **风险**：首次安装需要网络；Python 版本差异；OpenCV wheel 体积（Windows 约 44 MB）；YOLOv5 预设 GPL-3.0 与用户自带 ONNX 的许可/预处理不匹配；用户模型可导致 CPU 内存/耗时异常；用户自备 GPU venv 的 ONNX Runtime/CUDA/DirectML/OpenVINO 版本与驱动漂移，插件无法覆盖所有组合，只能显式报错并指向文档；不承诺 GPU 性能或跨平台一致性；运行时快照的并发写/陈旧 revision、Gateway 忙碌时的切换等待、以及自定义 venv 在新配置下启动失败，必须通过单写原子文件、revision、pending 状态和显式回滚信息处理，不能让半个配置生效；probe 只做只读检查，但仍可能触发用户 venv 的 import 副作用，需固定脚本、超时与不加载模型；缓存命中/失效的边界；DSH 设置 UI 与 Config schema 的兼容性；3D 穿插采样的 BVH 成本与骨骼/坐标系差异；新增 animation 领域会让 import-linter exhaustive 契约失败，必须同步更新 layers。
